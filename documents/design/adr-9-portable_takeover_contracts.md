# 可移植接管合同与来源自动退回

## 状态

已接受

使用者于 2026-10-19 批准更新后的阶段 3 执行书。本决定补充 [adr-8](adr-8-rendering_semantic_takeover.md)，不改变已接受的绘制和 PT 语义。

原版优先的核销环境与已知修改者变体原则由 [adr-10](adr-10-vanilla_first_takeover.md) 补充。

## 背景

阶段 3 开始处理会被其他模组修改的模型和动画来源。来源类名、模组名单和创建时的局部几何都不能证明后续执行保持原合同。公共接口若直接携带游戏对象，也会让版本适配扩散到资源、实例与调度实现。

## 决策

### 公共合同

资源、实例、外观、形变、绘制请求、依赖和发布的公共合同只使用版本无关的值、明确枚举及资源句柄，不引用 Minecraft、加载器或任何模组的类型。不得通过 `Object`、回调或泛型参数把游戏对象藏进合同。实际游戏对象和 API 调用留在当前 Target 的来源适配器内。

职责分为来源状态提取、不可变提交及执行；参考新版 Minecraft 的职责划分，不为未支持版本预先建立适配器。既有空间、材料、历史及退休机制继续复用，不能为接口名称另造一套渲染器。

为公共合同建立自动类型边界检查。新增合同字段时一并纳入检查；版本相关状态必须先由适配器转换。

### 来源自动退回

来源资格依据实际类变换链的字节码和变换记录，不按已安装模组名单推断。未登记的 Mixin 或其他字节码改动触及接管所依赖的来源时，该来源退回通用捕获，保留来源当前行为，并在日志和覆盖表记录具体目标及原因。

允许继续接管的变换必须有针对性原／新功能对照并登记。无法验证类内容或变换来源时按未证明处理，不默认允许。模型、材料状态、发布和辅助求值分别列出依赖，不能只检查一个模型类。

阶段 0～2 已接管的来源与阶段 3 使用同一原则。保留通用路径作为明确回退去处；迁移完成后移除的是该来源专用的重复兼容实现，不删除通用捕获。

验证中使用一个未登记的测试 Mixin 改动真实接管来源，确认接管停止、原执行保留、输出符合变更后的来源，并记录回退原因。重型双执行只用于功能验证，不进入正式性能窗口。

## 后果

资格检查是功能正确性的条件；因此加载组合改变后接管比例可能下降，性能报告必须记录实际资格。测试 Mixin、自定义类变换或来源不能被验证时，退回属于预期行为，不能通过放宽资格换取性能数字。

本决定不承诺任意运行时重定义、原生内存修改或未知加载器都能被检测。支持范围须用当前加载管线的实际检查与反例说明；未覆盖的变换入口不得写成已保证。
