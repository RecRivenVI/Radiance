# 有界渲染目标的资源、状态与执行接管

## 状态

已被 adr-8 取代

使用者随后明确终点为当前 Target 几乎全部绘制的一比一来源语义接管，而非限定生产者集合的持久化迁移。当前方向以[完整绘制体系接管](adr-8-rendering_semantic_takeover.md)为准；下文保留最初记录。

使用者于 2026-10-19 决定，将接管渲染代替持续兼容最终绘制结果作为项目长期目标。本决定确定方向；具体迁移按[阶段计划](../project/plan-render_takeover.md)逐项实施，不等于本次已授权实现全部阶段。

## 背景

现有路径同时包含最终顶点捕获、受限的持久模型、Flywheel 后端及 Voxy 专用后端。绘画持久化已证明减少源端重复生产能够带来净收益；材质 JNI 批量化没有证明稳定整帧收益。仅在完整顶点生成后比较或转换，无法持续消除源端工作。

Minecraft、Create/Flywheel/Catnip、Create Aeronautics/Simulated/Sable 及当前 Voxy 移植是版本明确的目标。它们具有不同的资源、姿态、材质和更新入口，不能假定存在一个通用的几何 dirty 通知。来源调查与版本边界见[静态研究](../research/survey-render_takeover_sources.md)。

## 决策

### 接管的完成定义

Radiance 为已承诺的目标拥有以下合同：

- 模型和纹理资源的身份、版本、创建、失效与销毁。
- 实例、部件、场景及所有者的稳定身份与生命周期。
- 按渲染帧提交的姿态、外观、可见部件及历史有效性。
- 几何位置、拓扑、顶点属性、材料绑定和实例变换各自的变化来源。
- 上传、形变、AS 构建、场景发布、执行及实际 GPU 完成退休。
- 来源的附加层、混合、发光、离屏依赖与正常及异常收尾。

已迁移路径不再每帧完整生成最终顶点用于比较、校验、轮廓或再次提交。用逐顶点 hash 判断未变不算完成源端接管；逐帧读取必要的姿态或小型外观状态仍是合法工作。

### 复用来源逻辑

保留游戏逻辑和来源能够独立复用的动画、模型选择、光照查询及必要回调。可在 Radiance 侧替换 renderer 的执行入口，直接消费这些结果；不要求原 renderer 的整段顶点展开始终继续执行，也不以重写物理模拟或复制整套模组源码为目标。

几何、外观和实例状态分离。位置或拓扑不变时优先复用模型与 BLAS；真正形变仍产生合法的 AS 输入。alpha、命中组或几何构建标志变化必须按实际依赖更新，不能一概当作无需 AS 处理的外观变化。

### 范围与迁移

支持范围以版本、来源能力和实际内容登记，不能用方块名、纹理名或 renderer 名称猜测材料、单面或发光语义。版本适配器可以识别真实来源 API 与资源身份。

每个目标分别登记“已接管、仍捕获、尚未覆盖、明确不适用”。迁移期间保留经过验证的原路径，且每次绘制只有一个执行所有者；在承诺范围内仍使用完整捕获的内容必须计为未完成。范围外扩展可以保留通用捕获，但不能据此宣称已完整支持。

升级依赖、额外 Mixin 或输入合同变化时重新核对能力。缺少更新通知的可变字段不能仅靠常见 setter 拦截来宣称已覆盖；可在来源提交边界采集必要状态。资源重载、世界切换和删除必须明确传播。

### 保持的产品合同

保持[查询可见性](adr-1-query_visibility.md)、[世界光栅权限](adr-2-world_raster_permissions.md)、[全亮传光](adr-6-fullbright_transport.md)及[语义决策索引](../reference/registry-semantic_decisions.md)。完整 PT 参与不依赖主相机可见性；不冻结屏幕外动画，不以世界后置光栅补全缺失。

Voxy 继续遵循已接受的 LOD 表达，完整参与指所选代理，不恢复来源舍弃的远景信息。GUI、结构图解和屏幕效果保留各自场景边界与绘制依赖；Ponder 保持默认行为，不恢复 Ponder PT。

本决定不改变既有透明、折射、面规则、线条宽度或发光强度。资源压力采用有界准入、合法旧版本和明确的未完成状态，不静默丢几何，不无限扩容，不以全局 GPU idle 作为通常更新机制。

## 后果

未来任务围绕完整生产者合同推进，性能计量同时覆盖源计算、生成量、传输、实例数、AS、GPU 追踪及整帧，不能只优化一个桥接计数。优先完成高成本原版刚性来源的闭合样板，再扩大到部件、Flywheel、航空学、粒子与 Voxy。

接管扩大了 Radiance 对来源行为和版本变化的责任，需要逐来源验收；不保证所有目标适合相同的几何粒度，也不承诺真实 60 FPS 或 4K 120 FPS。已有的验证、代际和退休机制继续复用，不为新目标先行重写整个场景系统。
