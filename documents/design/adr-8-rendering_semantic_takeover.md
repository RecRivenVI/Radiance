# 完整绘制体系与来源语义接管

## 状态

已被 adr-11 取代

2026-10-20 范围与完成判据以 [adr-11](adr-11-complete_drawing_scope.md) 为准：当前游戏版本，以及已纳入依赖在各自已验证版本范围内的所有绘制。下文保留为原决定记录，其余语义原则由新决定继承。

使用者于 2026-10-19 明确要求接管几乎所有绘制，在 Radiance 接管层一比一复刻来源渲染语义。本决定取代 [adr-7](adr-7-render_takeover.md) 对终点范围的收窄解释；原版和各模组是迁移、核对与验收批次，不是完整渲染能力的上限。

公共合同的版本边界与来源被额外字节码修改时的自动退回，按补充决定 [adr-9](adr-9-portable_takeover_contracts.md) 执行。

## 背景

最初计划主要围绕几个高成本生产者、持久几何和实例更新组织。它能够指导局部优化，但没有把 GUI、离屏依赖、表面程序、屏幕效果、加载画面和完整绘制顺序纳入同等明确的完成条件，不能代表使用者要求的终点。

Radiance 已有统一的部分状态、空间、材料与查询合同，以及专用实例和 LOD 后端。后续应逐步成为当前 Target 的完整渲染实现；性能优化是接管后的工作减少，不是决定某种绘制是否值得支持的唯一标准。

## 决策

### 范围

覆盖当前 Target 实际使用的几乎全部合法绘制请求：世界地形与流体、天空与天气、实体与 BER、粒子与程序化几何、附加层与标记、真实线点图元、GUI/HUD/文字/GUI 3D、离屏与渲染到纹理、屏幕覆盖与后处理、加载画面，以及已有 SDK 的输入、输出与呈现交接。

原版 Minecraft、加载器、Create/Flywheel/Catnip、航空学/Simulated/Sable、Veil、Voxy 和其他已声明支持的来源都进入同一能力清单。新版本和新来源仍需核对，不能承诺未来任意程序自动正确；当前实际用到的难例必须登记并推进，不能以未在城市出现、性能占比小或需要专用求值为由永久排除。

### 一比一语义的含义

以对应版本的原版 Minecraft 和各模组自身渲染实现为来源基准，逐项保存：

- 应绘制的内容、部件、层、更新时机、逐帧插值和调用依赖。
- 图元、拓扑、位置、空间变换、朝向、UV、法线、颜色及纹理／采样输入。
- 来源程序表达的 cutout、覆盖率、颜色运算、层叠加、动画与光照输入。
- 适用场景的深度、模板、混合、颜色写入、裁切、视口和输出位置。
- 多 pass、离屏生产和后续采样／读回、清除、resize、重载及正常／异常结束。

未经明确批准的差异作为缺陷或未实现项记录，不能将“看起来接近”“已经翻译”当语义等价。当前 [语义决策索引](../reference/registry-semantic_decisions.md)和已接受的 PT、查询、线条、发光、Ponder、结构图解及 Voxy LOD 决策是显式变更，保留原合同，不由“一比一”自动撤销。

原版光栅照明与世界 PT 的最终 RGB 不是逐像素一致的承诺。应按来源内容、表面求值、执行依赖和已接受的世界照明合同验收；GUI 和屏幕效果则按对应输出关系对照。随机误差、允许的浮点容差和每项有意差异需要单独说明，不能把整幅平均像素误差当成全部正确性的证明。

### 接管层的职责

接管层独立于 Flywheel。公共资源、实例、材料、状态和依赖合同不引用 Flywheel 的 Model、Instance、Visual 或 Engine 类型，不要求原版或其他模组实现 Flywheel 接口。Flywheel 只是来源适配器之一；现有 Flywheel 后端仅提供可复用实现和来源证据，不成为整个接管层的基础接口或调度所有者。

接管层同时拥有资源、状态、程序、请求及场景依赖。资源、模型和实例分离；对于可持久内容，从来源的模型和状态边界直接产生提交。真正动态的网格可以提交实际新顶点，不能为了追求“零顶点输入”冻结或改变内容。

已核对的高层模型直接提交和完整的通用绘制请求表达共同构成渲染实现。通用请求必须有明确状态、资源身份、程序含义和执行所有者，不能依赖兼容层猜测材料或沿用失效状态。迁移期的旧路径必须显式计量；它不会因某类内容已有快路径就自动退休。

世界表面程序需要保存其实际表面含义并进入 PT；不能把任意 GLSL 或混合状态简化为固定 PBR 分类。对于依赖已有屏幕颜色、深度、导数或多 pass 的程序，先区分表面求值与屏幕效果，再设计等效执行。没有证明时保留未完成项，不静默丢弃效果，也不把世界几何退回后置光栅。

GUI、离屏与合法屏幕后处理可以使用 Radiance 拥有的 Vulkan 光栅／计算执行；它们不因使用光栅而被排除出接管。世界仍完整参与 PT，遵守 [adr-2](adr-2-world_raster_permissions.md)；Ponder 保持默认渲染语义，不恢复 Ponder PT。

地形与流体是第一类持久场景来源，包含近景区段、附加区段几何、子世界及 Voxy LOD 各自的版本发布。实例化同时覆盖单个对象变化和共享组件的多实例，内部明确区分变换、外观、形变与拓扑，不将它收窄为同模型批量复制。

世界输出、GUI／HUD、屏幕效果与呈现分开拥有；当前 FG 以 DLSS 为实施对象。严格 GUI 绕过 FG 是目标，不是已经核实的 SDK 能力；标准 UI Recomposition 不构成该能力的证明。来源合同不引用假定存在的生成帧后 GUI 回调，具体边界见[功能实验](../research/experiment-takeover_boundaries.md)。

### 推进和验收

按[完整绘制体系计划](../project/plan-render_takeover.md)分别核销能力轴和来源轴。模型实例化仅是其中一类能力；来源覆盖率、语义符合度、生命周期正确性和性能收益分别报告。不能用一个快路径、单个场景或全部可编译代替完整接管。

保留来源业务、动画及必要回调，复用现有 native 生命周期与 GPU 完成退休。阶段实施可以从高频来源开始，但应能扩展到完整能力，不能让某类材料、离屏依赖或合法屏幕效果永远留在无法解释的例外里。

## 后果

需要维护图元／状态／程序／目标依赖与来源的二维覆盖表，并以原始实现对照验证；支持成本高于仅做持久模型优化。未知程序策略仍按 [adr-5](adr-5-unregistered_surface_programs.md) 的当前状态处理，本决定没有批准先拒收未知程序或制造可见缺失。

本次只扩展长期目标和计划，不实施渲染重写、修改现有产品语义、启动运行或承诺帧率。无法同时满足的来源效果与已接受 PT 合同必须给出具体反例及方案，需要产品取舍时再请求决定，不能自行削弱完整几何或视觉目标。
