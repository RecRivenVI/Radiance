# 查询规则验收

先使用本轮固定的 Minecraft 1.21.1 NeoForge 本地候选包。机器证据、产物身份与自动结果见[当前状态](../project/status-current.md)，产品合同只在[决策记录](../design/adr-1-query_visibility.md)定义。部分使用者结果见末节，没有反馈的观察保持待验，不包含性能实验。

## 启动

从仓库根目录运行带 Create、Sable 和 Aeronautics 的项目内日常实例：

```powershell
.\gradlew.bat :version:1.21.1-neoforge:runClientAeronautics -x :native_renderer:installNative
```

该命令只复用本轮已完成安装与验证的原生产物，避免为手工观察重新编译或重打包。先创建独立测试世界，不使用正式世界。自动运行均静音；手工窗口、声音、名称与辅助模组按[构建规程](procedure-build.md)，保留既有画质、DLSS 和业务兼容组合，不通过它们制造通过结果。使用者另行授权的 Prism 投放与手工反馈见[当前状态](../project/status-current.md)，不将其作为自动验证实例。

## 连续观察

1. 正常进入、持物和切换第一/第三人称。第一人称专用手部必须不透明；身体在直接画面中隐藏，第三人称完整显示。
2. 用玻璃和两层水面观察第一人称自身与单面薄片背面。连续折射不应让隐藏对象重新出现，也不能把不透明正面变为半透明。
3. 从两侧观察草、藤蔓、平面物品等来源单面几何，并观察其阴影、反射。直接成像遵循来源状态；传光仍可从两侧与材质交互。
4. 在可产生清晰反射的场景观察自身世界模型与专用手部。身体仍参与，专用手部不得新增世界反射或影子；它本身仍可受世界照明和遮挡。
5. 检查发光轮廓、名称牌和手杖锁定标记。其他实体仅优先级通道显示，文字边缘和背景透明度正确，不出现两份；第一人称自身的派生轮廓不能重新出现在优先级画面，第三人称和反射仍有其合法贡献。改变照明后材质受光，原有真实发光保留。
6. 放置船并从船内、船外、水下和反射中观察。船内遮罩覆盖的实际水面不存在，船外以及相邻船下水面仍存在。移动或旋转船后不能留下水面孔洞。
7. 检查两层不同高度的水、真实入水与出水、掠射角和转动视角。不能整片闪黑、跳过第二层水面或反复计算同一界面。
8. 在 Vanilla PT 与 Advanced 分别检查相关场景；资源重载、离开世界、重新进入后规则和纹理定位不变。最后正常保存退出。

## 判定与边界

用户负责可见结果。日志、加载 DLL 路径和哈希、错误传播与正常关闭由 Agent 读取；输入资源、CPU/GPU 合同与编译通过不代替视觉反馈。

出现 native fatal 或设备丢失时停止当前用例并保全证据，不自动重启或重复压力操作。GPU 根因和长期稳定性不随本轮规则修复闭合。来源船内遮罩目前要求封闭凸网格；原版船／箱船使用真实 bottom 边界，竹筏不创建孔洞。非凸或不封闭来源会明确报错；没有 bottom 来源的自定义船型保留原有限遮罩，需要对应适配证据。

本轮集中修复对应第 2、5、6、7 项：确定性透明分支中的自身、自己的发光轮廓、船／箱船内外水面和相邻合法水面。自动回归包含实际 priority 循环、从产品原样提取的透明调度和真实 BoatModel／ChestBoatModel 输入，不代替目视结果。浮空水晶不加入本轮验收。
