# 建议词表

本文解释 [AGENTS.md](../../AGENTS.md) 第 9 节建议词表中每个分类与类型词的用途。文件名的类型词决定文档的读者与写法（D-02、D-09），因此新建文件前先在本文找到最贴切的词；找不到时按 D-03 登记补充词。

## 选词原则

| 原则 | 说明 |
| --- | --- |
| 一类内容只有一个去处 | 同一分类中的词互不重叠；容易混淆的词在下文写明区别 |
| 按内容的性质分类，而不是按写作者 | Agent 写的计划、交接与调查报告，和人写的同类文档放在同一个分类 |
| 不与 Minecraft 术语冲突 | 不使用在 Minecraft 中另有含义的词。`model` 会被理解为方块与物品的渲染模型，`property` 会被理解为方块状态属性，因此不在词表中 |
| 玩家文档用玩家会搜索的词 | `usage` 与 `release` 的词对应玩家遇到问题时会查找的主题 |

## 分类

| 分类 | 默认读者 | 放什么 | 不放什么 |
| --- | --- | --- | --- |
| `usage` | 玩家与服主 | 安装、配置、玩法、命令与问题处理 | 源码、构建命令与仓库路径 |
| `release` | 玩家与服主 | 版本改动、升级与迁移操作、支持范围与弃用预告 | 开发过程 |
| `development` | 开发者；`procedure` 写给 Agent | 环境、构建、日常工作流、测试、调试、移植与操作规程 | 设计理由 |
| `design` | 开发者 | 系统为什么这样设计、各部分如何配合，以及决策记录 | 字段级的精确定义 |
| `reference` | 开发者 | 可以查询的精确定义 | 教程式讲解 |
| `project` | 开发者；`plan` 与 `handoff` 写给 Agent | 方向、范围、计划、进度、待办、技术债、交接与阶段记录 | 已落地的设计 |
| `research` | 开发者 | 某一时刻的调研、调查、审计、评审、实验与故障分析 | 持续维护的现状说明 |

前六类描述当前状态，内容过时就修改或删除。`research` 记录"当时查到了什么"：文档开头写明调查日期（D-16），固定包含"问题、方法、发现、结论"四节（D-06），事后不改写结论（D-10）。结论被采纳时，写进决策记录或相应分类的文档；整个调查不再有参考价值时直接删除，由 Git 历史追溯。

## documents/usage

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `installation` | 安装 | 下载、放入模组文件夹、安装前置模组 |
| `configuration` | 玩家配置 | 配置文件与游戏内设置界面的用法 |
| `guide` | 上手教程 | 带玩家按步骤完成一件事 |
| `feature` | 单个功能 | 介绍一个方块、物品或机制能做什么；与 `guide` 的区别是讲一个东西，而不是带玩家做一件事 |
| `command` | 命令用法 | 玩家可用的命令与示例 |
| `compatibility` | 兼容情况 | 与其他模组、光影与硬件能否一起使用 |
| `troubleshooting` | 故障排除 | 按"现象、原因、解决"排列的问题处理 |
| `faq` | 常见问题 | 简短的问答 |
| `limitation` | 已知限制 | 明确不支持或不打算支持的情况 |

## documents/release

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `changelog` | 更新日志 | 按版本累积的改动清单，每个项目都有 |
| `release` | 发布说明 | 某个版本需要在更新日志之外单独介绍时 |
| `upgrade` | 升级操作 | 玩家或服主从旧版本升级需要做的事 |
| `migration` | 数据迁移 | 存档、配置或接口格式变化后的迁移方法 |
| `support` | 支持范围 | 仍在维护的游戏版本与加载器 |
| `deprecation` | 弃用预告 | 即将移除的功能或版本 |

## documents/development

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `setup` | 环境搭建 | 第一次拿到仓库需要安装与配置的内容 |
| `build` | 构建 | 打包方式与产物位置，包括组件的构建 |
| `workflow` | 日常工作流 | 修改、试玩、检查的循环 |
| `testing` | 测试 | 运行测试、解读结果，以及需要人在游戏中逐项确认的测试清单 |
| `debugging` | 调试 | 排查开发中问题的通用方法 |
| `porting` | 移植记录 | 游戏版本、加载器或依赖模组之间的 API 差异 |
| `contribution` | 贡献须知 | 外部贡献者需要遵守的约定 |
| `compatibility` | 集成要求 | 与其他模组或 API 对接的技术要求 |
| `procedure` | 操作规程 | 给 Agent 按步骤执行的流程，有固定小节（D-06） |

## documents/design

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `overview` | 系统总览 | 系统由哪些部分组成、如何运转 |
| `concept` | 核心概念 | 玩法或系统的基本概念 |
| `principle` | 设计原则 | 做取舍时遵循的原则与约束，例如选项的设计准则、渲染的正确性优先级 |
| `architecture` | 架构 | 模块与组件的划分及依赖关系 |
| `mechanism` | 机制 | 一个子系统或游戏机制内部如何工作，包括实现要点 |
| `flow` | 流程 | 跨多个部分的步骤顺序，例如网络同步 |
| `lifecycle` | 生命周期 | 一个对象从创建到销毁经历的状态，例如加载顺序 |
| `security` | 安全设计 | 服务端校验与防作弊 |

决策记录写作 `adr-<number>-<topic>.md`，不使用上表的词。

## documents/reference

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `api` | 代码接口 | 供其他模组、光影包或脚本调用的接口 |
| `protocol` | 网络协议 | 网络负载的格式与时序 |
| `schema` | 数据结构 | 存档、数据组件与持久化数据的结构 |
| `registry` | 注册内容 | 本模组注册的方块、物品、实体等的 ID 与标签 |
| `command` | 命令语法 | 命令参数的完整定义 |
| `configuration` | 配置定义 | 配置项的完整定义 |
| `event` | 事件 | 本模组发出的事件 |
| `format` | 文件格式 | 数据包、资源包、元数据等文件的格式 |
| `version` | 版本对照 | 各版本支持情况的精确对照 |
| `dependency` | 依赖 | 依赖的模组与库：来源、版本范围、用途、是否内嵌与许可 |
| `upstream` | 上游 | 本项目派生自的上游项目：来源、许可、同步方式，以及本项目与上游的差异 |
| `glossary` | 术语表 | 名词解释 |
| `example` | 示例 | 可以直接复制的配置或代码样例 |

## documents/project

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `overview` | 项目定位 | 项目要做什么、不做什么 |
| `scope` | 范围 | 一个版本或阶段的边界 |
| `proposal` | 提案 | 尚未决定的方案 |
| `roadmap` | 路线图 | 未来一段时间的方向与里程碑顺序 |
| `milestone` | 里程碑 | 一个里程碑的内容与完成条件 |
| `plan` | 计划 | 给 Agent 执行的分步计划，有固定小节（D-06） |
| `status` | 进度 | 项目整体的当前状态；内容过时时立即更新 |
| `backlog` | 待办 | 已记录但尚未排期的需求、想法与后续事项 |
| `debt` | 技术债 | 已知需要偿还的技术债 |
| `handoff` | 交接 | 一项进行中工作的交接：现状、未完成事项与注意事项，供下一位执行者接手；接手完成后删除 |

阶段记录写作 `phase-<number>-<topic>.md`，不使用上表的词。

## documents/research

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `survey` | 调研 | 了解外部方案、上游项目、其他模组或技术资料 |
| `investigation` | 调查 | 追查一个具体问题的原因，例如崩溃、性能热点或行为异常 |
| `audit` | 审计 | 按一组标准系统检查现状，例如代码、文档、依赖、许可或移植进度 |
| `review` | 评审 | 对一项具体改动或方案给出的评审意见与核实结果 |
| `experiment` | 实验 | 为验证一个假设而做的原型、测量或对比 |
| `incident` | 故障分析 | 已经发生的故障的复盘：现象、原因、修复与预防 |

## validations

| 词 | 用途 | 什么时候用 |
| --- | --- | --- |
| `smoke` | 冒烟 | 能否启动、能否加载 |
| `feature` | 功能 | 一个功能是否按预期工作 |
| `visual` | 画面 | 渲染与界面外观的截图对比 |
| `regression` | 回归 | 修复过的问题是否复发 |
| `integration` | 集成 | 与其他模组的主动对接是否正常 |
| `compatibility` | 兼容 | 与其他模组或环境共存时是否冲突 |
| `parity` | 一致性 | 各 Target 的行为是否一致 |
| `conformance` | 符合性 | 产物是否符合格式或规范 |
| `performance` | 性能 | 帧率、加载时间与内存占用 |
| `stability` | 稳定性 | 长时间运行与内存泄漏 |
| `migration` | 迁移 | 旧存档、旧配置能否正确升级 |
| `security` | 安全 | 恶意数据与越权操作 |

## 同名与相近的词

| 词 | 区别 |
| --- | --- |
| `usage/configuration-*` 与 `reference/configuration-*` | 前者讲玩家如何配置，后者是配置项的准确、完整定义 |
| `usage/compatibility-*` 与 `development/compatibility-*` | 前者讲玩家环境、其他模组与硬件的兼容情况，后者是开发与集成的兼容要求 |
| `design/overview-*` 与 `project/overview-*` | 前者讲系统由什么组成、如何运行，后者讲项目定位、范围与方向 |
| `development/porting-*` 与 `release/upgrade-*` | 前者是源码跨游戏版本、加载器或依赖的移植，后者是玩家或服主的升级操作 |
| `release/upgrade-*` 与 `release/migration-*` | 前者是升级要做的操作，后者是格式变化引起的数据、配置或接口迁移 |
| `development/debugging-*` 与 `research/investigation-*` | 前者是长期有效的排查方法，后者是一次具体调查的过程与结论 |
| `development/testing-*`、`validations/` 与 `research/audit-*` | 测试文档讲如何运行测试与人工测试清单；验证目录是可重复执行的自动化验证；审计是一次性的系统检查 |
| `design/principle-*` 与 `adr-*` | 前者是长期适用的取舍原则，后者是一次具体决策及其背景 |
| `project/status-*` 与 `project/handoff-*` | 前者是项目整体进度，后者是一项进行中工作的交接 |
| `project/backlog-*` 与 `project/debt-*` | 前者是尚未排期的需求与想法，后者是已知需要偿还的技术债 |
| `reference/dependency-*` 与 `reference/upstream-*` | 前者是运行或编译时用到的模组与库，后者是本项目代码的来源项目 |
