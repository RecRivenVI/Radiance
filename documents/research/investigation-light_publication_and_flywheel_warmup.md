# 光照发布去重与 Flywheel 首次准备

2026-11-04。本轮承接[长帧归因](investigation-client_light_and_spikes.md)，按使用者批准的边界分离纯光照失效，并提前准备 Flywheel 稳定模型、线程缓存及已确认的公共适配类。上一轮四项移动优化全部保留，不降低内容或画质。

## 问题

客户端光照数据仍有环境声等消费者，但光栅专用更新会触发 PT 区段重编；Sable 结构光照包在收包期间重复整理存储。Flywheel 首次模型烘焙、线程局部状态及类加载曾导致渲染线程长时间等待。不能通过停用亮度数据、漏画或延迟显示绕开这些成本。

## 方法

Core 只修改客户端的区块包接收和光照入口：收包期间，同一当前客户端光照引擎的重复运行由既有世界绘制前入口合并执行；数据应用和新区块启用不延后。纯光照通知保留数据与其他监听器，只跳过其调用世界 renderer 的区段变脏操作。独立的内容通知、逻辑服务端及其他引擎不受此限制。接收范围嵌套及异常退出有回归检查，不保留世界引用或另一份光照队列。

Extra 在 Flywheel 原缓存清空之后，通过 `Models.partial` 预热已登记且已有烘焙资源的稳定部件；没有第二套模型缓存。工作线程开始接任务前，通过公开模型构建 API 初始化自身的 emitter 缓存。没有创建临时世界实例，也没有移除帧前／绘制前完成条件。资源重载后使用来源的新资源重新准备。

沿用上一轮冻结城市及设置，自动实例按约定静音、1920×1080、32 视距；RR、DLSS balanced、4 次反弹、SHARC 等有效配置由记录核对，FG 关闭，不加载 Voxy。两端恢复同一存档输入；该副本省略未使用的 Voxy 数据库，完整原输入不动。预热 90 秒后记录同一 24 秒 TIMED 窗口：静止 3 秒、沿 X 往返 16 秒及收尾。没有 JFR 的窗口用于耗时对照，另一次 JFR_ONLY 仅用于定位剩余类加载。

证据位于 `validations/performance-sources/result/light-flywheel-20261104/`。`baseline` 为原诊断 Core 和原 Extra；`candidate2` 为模型预热后的中间版本；`candidate-sample` 保留其 JFR；`candidate3` 为最终候选。`comparison.json` 保留各次身份、完整统计和限制。`candidate` 在首次回归中发现私有类静态访问器跨模块失败，正常关闭并保留原日志；已改用公开 API，不将失败改写成通过。

## 发现

### 正确性与准备成本

最终候选实际缓存 466 个部件模型、53,160 个顶点，10 个工作线程完成初始化；加载阶段准备耗时约 77.92ms，F3+T 后重新准备约 46.37ms。它将准备提前，并增加尚未使用部件的 CPU 驻留，不宣称这部分成本消失或菜单总启动时间缩短。没有为未遇到的模型预建 GPU 实例或 AS。

项目内断言确认：纯光照通知不会使已干净的 PT 区段变脏；修改后的亮度数据能发布、读回并恢复；真实内容通知仍使同一区段变脏。资源重载后 466 个来源部件仍全部存在于共享缓存，工作线程继续可用。客户端正常完成路线、重载与保存退出，没有设备丢失或其他客户端重叠。截图只用于检查明显缺失，不能代替使用者的连续画面验收。

中间候选仍有约 55.69ms 的 Flywheel 帧前入口尖峰。针对性 JFR 发现，稳定部件和线程缓存已存在，仍在首次加载本适配器的 embedding、实例／网格／材质解释类及公共区段集合类。最终版在加载阶段链接这组有限的自有类及所需集合形态，没有扫描或初始化任意第三方类，也没有实例化虚假机器来预热。

同样的光照包和启用次数下，整理累计耗时降低约 64.5%，通知减少约 10.7%；整理入口已经包含通知，不能再次相加。它是局部成本下降，不等于平均 FPS 增加。

本轮基线没有复现历史 161ms 的 Flywheel 帧前停顿，因此不能把历史数字直接减去最终 9.34ms 当作同条件收益。最终窗口平均间隔约增加 1%，p95 也略差；p99 与最坏长帧有所改善。只有一组基线和随实现推进的候选，不提供统计置信区间，不宣称整体平稳性或平均性能已经普遍提升。最终仍有约 83ms 的长帧，主要剩余部分在批量收包／Sable 内容准备等范围，未继续扩大本轮。

JFR 启动产生的长帧、安全点及采样开销单独保留，不混入上述 TIMED 对照。GPU 算法未改动，生成帧没有计入真实帧率。

## 结论

保留两项实现：纯光照变化与 PT 几何失效已分离，重复存储整理已有实测下降；稳定模型、线程缓存及已确认适配类的首次准备已提前，所有必需实例仍同步完整显示。平均 FPS 未取得明确收益，其他收包与真实内容准备仍会产生长帧，不能将本轮称为全部移动卡顿修复。最终配套候选交使用者在 Prism 体验，不提交、不推送、不自动启动 Prism。
