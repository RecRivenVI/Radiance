# 成像光路的介质边界修复

2026-11-05，调查并修复水面朝向、相机初始介质、微表面越面和异种介质相接四项缺陷。范围为世界成像与连续重建引导；原有单面可见性、薄片成员所有权及阴影通光近似保留。

## 问题

流体为光栅提交的反向顶面曾同时反转物理法线，使水下向上的光线被判断成再次入水。光栅深度偏移还在水与玻璃之间制造了不存在的空气缝。相机在水里时只初始化折射率，未给第一段到不透明物体的水路设置吸收；玻璃内部直接命中物体也存在同类缺口。

微表面采样原先只依据着色法线决定反射或透射，可能与实际几何两侧矛盾。相接介质还可能被当作嵌套体积：A 尚未退出就进入 B，随后从 B 出去时错误恢复 A。

## 方法

保留本轮开始时的源码与既有 A～D 候选，使用同一冻结城市、配置和固定视角比较。功能夹具直接调用已经混入的流体生产器，检查真实正反面顶点、绕序、法线和水／玻璃接触位置；再在隔离客户端中覆盖水下看水面、水底和实体、玻璃内部看不透明物、异色玻璃相接、掠射法线及玻璃板内外。

Native GPU 契约检查介质栈、两种相接命中顺序、嵌套、全反射、微表面几何半球及跨阶段状态恢复。实际发行包同时检查 Vanilla PT 与 Advanced 的着色器请求及客户端运行。自动结果和静态截图不代替用户连续画面验收。

## 发现

物理边界现在用真实朝外方向；流体背面保留相同的物理朝外法线，绕序仍相反。世界 PT 不再使用光栅流体深度偏移，预览保持来源行为。水的源高度保持实际值，没有将非满高度水强行填满。

水下相机从实际流体贴图、来源透明度及共用水光学参数初始化吸收。其他已知透射方块通过实际烘焙模型判断相机是否可能在体积内，GPU 查询决定真实介质参数；仅与玻璃板处于同一格不算在板内。未知自定义模型保守保留查询，不凭碰撞形状代替渲染形状。

反射和透射样本必须分别落在真实几何对应的一侧。越面的微表面样本权重为零，不强行改名为另一种光路；偏移和连续引导使用同一几何法线与全反射条件。

接触查询只检查边界附近的数值邻域，不跨过真实空气缝。相接 A→B 替换当前栈顶；真正嵌套仍入栈、出栈。同材质的正反薄片按来源属性和 UV 范围标记，只排除隐藏成员；不同材质以及合法的双面流体邻居仍参与边界判断。

Advanced 将当前、外层和目标介质及几何法线放入已有全精度表面缓存，避免半精度中转折射率或丢失边界事件。代价为每个内部像素额外 128 字节；1485×835 时约 151 MiB，1114×626 时约 85 MiB。Vanilla PT 不分配这部分 Advanced 缓存。

中间候选 `198bd474…` 出现明显退化：城市主世界 PT 均值从 17.09 ms 增至 27.90 ms，平均帧间隔从 25.10 ms 增至 34.18 ms。其相机恰在玻璃板所在格内、实际却在板外，过宽的介质提示导致逐像素额外查询。这份中间候选禁止投放，其数据保留，最终结果另列。

进一步对照表明，玻璃板误判不是全部原因。介质查询移出普通阴影 SBT，改用独立内联查询后，主世界 PT 降至 21.40 ms；禁用接触查询的诊断包为 16.23 ms。后者不满足相接介质的正确性，绝不作为交付候选。普通阴影的两套 any-hit 与 miss 源文件已经逐字节核对，与本轮修改前一致。

最终候选 `c1cfe533…` 保留全部修复，进一步跳过自身三角形、按真实几何法线做短距离检查，并依据已声明的介质／附加层／LoD 角色提前过滤候选。两次基线与最终值如下；均为同一冻结城市、32 视距、2560×1440、RR Balanced、内部 1485×835、四次反弹、FG 关闭的静止窗口，不外推移动收益。

| 窗口 | 主世界 PT 均值 | 平均帧间隔 | 帧间隔 P95 |
| --- | --- | --- | --- |
| 起始基线 | 17.09 ms | 25.10 ms | 31.05 ms |
| 邻近重复基线 | 15.47 ms | 22.89 ms | 27.25 ms |
| 最终候选 | 21.05 ms | 27.66 ms | 30.88 ms |

相对两次基线，主世界 PT 仍增加约 23%～36%，平均帧间隔增加约 10%～21%。采样无其他游戏重叠记录，未丢 GPU 事件或帧令牌；整卡统计不能证明所有外部进程均无占用。基线自身波动没有改变显著退化的结论。额外寻找接触邻居的成本仍是交付阻塞，没有达到用户要求的“无性能明显退化”。

最终包完成 `spotlessApply`、`check`、`verifyRelease`、82 项非 GPU 与 29 项 GPU 测试，296 个实际包的着色器编译请求通过。GPU 夹具包括真实非不透明介质 AS 与内部不透明障碍，检查查询仍找到介质出口。Vanilla PT 与 Advanced 各完成 13 个实际客户端视角并正常退出；生产流体的背面朝向、实际高度、接触平面以及相机玻璃板内外断言通过。初始版本同探针观察到错误朝向及光栅偏移，仅作为故障对照，不记为物理行为通过。未出现设备丢失。

已检查水下全反射和异色玻璃接触的最终截图，前者出现水底反射，后者不再残留上一种玻璃的吸收。静态截图和公式契约均不代替连续动态画面及用户验收。

原始日志、冻结输入、产物哈希和各次运行记录在 `validations/performance-sources/result/medium-boundaries-20261105/`。源码快照用于区别本轮初始版本、退化中间版和最终版本。

## 结论

四项边界规则已贯通主成像与连续重建引导，自动回归通过；独立阴影近似保持。性能门槛未通过，最终包只保留为待完善候选，未替换 Prism，未提交或推送。

下一步应优先研究在几何准备时声明可确定的静态介质相接关系，仅为未知或动态接触保留查询；本轮没有据此引入新的场景数据库或未经验证的邻居缓存。不能把取消第四项检测的较低数字当成修复收益。

任意非流形重叠体积、自定义渲染体内部的相机介质识别和复杂介质的完整体验仍有覆盖边界，不能由当前夹具推导为任意场景全部正确。完整交付仍待接触检测减负与人工体验。

## 2026-11-06 接触检测减负续查

本次保留四项正确性修复，未修改普通阴影通光规则。可运行的 C6 比正确性完整的 final7 减轻了部分成本，但相对修复前已验收版本仍有明显退化，不能投放。进一步的独立查询阶段 C7 在实际管线创建时崩溃，已经保全并撤回该实验；此后停止客户端与 GPU 试验，没有自动重试。

### 证据口径与实际设计

上一节的 contact-off 直接父版本是 final5，不是 final7；它同时改变查询执行、编译负担和接触语义，不能单独证明寄存器是主因。本次正式比较不使用这个包。Vulkan 管线可执行信息扩展与功能可启用，但四个实际 RT 管线均返回成功、可执行项数为零，没有取得可用的寄存器、溢出、存活状态或占用数据。这些仍是未知。

C6 将接触遍历和邻居材质解码移到 ray generation。通用 closest-hit 在需要接触时先返回已有 Payload 中的最小请求，尚未执行照明或 BSDF 采样；RGEN 确定接触与目标介质，再只恢复同一已接受图元。相机初始介质识别独立保留。没有增加 `MainRay` 或复制 `SampledSurface`，也没有改变普通阴影的 any-hit／miss。C6 两套算法实际运行的七份通用 closest-hit SPIR-V 模块已逐份反汇编，均不含 ray query 指令。这证明依赖已移出通用命中阶段，不能证明整个管线的资源负担已经消失：RGEN 仍有查询与恢复成本。

CPU 从最终几何与介质角色建立局部网格、内部接触及 BVH，不按 Minecraft 渲染层判断。区段、持久模型与动态实例使用共同的来源登记和空间关系；静态快照复用登记句柄，刚体共同空间运动复用内部关系。空间网格仅保守排除远邻，已知相接只标记可能需要确认的图元；贴图采样后的目标吸收与折射率仍由 GPU 精简查询确认。

已知无内部及外部接触的独立玻璃、对空气和不透明边界可跳过接触查询。未知网格、未完成的后台关系和运动中的候选保持兜底，不能把包围盒重叠直接认定为介质接触。后台任务有数量和队列上限，并按来源代际、几何及姿态版本发布；替换、删除和重载不会继续使用旧的排除证明。每帧 GPU 数据不可变，沿用在途帧资源退休。远坐标下只扩大保守候选误差范围，实际接触仍需确认；真实空气缝不因此合并。

### 正确性与覆盖边界

C6 的非 GPU CTest 83 项、GPU 契约 29 项通过。Vanilla PT 与 Advanced 各完成 20 个客户端视角，覆盖原四项缺陷、真实流体背面、水下首段吸收、掠射微表面、异种介质和连续引导，以及下列新增场景：独立悬空动态玻璃、同一动态网格内红蓝玻璃相接、动态接近静态介质及分离、真实空气缝、部分玻璃板／水接触、跨区段的普通玻璃与染色玻璃接触。跨层夹具确认普通玻璃是 cutout、染色玻璃是 translucent。GPU 契约也实际使用过滤元数据，检查已知、未知和局部候选状态。

远坐标负向平移、不同旋转中心及共同父空间运动由 CPU 回归覆盖，包括 3000 万坐标附近的共面和微小空气缝；这不能替代远坐标客户端的连续画面验收。动态专项采用真实公共持久实例入口，不代表逐一验收了所有机械动力装置。已检查 C6 跨区段及动态内部接触截图；连续游玩和用户视觉验收仍未完成。成功城市运行另有窗口外资源重载及正常退出记录。恢复源码后补充了内容更换立即使旧证明失效的 CPU 用例。

### 同条件性能与资源

最近的一组相邻正式窗口使用同一冻结城市、相机、2560×1440、32 视距、RR Balanced、内部 1485×835、四次反弹、FG 关闭。主世界 PT 来自 TIMED 窗口，整帧来自不启用 GPU 分段时间戳的 FRAME_ONLY 窗口，二者不混算。

| 版本 | 主世界 PT 均值 | 整帧均值 | 整帧 P95 | 整帧 P99 |
| --- | --- | --- | --- | --- |
| 修复前已验收参考 `539a53d1…` | 15.87 ms | 22.36 ms | 26.17 ms | 32.96 ms |
| 正确性完整的 final7 `c1cfe533…` | 20.76 ms | 27.45 ms | 28.72 ms | 31.08 ms |
| C6 `c47f5500…` | 19.09 ms | 25.30 ms | 29.25 ms | 33.69 ms |

C6 相对 final7 主世界 PT 减少 8.1%，整帧减少 7.8%；但相对已验收参考仍分别增加 20.2% 和 13.2%，P95／P99 也没有稳定改善。较早 final7 窗口曾为 22.37 ms／29.26 ms，说明存在跨运行波动，不能只选它作较有利的分母。本次邻近结果支持“部分减负”，不支持“已消除退化”。

城市中近景 1034 项方块实体、361 个实体及来源身份相符，邻近五乘五区块未见运动中的动力装置；两个马实体姿态有变化，动画相位没有完全冻结。这是对照限制，不能把所有动态条件称为逐帧一致，也不能据此宣称移动场景收益。未记录其他游戏重叠，观测 GPU 时钟均为 2790 MHz；这不能证明任意外部程序均无负载。

另做同 C6 代码生成、强制保持未知关系的诊断对照。每 16×16 像素抽样中，正常过滤的接触查询为 426 次左右，强制未知约 7078 次，约 94% 被排除；两边抽样均未观察到真正接触或邻居材质解码，光路段数差异小于 0.4%。诊断 PT 为 19.16 ms 对 30.46 ms，表明这一路无谓查询及命中恢复具有实际成本。它包含查询和恢复，不是纯遍历耗时；高频计数未混入正式收益数据。城市样本没有真实接触事件，真实接触正确性依靠上述专项，不能互相替代。

CPU 接触准备均值约 1.27 ms，已有静态场景追加在中间改进中从约 2.22 ms 降到约 0.22 ms；不把它们直接相加为整帧收益。稳定 CPU 网格／BVH／关系约 353 MiB，发布表约 2.30 MiB；当前 GPU 接触过滤数据约 0.88 MiB，不含旧帧在途副本。VMA 稳态为 6.06 GiB，与 final7 的 6.08 GiB 接近。

进程占用还有更大的未闭合增量：FRAME_ONLY 稳态工作集均值 C6 为 9.03 GiB、final7 为 6.44 GiB，私有提交量为 16.71 GiB 对 14.02 GiB。全运行峰值工作集为 9.42 GiB 对 6.98 GiB，私有提交量为 16.96 GiB 对 14.35 GiB。已统计的接触缓存不能解释全部增量；尚不能区分其余堆容量、临时准备或其他驻留，不把它直接称作泄漏，也不能忽略这项代价。整卡显存与 VMA 都未显示同量级增长，整卡数据不单独归属于 Radiance。

### 独立查询阶段实验与停止原因

C7 尝试把查询及解码进一步隔离为专用 miss 阶段，用已有的小型查询状态交换结果。十个定向优化 SPIR-V 离线验证通过，完整检查与发行检查通过；但实际客户端在进入世界前、创建 RT 管线时以 `0xC0000005` 退出。Windows Application Error 指向 `nvoglv64.dll`，未观察到 `VK_ERROR_DEVICE_LOST` 或同期显示驱动重置事件，也没有取得可分析的 GPU 转储。

故障模块只能说明异常发生位置，不能排除应用管线或驱动约束，也不能凭有效 SPIR-V 宣布是驱动缺陷。实验包 `64980d5b…`、匹配符号、源码和 Windows 事件保留。没有重试；已恢复逐文件核对的 C6 产品源码，三份只属于 C7 的实验着色器移入回收站。恢复后的构建不算 C7 运行通过，也不把新构建哈希冒充已经实测的 C6 二进制。

本轮记录位于 `validations/performance-sources/result/medium-contacts-20261106/`：`comparison-retained6.json` 为阶段与查询对照，`comparison-resources6.json` 为稳定窗口资源统计，`runtime-spirv-final6.json` 为实际命中产物检查，`restored6-source-verification.json` 确认恢复后的 592 份 Native 产品源码与实测 C6 快照一致；`executable-statistics.json` 记录无法取得寄存器数据，`query-stage-windows-crash.json`、`query-stage-reverted.json` 记录失败和恢复。旧结果、contact-off 和失败运行均未覆盖或改记为通过。

本轮未达到投放门槛。四项正确性修复与已验证减负保留在工作区，Prism 维持原版。剩余阻塞是约 20% 的主世界 PT 退化、进程内存增量及进一步阶段隔离的创建异常。后续应先解释未过滤的边界请求和这些成本，不继续叠加未经证实的缓存或以 contact-off 交付。没有提交、推送或操作 Goal。
