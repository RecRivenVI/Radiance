# 区块流水线增量组织实验

2026-10-24，使用者授权在同一城市及配置下优化完整区块加载链路，后续对照使用 1920×1080；本记录区分实现、机械验证、性能与人工视觉结果。

## 问题

既有 32 视距全链路显示静态场景在区段持续发布时反复全量重建；原生区段输入还花费大量时间在拓扑配对。已有并行编译、快照前准入、优先级、GPU 完成后发布和资源退休，不能将这些现有机制重新算作新优化。加载波动还包含 GPU 等待，不能预设全部属于 CPU。

## 方法

冻结清单位于 `validations/performance-vanilla/result/chunk-pipeline/`，每轮独立案例保留 `launch.json`、配置、实际加载 core 身份、完整质量状态与 `raw-evidence.zip` 校验索引。世界使用既有城市冻结副本，源实例与 Prism 不写入。使用 Vanilla PT、DLSS SR Balanced、SHARC、32 视距／32 模拟距离、512 MiB／16 GiB Java 堆；保留独立 shader 配置，不以默认主选项推断实际值。FG 关闭，自动实例静音。

完整加载使用 FRAME_ONLY；平静要求 Java/native 队列为空，磁盘读取、生成、客户端到达及 native 输入／构建／提交／完成均连续十秒不活动，再观察二十秒。平静不等于最终画面收敛。短 TIMED 窗只解释热点，不作为完整就绪时间。区块 GPU 提交至完成墙钟包含排队与轮询，主队列 GPU 时间戳不是整卡忙碌计数。

实现包括以下正式路径：

- 静态内容按 64 槽位发布不可变页；变化只重建对应页，其他页共享。稠密顺序、局部偏移、相机变换和历史沿用原合同。
- 九张场景表保留独立版本；变化页及动态部分经 staging，未变化页从上一 GPU 版本复制。旧源和新目标都在记录命令前登记到帧保留器。仍然是连续表，未实现全局稳定地址数据库。
- 拓扑键增加最终混合，避免整数坐标在低位桶聚集；每组只保留判定所需的前两成员和歧义计数，配对及对角线规则不变。
- Java 区段队列使用优先级／后台年龄两套索引堆，提级、删除及公平选择不再扫描积压。相机跨区段后线性重建索引，保留等待年龄；同一同步准入轮复用区域快照缓存，来源失效后重新创建。
- 后台请求在最后变化后 25 ms 合并，累计等待不超过 100 ms；交互不等待。Java 编译、原生输入、打包、GPU 构建与完成待发布共同占用准入额度，整体 128 项并为交互保留 4 项，后台原生输入预算 64 MiB；不将积压无限转移到 GPU。
- 原生使用独立命令池与一个可停止、可失败传播的工作线程连续推进；后台按逻辑输入字节、真实时间补充 8 MiB／16 ms 额度，在途输入 32 MiB、未发布区段 64 项，单个超大区段排空后独占准入。逻辑输入不是实际 PCIe 传输量，AS／scratch 另受活动构建批次容量限制。交互可借额度但仍记账，后台保留公平槽位。同族第二队列启用，异族时主线程安全执行，不隐式转移所有权。
- GPU 完成先回收上传暂存与 BLAS scratch，再由渲染线程按槽位代际及请求修订发布；完成信号通过一次主队列等待传递可见性。每批独立二值信号量由场景帧保留，退出／重建先停后台，再排空使用。旧几何维持到新版本可发布，缺数据不清空有效场景。
- 外部世界区段同样使用有修订的完成后发布，不保留旧即时构建分支；轮询尚未编译的外部区段不再取消正在执行的修订。来源的变换和历史不变，外部 Java 准备仍限制为原有单项并发。
- 不可变页目录在发布时构造并共享；未变化帧不再重建并逐页比较同一组描述符。连续 GPU 目标仍有完整分配与未变化内容的内部复制；该成本和新旧版本共存必须计入结果，不以 staging 字节独立判成功。
- GPU 完成后立即归还命令缓冲与 fence，不必等下一渲染帧；区段和字节额度仍保持到发布。未取得来源的区段从可执行队列移至等待状态，保留 dirty 和旧几何，由来源到达或再次变化唤醒，不反复空转或伪装为空。

## 发现

离线整数坐标反例：1024 个四边形的旧键落入同一低位桶；新混合分散到 647 个桶，最大链长 5。此项证明散列分布修正，不直接代表整帧收益。

采样历史保留：A1 的旧平静判据漏掉空队列间的短 native 活动，不作为正式平静对照；A2 客户端正常保存，但 TIMED 输出达到 128 MiB 上限并丢批，性能采样无效；A3 因存储预检拒绝，未启动客户端。没有通过放宽输出上限或失败重试掩盖这些事实。A4 使用修正后的 q3 探针完整记录 6264 帧，无丢批或 GPU 故障，正常保存关闭。

第一批中间候选 B1 曾使 native 输入数从 A4 的 40,208 增至 86,026；加载平均帧间隔 31.65→26.97 ms，但平静平均 21.38→25.15 ms。它不能判为完成或整体优化成功，促成本轮进一步请求合并、后台打包及目录复用。A4 有其他客户端进程的重叠记录；这组只作暴露问题的中间证据，不代替最终同探针对照。

整条流水线的 75 项非 GPU、23 项 GPU 检查通过，包括随机分页／补丁对照、旧版本保留、真实跨队列完成／等待／读取、容量恢复、过时代际拒收、公平性及后台停止／重启。停止时的条件变量握手经自审补上互斥，128 次启停回归防止睡眠通知竞态。首次检查拦下旧 JNI 头文件；交互探针首次编译缺少受检异常声明；纠正后均通过完整构建、Java／probe 测试及发行包检查。机械结果不等于人工反馈。

### 冻结身份与失败留痕

最终包为 `components/render_diagnostics/build/chunk-pipeline-worker3/radiance.jar`，SHA-256 为 `28f446d87698bc1d750ed46c24b3e2f710bbcbabd6c66ebc6cdfde85fdc77288`。正式性能组 A5／B3 的产品为 `2b68c395…`／`13cc2527…`，同一 q5 探针、城市、配置和 Java 堆；完整身份在 `validations/performance-vanilla/result/chunk-pipeline/` 的清单中。

最终包与 B3 产品的唯一产品源码差分是 `chunk_build_worker.hpp` 的停止握手；GAME 类与资源、shader ZIP 的成员内容及 SDK 数据逐字节相同，shader ZIP 元数据、runtime.index 与 core.dll 不同。`final-candidate-equivalence.json` 保留比较，不能把两个 SHA 写成同一次运行。最终包另执行 B4 交互以及 `chunk-pipeline-worker3-functional-r8-1080-20261024-172329` 的真实加载、F3+T、场景表／历史对照和正常保存关闭，未发生设备丢失。

A6 的 q5 交互窗口误启用被性能模式排除的孔洞访问器，产生 Java `IllegalClassLoadError`；服务器正常保存，失败、崩溃报告、原生取证及探针身份保留，没有 GPU 故障。q6 将窗口限定为 CHUNK_UPDATE，并测试不会开启 CHUNK_HOLE／BUILD／PERF。A7 因存储预检拒绝，未启动游戏；A8／B4 使用修正后的同一 q6 完成。解析器随后修正 MutableBlockPos 与跨窗口尾操作关联，旧解析结果另存，直接重算原始证据，没有重跑客户端寻找有利数据。

A5、B3 均正常保存关闭、采样完整，没有另一个游戏进程的重叠记录；整卡仍可能有非游戏负载。主证据为 `comparison-A5-B3.json` 与 `comparison-A5-B3-details.json`。只有一组最终正式配对，不作跨机器或长期性能承诺。

有效区段数是 GPU 构建完成后的 CPU 发布统计，不是显示器扫描输出。两边初载读取／生成／到达均为 7,759／4,761／3,653；第一指标不能偷换为全部数据更新已停止。候选达到最终有效数更早，但后来仍有零星构建，严格平静反而更晚，未证明该终点改善。全阶段窗口长度不同，因此同时列共同 60 秒；不以更多低负载帧夸大收益。

路线是同一组 64 个经客户端确认的服务端步点，来回 512 格，耗时 17.71／17.10 s，不是持续步行的视觉证明。结束时有效区段为 27,541／29,691，实际流式内容暴露与构建进度不同，不将路线结果包装成逐帧相同场景的纯 GPU 对照。A5、旧中间 B2 返回后残留 6,645／3,973 项 Java 请求而编译／GPU 均空闲；来源等待修正后 B3 正常排空，未删掉等待来源的有效几何。

初载 native 输入数为 41,342→49,399，未实现相对原基线的净减少；较早出图也使部分邻区依赖更早重新生产。输入段跨 worker 累计墙钟为 128.63→20.83 s，批次准备为 4.19→6.49 s，后者转到后台；这些相互重叠，不能相加或直接算作加载省时。请求合并抑制了中间候选的重复生产退化，但不称为完全消除重复工作。

### 放挖、边界和时钟

A8／B4 分别使用同一 q6 和原产品／最终产品，各做平静与加载两窗、每窗 12 次普通创造放挖，覆盖石头、玻璃、海晶灯、树叶以及水平／垂直区段边界。平静窗 12 次操作的队列均空；加载窗 12 次均有实际后台工作，不凭场景名称推断。完整原始值在各案例的 `chunk-interactions-analysis.json`。

| 动作至目标新版本完成帧的 CPU 观测 | A8 平均／p50／p95 | B4 平均／p50／p95 |
| --- | --- | --- |
| 平静放挖 | 105.55／81.91／174.29 ms | 79.99／77.15／138.95 ms |
| 加载中放挖 | 165.51／160.80／223.64 ms | 107.02／108.68／166.24 ms |

两边每窗 12 个目标区段均有实际构建／发布／记录／完成帧链。最终包的直接标脏依赖全部有证据：实际非空 GPU 构建、删除后的缺席，或已确认不变的空依赖后续完成帧；不为空依赖伪造 BLAS。原基线未登记不变空依赖，全部依赖的完成时间保留未观测，不能补填为通过。较远光照等 action=0 更新仍在原始证据里，不能强行归属某次操作。

Java/native 通过 JNI 前后时钟夹定，窗口最窄区间为约 8～22 µs；窗口前的环形记录丢失计数保留，窗口内不增加。端点含 fence 的 CPU 轮询延迟，不等于 GPU 精确结束时间或屏幕首个像素。12 次不足以估计长期 p99。客户端预测、服务器确认与渲染并列记录：加载时客户端状态均值 6.76→0.86 ms，服务器确认 53.96→33.56 ms，不能把全部 58.5 ms 差值独占归因于 native 调度。

## 结论

收尾复核发现旧空间预检漏算独立实验目录 `RadianceFeasibility`，现已计入并补回归；没有改动该目录。为恢复外部硬上限，将本线程的三组源码快照／JFR 冷证据迁入 `validations/performance-vanilla/result/chunk-pipeline/relocated-evidence/`，逐文件读回 SHA-256 一致后将原目录送入回收站。原记录中的外部位置以 `evidence-relocation.json` 为位置索引，证据内容和原始测量不改写。外部软超仍包含受保护证据及 SDK，沿用存储审计中待决定的边界，不称为软上限达标。

整条正式区块链已接入请求、快照、后台编译／打包、预算、GPU 完成后发布与退休；不重写存档、生成、实体或 BER。相同条件下已取得更早有效区段、较低共同加载窗口及路线帧时、较低放挖完成帧延迟，值得交付候选；静止 FPS、严格平静终点和资源占用没有全面改善，最坏路线单帧仍超过 100 ms，不扩大为所有卡顿已解决。

最终工程门槛、源码、完整产物及运行清单集中登记于 `validations/performance-vanilla/result/chunk-pipeline/final-candidate.json`。纯原版[人工入口](../../validations/visual-takeover_stages/validation.md)保持 2560×1440、音量 50%、音乐关闭、RecRivenVI，本轮视距 32，不自动启动。人工视觉、真实步行体验、长期稳定性和历史 GPU 根因仍待相应证据；本轮不暂存、提交或推送。
