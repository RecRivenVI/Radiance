# CPU 捕获容器减负与几何准备并行实验

2026-10-19，基于新的低开销诊断，分别验证捕获容器自身成本与稳定输入的 CPU 准备并行潜力。保持画质、完整几何、材质、历史与资源退休规则，不把局部成本下降或增加线程解释成整体提速。

## 问题

BER 每次还建立未使用的破坏覆盖层 provider，空输出随后仍整理提交容器；父类固定缓冲表也预留默认容量，虽然实际批次全部由覆写的入口管理。几何已捕获后的拓扑准备另有约 0.71 ms/帧，需测量分发与汇合能否取得净收益。原 renderer、材质回调、覆盖层合成、GPU 操作与场景发布不并行执行。

## 方法

沿用冻结的 `dynamic-baked-comparison.zip`，每次恢复并逐文件验证 206 个世界文件。1920×1080 输出、实际 PT 1114×626、32 视距及模拟距离、Vanilla PT、RR Balanced、SHARC、Reflex 2，FG、VSync 与区块发光收集关闭；静音、固定相机，保留正常实体、动画与 tick。Voxy 源码保留，本实验不加载 Voxy。外部客户端仍存在，只记录，不操作，不能声称硬件独占或排除背景扰动。

使用既有 `calibration` 顺序的六个 30 秒窗口，分别汇总三个 FRAME_ONLY 和三个 TIMED；另用 `throughput` 单个 60 秒 FRAME_ONLY 窗口作控制。均先预热 60 秒并满足队列平静至少 10 秒，单进程期限 600 秒，重载、保存和正常关闭不变。长帧不裁剪，重型诊断不混入正式帧率。证据根为 `validations/performance-scene_diagnosis/result/cpu-tasks-20261019/`，包含实际命令、加载 DLL、原始 profile 与回执，汇总为 `summary.json`。

基线来自 `a7bd377742c673c626edd04304b5e831ade93395` 的构件。第一轮 CPU 候选只缩小 `StorageVertexConsumerProvider` 中未使用的父类固定缓冲表，不共享可变容器，不跳过 renderer。第一轮两边 core 相同；并行原型尚未编入这些运行的 DLL，不能称为联合优化结果。

并行原型借用本帧已经拥有的几何，调用相同的 `mcvr::geometry::prepare`；各任务独占自己的顶点、索引与结果。主线程参与工作，所有任务完成后才继续，包括异常收尾，按原始顺序消费结果。同一对象重复引用时回退原有路径，少于 8 个任务或 2,048 顶点不分发，GPU 转换输入不重复准备。Vulkan 录制、覆盖层、审计、上传与发布仍在主线程。跨线程任务服务时间之和不是主线程延迟或活跃 CPU 时间，不加入帧分区。

`RADIANCE_CPU_TOPOLOGY_WORKERS=0/1/2/4` 分别为原串行路径、带分发整理的单线程、总计二或四线程，包含调用者。默认 0，不创建线程池；开启时也仅在首次有效批次懒启动最多三个后台线程，UI 场景不分发。任务不跨调用存活，不延长或改写 GPU 退休规则。线程创建中途失败会收齐已创建线程，保留原始异常；回归通过可控 factory 接缝验证，没有耗尽线程或注入 GPU 故障。

## 发现

| 第一轮窗口 | 基线均值 ms | 空表减负均值 ms | 基线 p95 / p99 ms | 候选 p95 / p99 ms |
| --- | ---: | ---: | --- | --- |
| FRAME_ONLY | 25.296 | 25.913 | 29.391 / 35.729 | 31.414 / 37.852 |
| TIMED | 26.302 | 25.742 | 30.563 / 36.184 | 29.621 / 33.627 |

两个进程均完成六窗和正常生命周期，无丢记录或设备丢失。BER self 为 2.442 → 2.134 ms，容器关闭 self 为 0.935 → 0.876 ms。不以分段窗较快覆盖轻量窗未改善的事实，不将局部差值直接解释为整帧收益。

基线运行器沿用了旧证据根与夹具回执文件名，实际恢复工具已生成新回执并使用相同冻结夹具。结束后将新案例移到本轮目录，保留原始记录，另附 `actual-fixture-prepared.json`；不回填旧进程身份。

### CPU 任务本身的后续减负

随后确认 BER 没有破坏覆盖层时仍创建第二个 provider，并在没有普通批次或持久刚性模型时仍进入空记录整理。候选仅在真实破坏阶段有效时创建其 provider；所有 renderer 仍执行。空记录快退发生在 `endBatch()` 与已完成批次检查之后，并同时检查刚性模型，不把零输出推断为无需执行来源。

| FRAME_ONLY 样本 | 有效间隔数 | 均值 ms | p95 ms | p99 ms | 最大 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| C1：仅空表缩小，独立 60 秒控制 | 2,372 | 25.285 | 29.254 | 39.074 | 92.908 |
| C2：再加覆盖层延迟创建及空记录快退，三个 30 秒窗 | 3,722 | 24.173 | 26.726 | 29.568 | 42.350 |
| 最终构件：同一 C2，独立 60 秒复查 | 2,338 | 25.657 | 30.682 | 34.601 | 49.728 |

C1/C2 使用相同原生 core `F476DF6E…`，C2 的对应 TIMED 窗口 BER self 为 1.545 ms、关闭 self 为 0.589 ms；第一轮 C1 对应为 2.134／0.876 ms。控制与 C2 的平均渲染线程 CPU 为 25.054／24.010 ms，时钟实际有量化，不逐帧推算等待。

这组 C1/C2 观察到约 1.112 ms 的帧间隔下降，但最终复查没有重复同等收益。因此确认减少了无用创建／空整理，不能宣布稳定的 4.4% 整帧提升。FRAME_ONLY 关闭嵌套计时，仍保留探针的 Mixin 包装与基础记录；`processEntityRenderData` 的包装调用也随空覆盖层消失而减少。未取得完全无探针对照，不能把全部差值归为产品独占收益。保留实体与动画正常 tick，输入顶点约 13,057～13,082/帧，也不是逐帧字节完全相同的回放。

### 同一原生原型的并行可行性

以下四个 30 秒 TIMED 样本使用同一 JAR `EE4A1574…`、同一 core `F476DF6E…`、同一 C1 GAME；只改变进程启动前的线程数变量。不是 FRAME_ONLY 正式吞吐结论。

| 总参与线程 | 拓扑主线程延迟 ms | 任务服务区间和 ms | 后台任务/帧 | 帧均值 ms | p95 / p99 ms |
| --- | ---: | ---: | ---: | ---: | --- |
| 0：原路径 | 0.730 | 未采集 | 0 | 26.553 | 30.541 / 36.000 |
| 1：分发控制 | 0.756 | 0.691 | 0 | 26.440 | 29.915 / 34.189 |
| 2 | 0.458 | 0.760 | 67.041 | 25.755 | 29.134 / 37.297 |
| 4 | 0.336 | 0.892 | 87.178 | 26.142 | 32.029 / 39.549 |

原路径值为 topology；其余值为完整 dispatch 加原顺序取回结果的 topology，不只计 worker 函数。每帧约 122 个并行任务、约 1.67 MB 逻辑输入，不等于实际 GPU 上传。真实后台任务计数证明运行发生了并行；两／四线程局部净省约 0.27／0.39 ms，但服务区间和增加，四线程尾部更差。单轮受观察器和外部活动影响，不能将总帧差归为并行收益，更不足以支持直接并行 Minecraft／第三方 renderer。

最终代码进一步限制 UI 不分发并懒启动线程，补齐线程创建失败回归。最终串行流程成功；最终两线程进程 PID 43840 在进入世界之前遇到 Create/Registrate `RegisterEvent` 的 `Found unused register callbacks`，随后注册回滚产生未绑定属性错误。没有 profile、没有 `VK_ERROR_DEVICE_LOST`，未取得最终 DLL 的两线程城市性能结果。保存完整原始日志与 crash report 后，仅对该项目客户端请求正常关闭窗口，没有自动重启或改动 Create 注册逻辑。Gradle 退出码为 0，但此案例明确失败并由分析器排除；注册错误根因未确认，不归为 GPU 故障或已证明的线程池问题。

### 生命周期、失败与存储

24 个有效窗口共 30,612 帧均经完整性检查；成功进程均完成 F3+T、字体违规 0、世界保存与正常关闭，无采样丢失或设备丢失。最终两线程注册失败另列，零有效窗口，不凭 launcher 成功代填世界验收。没有 GPU 转储，不关闭既有根因未知或公开二进制许可边界。

存储预检后，将已完成验证实例中的 44 个当前 JAR 匹配二进制副本、6 个登记输入的匹配 JAR 副本、11 个可再生管线缓存送回收站，共 714,114,876 字节。城市各次运行结束后，另回收匹配运行库副本和可从冻结夹具再生的世界副本。注册失败案例先校验日志／crash report 归档、确认客户端已关闭且从未进入世界，再回收其可再生副本；不伪造正常保存记录。清单留在证据根，原始 profile、JFR、日志、夹具、源码快照和唯一证据保留；送回收站不等于已经释放物理磁盘空间。

## 结论

保留三处能证明无须执行的容器／空记录减负，整帧收益仍受波动和探针边界限制。并行证明了稳定、独立输入的拓扑工作可以合法拆分，但此场景的净预算只有零点几毫秒，不是 60 FPS 的主要解法；默认继续 0，四线程不推广，最终两线程城市复查未完成。后续优先依据现有计时检查材质 setup／capture／restore 的重复工作，而非直接并行第三方 renderer；本轮不启动该项或扩大到全局场景表、Vulkan 多线程录制。没有操作 Prism、暂存、提交或推送。
