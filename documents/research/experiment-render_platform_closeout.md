# 接管平台收尾与下蹲复核

2026-10-25：128 号收尾补齐受限效果扩展和来源／资源接口，修正了实测发现的 LOD 覆盖表重复重建。复制的验收点位没有重现“下蹲立即改变 GPU 状态”的因果；捕获到的是后台远景加载期间的 CPU 台阶。新组合候选正常重载、保存和关闭，人工体验待验，不宣称用户报告的所有触发条件均已消失。

## 问题

用户反馈 127 候选站立时降帧、下蹲后暂时提速，其他地方暂未发现问题；这不是完整验收通过。另需补齐公共效果计划和第三方来源边界。127 的候选及用户实例不动，未推进设置界面、Early Window、后续集中性能或其他功能计划。

## 方法

读取当前工作树、127 源码快照和 10-21 的室内 SHARC 记录。Java／Native 的视图、第一人称输入与实例 mask 比较规则保持旧修复的前提；Vanilla 和 Advanced 的 SHARC 首段入口没有被这轮改写。

用 `platform_closeout.py` 在自己的 `closeout` 实例中只读复制用户已保存退出的 `Audit Benchmark`。冻结设置、世界及皮肤缓存，来源收据在 `components/render_diagnostics/build/platform-128/fixture-complete.json`。保留 32 视距、Vanilla PT、SHARC、RR Balanced、四次反弹及原有模组；只按自动实例约定设置 1920×1080、静音与不因失焦暂停。实际数据记录无生成帧。

点位为 `(11.496913877,65,15.473563680)`，朝向 `146.4393/4.050007`，脚点不动；相机站立／下蹲高度为 66.62／66.27。这里能看到天空，是用户保存的验收夹具，不是 10-21 的城市室内。旧探针的 `indoor-crouch` 标签不代表本轮选择了室内。两轮均正常输入驱动 8／2／8／2／8 秒的站立、下蹲、恢复序列；无宿主输入、质量降级或 SHARC 开关变化。

最先检查实际 DLL、JNI／加载器边界、覆盖表依赖与在途寿命、效果输入和截图读回时机。效果测试在性能窗口结束后进行，不把效果编译、读回和重载加入姿态统计。身份只在 `validations/conformance-takeover/result/platform-closeout/candidate.json` 定义；旧比较 DLL 与源码覆盖关系记于 `components/render_diagnostics/build/platform-128/before-lod-fix/provenance.json`。

## 发现

### 帧率台阶与局部修正

首个有效窗口为 `candidate-jni-registered-20261024-233415`；其后效果探针失败，但此前性能窗口已完整结束。1597 帧无丢批、缺帧或失败帧；有效部分和后续失败不混为整场通过。

| 窗口 | 帧间隔 p50 / p95，ms | GPU 世界 PT p50，ms | SHARC 命中率 |
| --- | --- | --- | --- |
| 首次站立 | 38.36 / 40.55 | 3.39 | 84.92% |
| 首次下蹲 | 38.19 / 40.47 | 3.52 | 83.81% |
| 恢复站立 | 12.77 / 39.23 | 4.54 | 86.98% |
| 第二次下蹲 | 12.95 / 15.13 | 5.06 | 89.38% |
| 最后站立 | 13.24 / 16.53 | 3.65 | 87.29% |

慢窗的渲染线程 CPU 均值约 38.4 ms；`pt.prepare.voxy-metadata` 自身约 24.26 ms，末窗该段约 1.77 ms。CPU 时钟正量子为 15.625 ms，只看多帧均值，不从单帧 CPU 数值推导等待。

所有窗口的 SHARC 训练首段近处命中均为零，与上次“训练大量命中隐藏自身”的故障不同。第一次下蹲仍慢，恢复站立后才提速；同期 Voxy 的空节点／选择数持续增长，非空 GPU 构建计数已经不变。TLAS 实例仍约 10245～10246，不是删除场景造成提速。两种姿态截图已查看，未见该点位明显冷暖突变。

源码确认 `LodScene::tables` 因任意远景版本推进重建整张近景覆盖表：即使近景、确认空区段和材质都没变、也没有交接残留，仍重复整理坐标和分配上传。旧 Voxy 代码已有同一依赖，不能称为 127 首次引入。

修正只缩小失效条件：没有交接残留时，远景进度不改变近景覆盖；有残留时继续按远景版本重评。近景发布、空区段、材质变化仍强制刷新；远景自身的选择、构建、历史身份和 TLAS 输入照常处理，旧表继续由帧退休机制保活。没有移除几何、改变 LOD、冻结动画或修改查询规则。

复核窗口为 `candidate-lod-coverage-20261025-000042`，2077 帧无丢批、失败帧或 GPU 遗漏事件。目标段首窗均值 1.86 ms，五个姿态窗口每帧均复用了覆盖表，且记录的远景版本与表版本不同，说明确实走过缩小后的依赖边界。TLAS 实例始终 10246。

| 窗口 | 帧间隔 p50 / p95，ms | GPU 世界 PT p50，ms |
| --- | --- | --- |
| 首次站立 | 13.44 / 17.02 | 3.05 |
| 首次下蹲 | 13.17 / 16.30 | 3.12 |
| 恢复站立 | 13.26 / 15.85 | 3.06 |
| 第二次下蹲 | 13.41 / 17.50 | 3.04 |
| 最后站立 | 14.73 / 23.84 | 2.92 |

这些是同一冻结输入的定位与一次定向复核，不是完整 ABAB 收益实验。末窗仍有波动；节点推进速度随帧率改变，不能将早期加载和已平静窗口混成整体提升百分比。确认了具体冗余和局部成本下降；尚未证明用户“下蹲本身”的全部触发条件与该项同根，人工体验仍需补验。

### 效果与公共资源

效果形式与互操作范围集中在[公共接口](../reference/api-render_platform.md)。Native 反射受限 fragment SPIR-V，实际按声明绑定输入、尺寸、采样、常量与最终输出；现有程序走同一执行器，图解必要程序保留。未建立任意 GLSL 兼容器，GUI／FG 政策不变。

实际像素回读确认：原内置反色与注册的相同 SPIR-V 输出一致；半尺寸中间目标再反色得到预期的两次变换，排除了始终读原图的假接通；苦力怕和蜘蛛均执行原 shader。F3+T 后注册程序仍有效。本次重载没有更换 UIModule 代际，因此“模块重建后重新注册”的代码分支未单独运行触发。

参数先于纹理存储创建的原生调用、公共纹理上传／关闭和持久缓冲范围上传／替换／关闭均经过实际入口。Voxy 投影页和 Sable 缓冲已改用有所有者的资源；Flywheel／Veil 不再直接写读 tracker 映射，既有 framebuffer／程序／顶点数组互操作被明确为受支持能力，不复制一套执行器。

Ponder／Catnip 覆盖层与航空学离屏层判断移到 Extra；Core 接收通用语义。与 127 源码逐项比对原分类，未改变命中范围。组合运行登记了 Sable、Flywheel、Simulated、Veil、Voxy 和 outliner 六个来源；登记本身不等于每种专项画面都已发生或通过。

### 失败、验证与保存

- 早期运行缺少标准审计标记，尚未进入游戏即停止；补齐自己的实例标记。
- 冻结旧包在图像存储创建前设置 filter 时失败；补全皮肤缓存后仍失败，排除了仅因缓存缺失的解释。修正合法的参数／存储先后顺序，保留已设置 sampler，不吞异常或补假图片。
- 首个新包导出且加载了正确 DLL，但新 JNI 类漏入 GAME 注册表；补齐实际注册与回归测试，未改变 SERVICE／GAME 加载流程。
- 首次像素检查读到了上一帧，证据显示正常世界后才读到反色；探针改为跨帧维持输入和效果，再取已呈现结果，未因探针时序修改产品 shader。
- 初次发行核验仍读受保护的 127 路径，错误报告新增许可缺失；新包实际已有许可。外置 init 脚本把构建、收集及核验都指向本轮目录，未改模板或旧包。
- 最终本体 `spotlessApply check verifyRelease`、JNI／ABI 检查、实际 Native INSTALL 和 77 项非 GPU CTest 成功；Extra 独立 `spotlessApply check verifyRelease` 成功。严格合规成功。本轮不重跑未受影响的全部 GPU 合同，效果／资源通过本轮真实客户端验证。
- 最终会话有 `PLATFORM_CLOSEOUT PASS`、`CROUCH PASS normal-stop`、维度保存和正常关闭，无设备丢失。失败和交付原始证据保留，自己的复制客户端已回收。

构建输出摘要在 `components/render_diagnostics/build/platform-128/`；有效原始窗口、派生 `pose-summary.json`、效果像素和保存收据在上述两项 case 中。验收包、来源快照和新人工入口由唯一候选清单关联，旧 127 实例与产物保持不变。使用者仅本轮批准验证目录临时 5 GiB；其他存储上限未放宽。可再生打包副本、缓存下载包和增量链接缓存送回收站，当前 SDK、基线 DLL、源码快照、用户存档和唯一证据保留。

### 仍有的逐帧工作

| 实际入口 | 当前仍做什么 |
| --- | --- |
| `LocalModelBatch.submit`、`PersistentInstances.changed` | 先填本帧姿态／外观再比较；仍分配选择、变化、绑定和组名临时数据。不是求值前去重 |
| `SourceHooks.begin`、来源 renderer 与捕获批次 | 每视图执行必要回调、状态和收集。零展开顶点的批次仍可能供刚性记录消费，不能一律跳过 |
| `WorldPrepareContext` | 相机派生变换、历史、选中实例与元数据组织仍在；现有内容相同比较可复用 TLAS，不等于无条件每帧 GPU 重建 |
| `uploadBuffer` 与 LOD 组织 | 既有分页／版本上传和 GPU 内部复制仍存在；未建立完整常驻 GPU 场景数据库，远景选中节点的逐视图遍历也未取消 |
| `ScreenEffects` | 激活效果时仍组装小计划，首次程序／尺寸建立 pipeline；descriptor 按帧复用。旧 UI 资源诊断的专用 post 计数不等于新效果缓存总盘点 |

本轮没有顺带全面优化这些路径，也没有把 CPU 提交／复用计数当作 GPU 或实际 FPS 收益。

## 结论

效果扩展与来源／资源边界形成了实际消费者和可体验配对，已修正一个有源码与运行证据的 LOD 固定开销。不能宣称所有站立／下蹲异常已定案，亦不能把本轮短窗推广为所有世界的稳定性与性能通过。交付后停止，用户重点观察原先点位的静止／下蹲、重载和常用 GUI／第三方外观；步骤五、六、设置改版和 Early Window 仍待后续安排。未暂存、提交、推送、公开发布或操作旧 MCVR／Prism。
