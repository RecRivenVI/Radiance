# GUI 背景分类与补帧启停实现

2026-10-23，依据使用者直接讨论确认的 GUI 策略实施首个切片：背景变暗参与 HUD-less，保留已求值反色，实际全屏菜单模糊关闭 FG，暂停本身不再作为否决条件。本记录不改变阶段 3 已接受结果，也不恢复第三方接管或性能实验。

## 问题

普通 GUI 覆盖率不能将整屏背景渐变视为前景，否则菜单后仍可见的世界被当作 UI。暂停标志与能否补帧也不是同一个事实：模拟暂停时仍可产生合法的本帧世界颜色、深度与运动输入。此前全屏菜单模糊继续补帧的计划已被使用者改为实际执行模糊时关闭 FG。

96 号历史会话没有取得额外生成正计数，窗口焦点门槛尚未闭合。本轮不能用数学恒等式、离屏 GPU 通过或原生帧截图代替这一证据。

## 方法

沿现有 Vulkan GUI 执行器与唯一 Streamline 呈现所有者实现，不新增 GUI renderer。`GuiDrawScope` 在实际背景调用前后 flush，并在嵌套、异常退出时恢复角色；来源为 Screen 的透明背景、完整菜单背景、全景替代背景和死亡渐变。局部控件、列表底色、字体与 3D 不被整个 Screen 作用域误包。

背景角色进入 native 的同一准备入口。颜色仍按原调用绘制；明确的背景 source-over／乘法作用在 HUD-less 上重放，现有 HUD coverage 保持不变。其依据为仿射背景操作 `T(D)=b+mD` 满足 `T(U+(1-A)H)=(mU+bA)+(1-A)T(H)`。后续真实 UI 照常累积 coverage，离屏附件仍保留原始 alpha。

每帧 acquire 重置 GUI 事实，由 `GuiFrameState.decide` 汇总用户开关、能力、世界输入、替代背景、实际全屏菜单模糊和不支持合成。JNI 模糊入口只记录事实；模拟暂停不单独关闭 FG。加载 overlay 保守地全程关闭，淡出提前恢复与加载 alpha 修正不在本切片内。

窗口取证仅在既有 capture 开关下记录应用 GLFW／Win32 HWND、PID、前台窗口和 swapchain，继续复用原 GetState 查询。应用 HWND 不冒充 SDK 返回值，不激活窗口或注入键鼠。
