# Veil 状态、生命周期与资源复用

2026-10-28，依据 Veil 4.3.2 的固定源码和当前 Radiance／Extra 工作区实施。任务包括已有适配路径的正确性与重复工作；Voxy 保持暂停，不恢复性能测试，也不修改或启动外部实例。

## 问题

前次[边界调查](investigation-veil_adapter_boundaries.md)确认适配器省略了部分程序绑定与释放行为。进一步核查发现：已有编译变体切换没有同步 CPU 程序模型；同一原生 ID 的共享编译结果可能被另一所有者释放；重载替换在新程序成功启用前释放旧程序。固定全屏三角形逐次生成和上传，uniform block 逐次分配直接内存并重复序列化，持久缓冲每次初始化都重新分配。

## 方法

- 以本地留存的 Veil 4.3.2 `ShaderProgramImpl`、`VeilShaderBlockState`、`ShaderBlockImpl` 及固定／动态 block 为来源，保留实际 packed／global 所有权和来源变化通知。
- 沿用两仓库的构建、发行核验、单元测试及本体 CTest。针对 Native 在途缓冲复用扩展既有 `persistent-write-batch` 测试，不增加另一个资源管理系统。
- 项目内打包验证使用实际 Extra、Veil、Create／Sable／航空学组合，1920×1080、静音；不加载 Voxy，不操作旧手工验收实例。检查来源 block 变化缓存、连续全屏绘制和 Vulkan 离屏颜色读回，再执行资源重载。
- 每个候选固定 JAR、源码和符号。证据位于 `validations/conformance-takeover/result/veil-adapter-20261028/`；C 配套身份以 `candidate-c.json` 为准。

## 发现

### 程序状态与释放

程序启用统一经过 `applyProgram` 后的挂接，包括直接切换已缓存变体。每个 live `CompiledProgram` 及其 uniform cache 按对象身份登记自己的解释模型，释放时只移除自己的记录。Native ID 只在当前 UI 模块内唯一，管线重建可以重新分配；不能仅凭整数相同共用 CPU 布局。来源 owner 的解绑与编译结果释放分开，关闭全部变体时逐项释放，其他编译所有者不受影响。

替换先尝试启用候选，再提交映射并释放旧版本。启用失败恢复实际活动变体，而非假设当前 mask 的旧项就是活动项；回滚或清理异常附在原异常上，资源错误继续传播。

### block 与混合状态

程序绑定／解绑恢复来源 packed block 清理和混合模式。Veil 保留槽位分配、回收和 global／packed 管理；向全部程序广播 OpenGL block 索引没有 Vulkan 消费者，因此只省略该广播。实际 CPU block 绑定仍按来源名称维护，槽位逐出、显式解绑及释放都会移除对应记录。

固定／动态 block 拥有可扩容直接内存。首次、来源 dirty 或尺寸改变时清零并序列化；其余绘制复制已有字节到自己的 uniform 数据。不会把可变缓存地址交给延期绘制；可变对象即使引用不变，只要来源 `set` 就重新序列化。释放、序列化失败及扩容失败保留清晰的所有权。

### 全屏与持久缓冲

全屏三角形首次需要时创建，在 Veil 关闭时释放。绘制直接使用调用方已绑定的程序和 uniform，不隐式重新 apply／clear，也不重写调用方参数；这同时消除了连续绘制后的意外解绑和重复保存混合状态。

Native 持久缓冲每个逻辑 ID 最多缓存四个退休版本，保持当前版本独立。只有退休池成为唯一 CPU 所有者、尺寸相同且用途满足时才复用；待上传集合、帧保留器或绘制引用仍持有的版本不能复用。部分更新继续先复制当前内容，完整更新按请求写入；不增加 GPU idle 或同步等待。缓存会增加有限的闲置驻留，逻辑缓冲释放时一起清理；本轮未测量具体场景的显存和帧率变化。

### 不支持的内容与保持的边界

storage block 在创建 Native 管线前明确拒绝；来源对无关程序的绑定广播不会导致异常。纯 OpenGL buffer 的绑定保留生命周期管理，但无法读取的必需 block、未编译程序或不完整的绘制在提交前跳过。只捕获已声明的 `UnsupportedDraw`，分配失败、其他程序错误及设备丢失不被吞掉。

原版直接接管资格仍按实际变换和状态判断，不按安装 Veil 整体改道。已有 FBO 缓存、尺寸失效、异步 shader 重载和受限世界效果继续沿用；不建设任意程序解释器，不放开普通世界后置光栅。

### 自动证据与边界

本体完整 `spotlessApply check verifyRelease verifyCompliance --strict` 成功，非 GPU CTest 79/79；定向自定义顶点布局／framebuffer GPU 测试 2/2 成功。Extra 120 项测试、发行和严格合规通过。相同整数／相等记录下的独立编译所有权、替换失败回滚、缺少支持程序、dirty／尺寸变化、独立 uniform 副本及退休版本复用均有定向断言。

首次客户端用例缺少 GUI 作用域，被现有权限正确拒绝，读回空白后由探针断言停止；没有设备丢失。保留其日志、崩溃报告和源码身份，修正探针作用域及明确绘制状态后进行有效验证，不修改产品权限来通过用例。

最终 C 配套在 `platform-reorganization/sources-20261028-235524/` 完成两个重载前后检查点，固定／动态 block 各自的 32 次未变化写入只序列化一次；dirty 和尺寸变化重新序列化，旧绘制副本不变。每个检查点连续三次全屏绘制保留绑定，16×16 Vulkan 颜色读回符合源像素。平台、实体、正常保存和退出检查均通过，加载 DLL 与冻结包匹配；没有设备丢失，也没有性能收益或人工视觉通过结论。前一 B 配套的有效会话为 `sources-20261028-234701/`，不将其结果冒充 C 的验证。

## 结论

本轮减少的是已确认的重复序列化、分配、全屏几何生产及无消费者广播；变化检测沿用来源合同。支持边界、GPU 在途版本和实际每次绘制的独立状态继续保留。不由单元测试数量推导所有 Veil 效果兼容，也不由减少工作量推导整帧收益。
