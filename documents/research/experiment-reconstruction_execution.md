# 重建引导与渲染执行实验

2026-11-10。基线使用本体 `8ee195f` 和 Extra `8728777`。保留开工时的重建引导前移及重放实验入口。按 A、E、C、B、D 推进，SER 全程关闭。

## 问题

在相同场景、成像质量和重建条件下，缩短主线程和世界 GPU 路径，并定位重放管线多次重建后的染红。最终参照城市＋SPBR 与 RTX Remix 在 1440p、32 视距、RR Balanced、关闭 FG 时移动和转头的 16.67 ms 帧预算。

## 方法

在每张卡开工前记录限制方、上界、判别实验和门槛。正式对照保持单变量，使用前后基线衡量波动，另记 RR 和画面差异。正常比较每个重放进程最多两个窗口，染红窗口只用于查错。每次 GPU 运行检查环境、历史闸门和独立内存保护，遇到新的设备丢失或内存保护事件时停止全部 GPU 运行。

### A 重建引导前移

多层玻璃重放受 GPU 限制。历史主队列为 68.3 ms，运行时跳过引导但保留代码为 39.9 ms，完全移除引导为 36.3 ms。这把潜在上界限定在约 32 ms，已见的前移候选目标为约 19 ms。Remix 的预期变化接近波动。实机城市受 CPU 限制，不能把同等 GPU 节省直接记到整帧。

同一构件和快照只切换引导调用位置。重放按前后基线夹候选，以 RR 2.19～2.45 ms 和 R/G 核对可比性，记录固定与转头画面。实机使用相同冻结输入和配套，记录移动与转头。优先核对首命中材质状态、覆盖率分支与介质历史。通过要求为直接相关的 GPU 契约和 Vanilla PT 介质回归通过、图像差低于城市玻璃 0.29／Remix 0.45 的噪声底、玻璃主队列不超过 51 ms、Remix 无可辨认退步。

### E SHARC 多次重建后染红

历史复现窗口中，正常 R/G 为城市玻璃 0.991、Remix 0.745，异常分别达 2.15／3.79 和 1.83。判定目标为每图 7／7 窗口相对同进程第一个正常窗口的 R/G 差不超过 0.02，并检查截图；撤回修复后至少复现一个染红窗口。限制方是定位证据，染红窗口的性能数字无效；先在一次约一分钟的重放中比较重建 2、3、4 的设备地址、显存分配与清零，再以少量采样对照累加、解析和查询读取。若第 3 窗口首次使用前已经有非零，先查新旧缓冲所有权与清零；若初始数据一致，沿同一体素索引追查第一处不一致。只在追到首个分歧后改对应环节，实机重载独立验证是否同一问题。

### C 常驻实例稳定槽位

以修复染红后的产品为本卡基线。城市移动仍主要受 CPU 限制，当前参考 CPU 约 30.5 ms；若常驻元数据与选择的 4 ms 全部归零，仍约 26.5 ms，达到 24.5 ms 还需要来源或 JNI 约 2 ms 的独立收益。目标为同路线 CPU ≤24.5 ms，两段元数据和选择合计 ≤0.6 ms，静止帧 JNI 提交 ≤3 次、元数据上传 ≤1 MB。先比较真实 changed、selected、removed 数和元数据每帧实际传输，区分内容修改、可见集合变化、空间变换及历史成本。槽位实验必须保持变动、迁移、卸载、辅助视图和重载后的资源正确，实机前后基线评估收益。

### B 缩短引导结果的存活时间

Remix 受 GPU 限制，A 的固定重放主队列为 22.55 ms。早期死代码对照估计还有约 2.3 ms 静态成本可以争取，目标 ≤20.0 ms，图像差 ≤0.45，RR 保持在 2.19～2.45 ms。先单独量首命中上帧法线分支的静态成本，再只改变引导结果存放位置，比较前后基线。用已有输出的格式表达直接输出；需要参与合成的高精度输入保持精度。若剩余成本主要是真实引导射线，仅在能证明两个分支的下一命中相同的位置讨论复用，不减少光路覆盖。

### D 帧线程与主动光源采样

帧线程目标是查清实机移动时主线程等待多少，以及它在不等待时能和 Native 工作线程重叠多久。先在同一个产品包加计时，再只切换现有帧线程开关，比较城市 A／B／A 的真实帧间隔、P99、渲染线程实际 CPU 与 RR。若可重叠窗口均值不足 1 ms，则当前交接位置最多只隐藏这段时间，不扩大队列；若达到 1 ms，继续检查整帧是否超过两侧基线的波动以及等待是否转移。必须单独标出线程墙钟重叠的上界，不能把可运行时间当作同时占用 CPU 的时长。

光源表目标是查明从已发布来源到采样及真实命中的数据能否配对。以夜景的普通命中照明为能量基线，至少分别核对区段和运动来源，开关两侧的线性 RGB 区域均值差应低于重复基线区间或 2%，取较宽者。以相等时间的噪声变化或达到相近噪声的时间为收益依据。若直接复用区段记录和 Advanced 的采样会重算已有贡献，先验证命中身份与采样概率能否闭合。已有 Advanced 夜景直接光阶段约 0.23 ms，这是当前静态路径的量级参考，并非通用表的开销上界。

## 发现

### A 构件、契约与首批重放

候选本体 `2dc06822904b`，基线本体 `20162fa60192`，实机配套 Extra 产品包 `52a49fb65298`。本体只更换 Vanilla PT 算法包内的 `world/world.rgen` 及对应的包校验条目。通过 85 项 Native 检查和五项定向 GPU 契约。Vanilla PT 客户端通过全部 20 个介质回归，检查了水下出水和全反射、异色玻璃的接触截图。

城市玻璃固定视角的两组重放按前移前、前移后记为 63.01 → 49.11 ms 与 60.94 → 43.39 ms。RR 对照量 2.22～2.37 ms，R/G 0.9931～0.9934。候选和基线图像的平均 RGB 绝对差分别为 0.2888 和 0.2929，同侧跨进程分别为 0.2913 和 0.2914。第二组超过按两位小数记录的 0.29，四舍五入后与同侧波动同档。目视核对第一组的多层玻璃、后方条纹和手持物轮廓。

城市转头重放首组 RR 为 2.495／2.659 ms，计时不纳入收益。有效组主队列 63.85 → 46.28 ms，世界 PT 57.35 → 39.66 ms，RR 2.282／2.255 ms。转头图像差 0.409，两版各自重复转头的差异为 0.403～0.412。Remix 固定首组为主队列 22.66 → 22.55 ms、世界 PT 17.85 → 17.72 ms、RR 2.280／2.368 ms、图像差 0.298。该组重放墙钟间隔却从 23.00 增至 28.79 ms，P99 从 29.14 增至 39.93 ms，已测的获取、帧槽等待与呈现不能解释差额。其余 Remix 重放两次预检遇到桌面 3D 负载超门槛，没有发出 GPU 测试提交。不能据此排除 Remix 帧间隔退步。

首轮实机误用 Extra 探针包 `d00f694699c0`，NeoForge 报缺少 `radiance_extra`，未进入世界。保留原 STOP 和失败日志，经用户批准登记后使用由 Extra `8728777` 构建且通过 `verifyRelease` 的产品包复测，恢复仅限此项实机对照。

城市实机用相同路径左右移动约 8 m、转头约 24°，两次基线夹一次候选。整帧均值为 32.60／29.20／31.27 ms，P99 为 51.35／48.60／50.75 ms，渲染线程实际 CPU 为 31.20／28.88／30.42 ms。定向计时的世界 PT 为 20.75／18.24／21.63 ms，RR 为 2.327／2.214／2.449 ms。三次均未观察到另一个游戏进程。候选的世界 PT 低于两个基线，RR 也更快，具体收益幅度仍受 GPU 运行条件影响。固定截图的窗户、建筑边界和第一人称模型未见缺失。该实机视角是城市上空，和多层玻璃重放场景不同。

Remix 实机基线整帧均值 29.63 ms、P99 43.69 ms。候选启动前五次桌面 3D 负载在 20.4%～34.5%，未达到安静门槛，候选和回测基线未运行。保留 A 及已完成的证据，Remix 实机对照门槛暂未闭合。

### E 首帧写入失衡

Remix 地址与清零读回两组都在第三窗口复现。设备地址可以在已等待空闲的世代间复用，第二和第三窗口的累加与解析地址相同而颜色不同。四个数据缓冲在每个窗口的第一次更新前逐字为零，包含第三窗口，R/G 仍从约 0.746 变为 1.830。

每窗抽查 32,768 个槽位，在 SHARC 光线更新后、解析前读出累加和键，并在解析后读出同一槽位。第三窗口第一帧与第二窗口共有 332 个同键体素，样本数一致；槽 3618 只收到一个样本，累加 RGB 已从 `(0, 0, 0)` 变为 `(12504483, 30, 3044940)`，解析值约 `(12504, 0.03, 3044)`，符合该累加值除以量化系数。第四窗口同槽位约 `(1.233, 1.213, 1.109)`。因此首个实测异常已位于第一帧更新写入的辐射度，早于解析或成像查询。

对应的数据依赖是天空与大气生产顺序。SHARC 更新在执行计划外抢先录制，会在重建后的第一帧读取尚未生成的透射查找表与天空立方体。假设成立时，只将 SHARC 更新移到首个实际消费之前，固定夹具的首帧累加值应恢复正常，异常窗口应消失。快照、着色器包、重建次数和其他输入保持相同。

调整 `RayTracingModuleContext::render` 后，Remix 七窗 R/G 都为 0.74488，城市玻璃七窗为 0.99095～0.99096。Remix 第 2、3 窗在第 0、7、120 帧抽查的 332、1,330、3,856 个同键体素，累加和解析均无差异。旧顺序使用相同体素诊断时第三窗仍为 1.83014。目视核对第三窗，城堡与树冠恢复正常颜色。产品补丁只调整录制顺序，地址与体素读回诊断源码和证据另行保全。

本体 `d18f82244c0b` 和 Extra `52a49fb65298` 的隔离城市客户端连续重载五次，正常保存退出。重载前与五次重载后的截图 R/G 为 0.855～0.862，未出现重放所见的整体偏色；部分远景区段尚在恢复，不能逐像素比较。未在旧版实机复现使用者的偶发发紫，无法认定其与此故障同源。通过 `spotlessApply`、`check`、`verifyRelease` 和严格合规检查。

### C 判别基线

城市静止窗口每帧约选择 13,098 个刚体实例，发送 445 个变更，约占 3.4%。两段刚体整理和元数据选择为 1.84／1.35 ms，主机元数据上传 8.58 MB/帧，表上传依然远多于实例变更。移动参考窗口为 2.18／2.27 ms、8.66 MB/帧。静止的 `FRAME_ONLY` 帧时间 24.07 ms，不能用来代替移动门槛。第一候选让原生持久记录拥有独立的几何区间，并按区间稳定的记录计算补丁；相同记录留在已完成的录制槽位，补丁保留在途版本，实际重复选择不共享冲突区间。

第一候选将静止的上传减至 1.98 MB，但元数据选择增加到 3.35 ms，整帧为 30.00 ms，RR 2.72 ms 超出对照区间。第二候选省去已完成槽位的无效复制清单，邻近基线的上传与选择为 8.57 MB 和 2.19 ms，候选为 1.98 MB 和 3.22 ms。仍然逐帧整理表再检查哪些行相等，CPU 开销没有收回。两版 Native 槽位实验已撤回，仅保留对应差异与样本。

逐条读取静止窗口的提交事件，29 次调用中 28 次只有选择，另一次带 445 条变更。单独测试 Java 帧内批量选择：不变项共用提交，遇到变更或删除前按原顺序提交积累的选择，帧关闭前送出余量，放弃帧时丢弃。只合并已接受且没有新纹理、绑定或几何的选择。

Java 候选 `fc6f3787c29d` 的静止提交为 5 次，选择总量保持 13,098，重载和正常保存通过。两次未合并调用有独立的来源绑定或纹理所有权边界。整帧均值为 28.22 ms，RR 2.68 ms，超出对照区间，元数据上传仍为 8.57 MB。第二轮 Native 候选的回测基线也因桌面 3D 负载超限未启动。三项 C 门槛未闭合；原地字节判等路线已证明会转移成本，Java 候选暂不进入产品，仍缺按来源版本直接发布元数据的路径。失败实验差异保留在本轮外部证据目录。

### B 候选及运行阻塞

独立打包两个着色器变体。第一个只让首命中的引导专用历史法线分支在运行时不执行，供归因使用，不作为视觉候选。第二个在追踪后以现有输出格式写入引导，将完整法线、运动和材质数据移出后续光路的局部状态，只留下主导路径选择。需要参与合成的计算仍在原精度进行，末尾单独更新两张运动深度图的命中距离。空引导像素保留原有默认输出，避免读取上一帧残留。

两个变体分别在三种覆盖模式、引导开关两侧离线编译并通过 SPIR-V 校验。离线校验未涉及实际驱动的寄存器分配，也无法检查画面。两次有界正式启动预检均未得到安静窗口，第二次的五次桌面 3D 峰值为 16.2%～49.8%，高于 10% 门槛。未提交 GPU 命令，未取得 Remix 的对照量、画面及耗时，两个变体均未进入产品。

粗糙度为零也不足以证明可以复用两条成像分支的第二命中。引导查询要沿连续光滑介质继续展开当前与上一帧的几何，分裂成像则用本身的查询用途、随机种子、光路终止和 SHARC。即便第一段方向一致，若第二命中仍是光滑介质，它只是引导的中间结果。直接复用第二命中作为最终引导会丢失这一段。

### D 帧线程计时与光源所有权

在现有单帧交接点增加 `frame-worker.producer-blocked`、`frame-worker.overlap-window` 和工作线程执行区间。前者只量发起交接的线程实际在条件变量上等待的时间，后者量工作线程执行与生产者首次等待前的交集。Java 可能在此交集中空闲或被调度走，因此它只给出可隐藏开销的上界。用现有计时开关启用，未扩大在途队列。

代码上的首个常规回收点是 `RenderSystem.flipFrame` 入口，在事件处理和排队录制之前取回当前帧所有权。11-09 旧的同产品包 `71b382752512` 城市窗口，帧线程关、开时渲染线程 CPU 32.22、18.39 ms，真实帧间隔 34.50、32.24 ms，RR 2.502、2.391 ms。CPU 归属确实变了，基线 RR 超出本轮可比区间，且当时没有阻塞和重叠计时，不能据此启用或进一步拆分帧线程。

当前本体 `fa8522e2db34` 的格式、构建、Native 帧交接契约、发行包和严格合规通过。原定实机对照的五次预检中，同一设备上的其他 3D 工作带来 23.2%～36.8% 的峰值，未达到 10% 门槛。未启动客户端，暂无实机等待与重叠数据。现有帧线程默认关闭。

现有近景表由 `ChunkBuildData::buildLightInfos` 构建，采样端使用区段索引、区段内图元和 UV 子区域。它要求贴图且从四边形的 UV 查找发光区域，未接入随实例移动、形变、按实例改色或程序求值的来源。Advanced 已能按所选区段光源的身份重验其可见性和辐射。Vanilla PT 的 LoD 与程序薄层已有采样配对，普通近景主要沿光路累加发光。两内建包可在关闭收集时运行，但没有共用所有来源的主动采样表。

若直接叠加普通面光源采样，一个无遮挡的漫反射接收面会同时收到完整的命中估计和完整的主动采样估计。两者各自期望为同一贡献，直接相加会重复计算。光源表还缺真实命中侧可反查的采样概率，动态表需要身份、材质和姿态同时有效。已有夜景 0.23 ms 数据只比较 Advanced 的贴图求值与平均发光，无法证明开关两侧的能量一致。本轮未改光源默认和产品路径。

## 结论

保留重建引导前移、SHARC 生产顺序修复和按需的帧线程计时。城市玻璃重放与城市移动实机各自有可量化改善，城市移动仍未达到 16.67 ms。Remix 的 GPU 主队列暂未见退步，重放帧间隔与实机候选仍缺可比数据。

常驻实例实验省下传输却增加了逐帧选择成本，单独合并 JNI 调用也未达到门槛，两项均未进入产品。B 的两种着色器变体仅完成离线核对。D 已能记录交接开销，尚无证据支持开启或扩大帧线程。通用光源表仍缺采样与真实命中的配对，现有主动采样和命中发光方式维持现状。

未执行 SER 重排，未新增设备丢失或内存保护停止。本轮回收 1.64 GiB 可再生产物，保留停止标记、前后截图、原始体素读回与源码差异。
