# Veil 接管边界与资源复用调查

2026-10-28，基于 Radiance 与 Radiance Extra 当前工作树，以及本机已登记的 Veil 4.3.2 源码进行静态调查。本轮未运行游戏、测试或性能采样，未修改 Veil 产品实现；下述代码行为与实际运行影响分别判断。

## 问题

确认 Veil 修改原版后的解释归属，区分已支持的界面、离屏及世界输入与未支持程序，并定位重复生产、异常收尾和资源复用的具体缺口。允许未适配效果缺失，不扩建任意着色器解释器，不恢复普通世界的后置光栅几何。

## 方法

读取两仓库的接管、状态、程序、顶点数组、FBO、动态缓冲及重载路径；与 `D:/Workspaces/References/minecraft-references/veil-4.3.2/` 中登记的源码对照。该参考记录指向 `540ad3778c1a5dafe905420adb21cb05e459b5c4`；Target 当前依赖版本为 4.3.2。未以相邻版本推断兼容性。

## 发现

### 原版与独立 Veil 输入没有整体互换

`SourceCompatibility` 检查实际加载类的变换记录，`ReviewedTransformations` 校验登记的类资源哈希。Extra 登记了 Veil 的模型管理器 getter 和 RenderType 修改；`VeilIntegration.supportsStaticState` 继续检查实际追加的状态片段，未知追加状态保留完整来源执行。类名用于划定 Vanilla 阶段范围，不是唯一的接管资格证明。

Veil 对原版 shader 的 CPU 预处理通过 `VeilVanillaShaderReloadBridge` 保留，按 ticket 配对顶点及片元阶段，过期结果不覆盖最新结果。Veil 的独立 `ShaderProgram`、FBO、顶点数组和事件则通过 Extra 的专用适配器接入。`VeilMixinCompatibility` 有意关闭的 OpenGL 程序替换与反射不能等同于关闭全部 Veil 行为。

事件包装继续在来源阶段执行一次。明确的法杖世界生产者使用 `WorldGeometryStageListener`，不再交给通用事件包装重复捕获；普通事件线使用共同线请求。GUI、图解和明确的离屏绘制保留 Vulkan 光栅路径。屏幕覆盖 `veil:core/blit_screen_effect` 按真实纹理与 uniform 进入现有相机效果路径。

### 未支持输入的失败边界还不完整

`VeilVertexArrayBridge.draw` 对没有世界语义的主世界顶点数组直接抛异常，事件包装本身不隔离这类拒收。包装缓冲只有 OpenGL ID、SSBO、未支持阶段及部分索引形式也存在显式拒绝路径。来源的后处理管理器会捕获部分管线异常，但这不能证明其他事件或图解调用也不会中断游戏。

应在整个效果或提交边界识别不支持，并成对结束其绑定及资源借用。不能全局吞掉异常、把不明几何补到世界光栅，或把真正的设备故障当成可忽略效果。已有 `WORLD_RASTER` 许可区分了后处理与普通事件几何，但 Veil 后处理许可仍是类别级别，不能据此证明任意程序都只做屏幕操作。

### 程序绑定与退休需要补齐来源语义

Veil 4.3.2 的 `ShaderProgramImpl.bind` 会解绑 packed shader block，并应用程序声明的混合状态；`ShaderProgram.unbind` 会收尾 packed block、采样器与混合状态。当前替代主要设置 `CURRENT_PROGRAM` 和块映射，未完整复刻这些步骤。对于实际使用这些声明的程序，这是已确认的实现差异；具体视觉影响尚未实测。

块绑定不是全部临时状态：来源还具有跨程序共用的全局块。修正时必须区分全局、packed 和程序自有块，不能以每次清空所有绑定代替正确生命周期。

多动态缓冲变体的释放还需定向验证：`freeInternal` 从当前程序进入 bridge 清理，而 `CompiledProgram.free` 仅清阶段、uniform cache 和依赖。非当前变体对应的 `MODELS_BY_NATIVE_ID` 记录可能残留。同掩码替换也先发布并释放旧记录，再附加新记录，失败时的保留与回滚边界应验证后处理；不能仅凭该路径宣称已经发生 Native 显存泄漏。

### 资源成本有明确来源，也有现成的复用

| 路径 | 可由代码确认的行为 | 处理判断 |
| --- | --- | --- |
| `RadianceVertexArray` 更新 | 持久句柄每次上传调用 `Buffers::initializeBuffer`；持久分支总是新建底层设备缓冲并退休旧缓冲 | 有复用空间，但旧版本保护是必要的；应按安全槽位、容量及在途读者复用，不能直接原地覆盖 |
| 动态／定长 shader block | 每次绘制快照分配堆缓冲及临时 native 缓冲，再序列化和复制 | 可复用适当容量的 native scratch，并按来源 dirty／尺寸维护快照；不能只比较可变对象身份 |
| 通用 screen quad | 每次生成固定三角形并上传 | 可复用稳定几何；底层普通帧槽已有容量复用，不能描述成每帧必定重新分配 GPU 缓冲 |
| Veil 额外区块层 | 每次调用复制原区段列表、收集当前区段并按相机距离排序，来源随后继续整理该图层 | 先过滤不支持的主世界路径；实际保留的离屏消费者再按内容版本和视图复用，不能跨相机冻结排序 |
| FBO 与动态附件 | 来源管理器缓存 FBO，在尺寸或动态缓冲配置变化时重建；Extra 创建失败会释放附件并恢复绑定 | 未发现普遍逐帧重建，不应整体重写 |
| Sable 动态程序 | 按 shader 源身份及动态缓冲掩码缓存，使用 `getNow`，旧程序完成后退休 | 已有合理机制；未发现需要取消的逐帧阻塞等待 |

上述成本没有本轮帧时间数据，不据此排序全部 CPU 热点或承诺 FPS 收益。未知效果仍可能走到这些入口，静态可达不等于当前场景每帧调用。

## 结论

保留当前 Vanilla／Extra 分工与公共 Vulkan 执行机制，实施应先补程序绑定、释放和不支持效果的安全边界，再针对实际消费者收敛缓冲与快照成本。不需要重建整个 Veil 适配层。

后续验证应覆盖：原版对象在 Veil 缺席／存在时的路由、事件仅执行一次、图解与 Ponder／GUI、世界屏幕覆盖、不同混合声明、全局与 packed 块交替、未知程序安全缺失、同掩码及多掩码重载、尺寸变化和在途更新。自动结果、实际画面与性能收益分别报告。本记录不恢复已暂停的 Voxy 工作。
