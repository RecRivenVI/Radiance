# Sable 与 Flywheel 共同交接

2026-10-27，修复合并及结构与主世界之间的 Flywheel 闪烁，检查装配、拆解、分离、合并与表示切换。API 9 最终配套候选为 `validations/conformance-takeover/result/sable-handoff-20261027-k/candidate.json`；自动功能回归通过，连续视觉仍待使用者验收，没有性能测量。

## 问题

区段已有替代版本门槛，Flywheel 却独立删除旧实例和 embedding，再建立新实例。只等待区段不能保护实例、模型及其父空间。合并还可能进入另一 sublevel，原处理却把所有移除都当作返回主世界。

拆分关系在当帧清除，孩子数据未准备时可能丢失来源关系；关联交接逐项提前返回，也可能让同一 Native 组的 Java 回调与局部表示选择错开一帧。来源删除和卸载必须与成功搬运区别处理，不能无限保留旧对象等待不存在的目标。

## 方法

核对实际 Sable 2.0.6、Flywheel 1.0.6 与捆绑 Simulated 1.3.2 JAR，结合留存源码检查跟踪、Finalize、RecentlySplit、胶水伙伴、方块实体视觉构造、实例删除与 embedding 关闭。不更改来源网络协议，不引入固定帧数延迟或另一套区块系统。

本体执行 `spotlessApply check verifyRelease`、24 项显式 GPU 回归及探针／开发 API 构建；包含 79 项非 GPU Native 检查。Extra 执行 `spotlessApply check verifyRelease`、探针编译及严格合规，108 项 Java 测试通过。文档追加结果后另行执行 Markdown 与严格合规检查。Native 算法与帧退休不变，公共 API 版本升至 9。

冻结实际发行包、DLL、配套 PDB 和源码，沿用 `world_materials.py handoff`。最终运行目录为 `validations/conformance-takeover/result/world-materials-134/sable-handoff-k-handoff-20261027-212735`。使用项目内 1920×1080 静音实例、轻量取证与 Aftermath，显式复用自有 E 会话缓存；不测试性能，不以缓存结果评价启动耗时。结束后逐项校验归档并回收复制客户端。

## 发现

### 统一发布边界

公共 `SectionHandoff.Participant` 提供准备、发布和取消。所有相关门槛先准备，再全部尝试提交，最后统一选择局部表示。区段使用当前请求版本的 GPU 完成状态；实例模型沿既有有序上传、BLAS 与 TLAS 帧依赖执行。旧资源仍按已有机制退休，没有 GPU idle。

Flywheel 在真实方块实体 visual 构造时捕获所有者，持有的 provider／instancer 保留该归属；不从共享模型或 renderer 类型猜测实例属于谁。交接期间旧实例的删除暂缓，新实例等待模型准备。仍在活动的旧来源继续更新；被来源删除的旧可消费版本保留到交换。模型、instancer 和 embedding 空间一起保留，原点重定位在旧租约结束后再进行。多个交接分别持有租约，不能提前释放彼此的资源。

### 操作覆盖

| 操作 | 来源关系与准备 | 发布与清理 |
| --- | --- | --- |
| 主世界装配 | 最终跟踪数据、格点映射、实际 visual 所有者 | 世界区段与新结构内容共用门槛，旧实例至替代准备后撤下 |
| 分离 | RecentlySplit 的父子身份保留到孩子准备；父版本先保留 | 关联区段合组，回调完成后再选择局部表示；父结构被实际移除时不先丢掉仍在使用的关系 |
| 合并 | 来源胶水伙伴给出实际接收 sublevel，以搬运后的锚点方块确认收到 | 等待接收区段及替代实例，关联双方交接，不统一改成主世界目标 |
| 拆解回世界 | 来源逻辑／显示边界、整数格映射及方块实体生命周期 | 等待世界当前版本与 visual 准备；来源更新完成回执可以确认已加载位置确实没有替代实例 |
| 单块与多区段切换 | 当前 renderData、待发布局部模型或区段 | 沿同一门槛选择表示，来源不变的实例继续保留 |
| 删除、卸载、重载与退出 | 终止租约与过时来源，不冒充成功搬运 | 清理已移除接收方和拆分关系；Flywheel 自己的世界关闭回调清理所有者，不依赖 Sable 安装 |

只在可确认的格点变换中映射来源位置；不逐顶点比较或 hash。实际用例中映射缺失为 0。空目标须由来源更新完成且区块数据已加载，或目标确实收到后被移除来确认；未知／不可用数据不直接作空处理。

### 失败与实际结果

首轮 F 候选保留胶水关系，却用插值姿态距离否决合并，最终等待错误的世界目标而超时。失败记录与产物保留，正常退出，没有设备丢失。后续记录显示合法搬运时姿态差约 1.29 格，因此不再将这个距离用作操作身份；使用实际伙伴和收到的方块确认。

最终 K 完成两个共享金块、单块→多区段→单块、分离、回世界、关联门槛、两次资源重载，以及真实 Create 转轴的装配、回世界、合并、再次分离、父结构完全消失的整体分离和直接删除：

- 28 次区段／表示交接完成，0 项积压；18 次 Flywheel 交接完成，0 项积压。
- 搬运窗口内两根转轴的 Native 实例登记数最低为 2；旧实例保留发生 9 次，替代暂存发生 8 次，直接删除没有对应的新实例。
- 最后明确删除一根转轴后，登记数正确降至 1；没有幽灵副本，合并关系索引为 0。
- 金块稳定窗口构建数保持 1，选择次数继续增长。Create 自定义烘焙模型仍有实时退回，不将它记为稳定模型覆盖成功。
- 实际配套候选退出码 0，无崩溃报告、设备丢失或 Aftermath GPU 转储。截图可见转轴与目标结构，但单张截图不能证明整个动画不闪烁。

### 实施与验证边界

统一的是区段、局部块模型与 Flywheel 持久实例的发布协调。普通 BER、普通实体及未知程序化内容仍按已有来源执行，本轮没有缓存其上一帧最终顶点，也没有宣称任意捕获批次已经获得跨来源原子交接。

夹具使用实际搬运 API、真实胶水伙伴同步与实际 visual 模型，但未覆盖任意网络乱序、未知第三方搬运协议或所有复杂运动结构。来源未提供的操作身份不能用空间距离或网格相似代替。使用者仍须观察巨大结构上带动画的组件、反复合并／拆解及快速连续操作。

## 结论

持久几何与 Flywheel 现在沿已有发布门槛协调，修正了独立撤下、错误接收方和关系过早失效。正确性自动证据支持提交连续性及资源清理；没有性能结论，也不把它写成用户视觉验收通过。最终候选本体与 Extra 必须配套更新，Prism 仅投放、不启动；实际回执登记在候选目录中。
