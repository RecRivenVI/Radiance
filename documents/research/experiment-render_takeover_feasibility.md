# 独立绘制接管关键路径可行性实测

2026-10-19，在当前工作区及已推送检查点上执行非性能功能实验。接管层独立于 Flywheel，Flywheel 仅为来源之一；本记录区分实际数据、现有后端能力和待实现的统一合同，不宣称完整接管或最终视觉等价已经实现。

## 问题

使用者要求正式工程前先验证关键路径能否由 Radiance 独立拥有，而非要求所有来源实现 Flywheel。需验证独立资源／实例输入能否进入现有世界 PT，以及原版姿态、外观、状态、离屏依赖和实际模组来源能否保留；性能实验没有授权，不采集帧耗时、FPS 或优化收益。

本次基线为已签名并推送的 `e76aa2c6b846b63e11a1caa3d38aefb972a22338`，原生 core SHA-256 为 `B023613AE93F98B4D54433ADB97D78D50DB1A380D4F8403F83FBE580F30A712C`。实验仅新增／修改探针、工具、验证配置和文档；没有修改产品 Java、JNI、原生渲染逻辑或 shader。工作区内容不能仅以 HEAD 代表。

## 方法

### 输入与实验边界

执行[独立接管验证](../../validations/conformance-render_takeover/validation.md)，模组列表只有 Minecraft、NeoForge、Radiance 与探针，不安装 Flywheel。配置为 1920×1080、主音量与音乐为 0，Vanilla PT／NRD／FSR 预设；本次内部分辨率为 1280×720。它是功能配置，不与城市或其他分辨率性能比较。

`TakeoverRigidBridge` 在探针模块内建立一份局部几何和两个稳定实例，给出不同颜色、姿态与镜像变换，经现有 `RigidModelCapture.Batch` 和 JNI 进入 native 世界场景。桥不实现或调用 Flywheel API。为避免为了实验扩大产品 API，本次通过反射访问受限测试接缝；正式公共合同不能沿用这个反射桥。Java 输入同步复制与 GPU 引用退休继续由既有后端负责，不建立第二套设备或退休系统。

真实原版模型仍执行原动画／renderer，通过现有 `PartModelProbe` 与 `RigidModelProbe` 对照局部模型输出和原始顶点展开；服务端改变两个盔甲架的姿态和手臂可见性，并确认客户端收到状态。该比较为 CPU 顶点／属性证据，不冒充所有 GPU 命中、动态历史或最终视觉证明。

`OffscreenDependencyProbe` 实际创建两个 64×64 附件：向 A 绘制红色底与半透明蓝层，B 采样 A 后再叠半透明绿色。通过当前 Vulkan 翻译路径读回两处 RGB，期望为 `(127,0,128)` 和 `(191,64,0)`，各通道容差 2。重载前后各执行一次；结束恢复原目标、viewport、矩阵、程序、纹理及状态。它证明本组合的真实写入→采样→再混合依赖，不证明任意程序／深度／模板组合。

随后执行现有[线条生命周期验证](../../validations/regression-line_capture/validation.md)，启用只读来源观察。该完整模组夹具运行原始 Simulated emitter、Sable 包装器、Veil／NeoForge 事件和 Create/Flywheel 既有后端；观察器只记录实际模型／实例与调用，不把它们迁入新公共协议。

所有客户端均为项目内拥有标记的验证实例，没有使用 Computer-Use、操作 Prism、故障注入或性能采样。轻量取证与本地 Aftermath 接通；没有设备丢失，零转储在这里不是采集失败或故障根因证据。

### 命令与源码证据

客户端准备、运行和分析命令见对应验证。另执行：

```powershell
.\gradlew.bat :native_renderer:gpuTest
.\gradlew.bat spotlessApply
.\gradlew.bat check verifyRelease verifyCompliance --strict
```

GPU 任务增加 `--stop-on-failure`，首个失败后停止同组，避免设备故障后继续派发测试。它不改变产品渲染。

本轮命令输出位于 `build/checkpoint-20261019/`。独立实例的 `result/source-identity-02.json` 记录 2,081 个源输入的原始字节哈希，`source-delta-02.zip` 保存对应未提交源码与差异；不做换行规范化，不用旧源码推造新哈希。后续分析器、文档和任务准备范围修正另以最终清单记录，不冒称它们在更早运行时已经存在。

各成功案例的 `runtime-identities.json` 是清理前提取 DLL 的路径、大小与哈希清单，并非操作系统的已加载模块快照。独立实例中所有 core 副本均与本次构建一致；来源实例还包含旧 core 副本，SDK 日志定位本次使用的运行库目录为 `549c77d3e3721a1323abfebc346724a630e7c192a25f49f56d67bb044d3f3a8b`，其中 core 哈希与构建一致。这是运行库目录及提取身份的证据，本轮没有另取 OS 模块映射，不升级为直接测得的模块哈希。

## 发现

### 首次预检失败与纠正

第一次客户端在 JPMS 模块检查阶段失败：探针桥放入产品包 `com.radiance.client.vertex`，造成 probe 与产品 split package。没有进入世界，也没有 GPU 设备丢失。随后将桥放回 `com.radiance.audit`，通过探针专用反射接缝访问 ABI，未扩大产品公共 API。首次日志与说明保留在 `validations/conformance-render_takeover/result/runs/01-jpms-preflight/`，不能将它写成首次即通过。

共享准备任务原先会触碰其他基础验证目录；本轮加入显式 `RADIANCE_VALIDATION_NAME` 选择，本轮运行只准备当前项。未设置时保留原有行为，不声称已重构全部验证的实例所有权。

### 无 Flywheel 独立实验

第二次进程通过，11:02:58 进入世界，11:03:29 请求正常结束；这段时间只表示功能覆盖时段，不是计时窗口。完成资源重载、所有维度保存、native 世界释放和正常退出，Gradle 返回 0。`feasibility.json` 及分析器确认：

| 证据 | 实际结果 | 证明范围 |
| --- | --- | --- |
| Flywheel 是否加载 | 否 | 独立输入不要求 Flywheel 存在 |
| Java 桥局部网格创建 | 2 次，分别对应重载前后 epoch | Java 每帧使用资源引用；native BLAS 构建次数本轮未单独计数 |
| 实例提交 | 10,356 次、5,178 次绘制回调 | 两实例共享资源且外观分开；不是帧率指标 |
| 真实部件对照 | pose 检查点 449 次、10,776 顶点、12 模型，位置／法线最大误差均 0 | 实际 `Cube.compile` 对照，非所有实体 GPU／视觉证明 |
| 实际烘焙对照 | 625 次、21,720 顶点、15 模型，位置／法线最大误差均 0 | 所选夹具实际触发的烘焙路径 |
| 离屏数值 | 重载前后两处 RGB 均通过容差 | 附件写入、采样及后续分数 alpha 混合 |
| 最终控制面板 | 重载前红／绿像素 10,341／10,329；之后 10,334／10,310 | 最终输出中两个受控实例仍分别可见，不是整幅视觉验收 |

控制面板统计仅检查图像中心限定区域，不使用全屏平均误差。对称面板的镜像可见不等于任意镜像模型的 UV／法线都已逐项证明。模型、附加层和 GUI 完整视觉仍待对应原图与使用者验收。

### 完整模组来源与生命周期

第二组进程 11:13:02 进入夹具，执行来源线条、取消阶段、1280×720 再恢复 1920×1080、F3+T 等效重载、退出世界及重进，11:13:58 正常停止。非法输入为 0，字体所有者最终违规为 0，维度保存及 native／SDK 关闭有日志；没有设备丢失。

Flywheel 观察到 5,417 次既有后端 render 调用、最大 2 个模型和 40 个实例。3 个 engine 身份跨重载／重进观察所得，不代表同时存在 3 个世界或实例总和。这证明现有来源适配入口实际工作，不证明新独立协议已接管 Create 全部 shader、Visual 或 crumbling。

线条来源 3～7 的请求／顶点计数均非零，非法输入和 Sable 无姿态回退均为 0；来源 0～2 未触发，不能补填原版实体／BER 全部线条通过。这些计数位于 JNI 前，不能独立证明 GPU 执行。证据位于 `validations/regression-line_capture/result/runs/takeover-20261019T032156Z/`；`client-evidence.zip` 的 1,158 个条目全部逐条读回 SHA-256 校验。

### GPU 与构建门槛

`gpuTest` 实际运行 22 项，22 项通过、0 失败、0 跳过。包括顶点转换、tessellation、自定义顶点数组、framebuffer、颜色同步、FG UI、执行缓冲、面规则、查询续接、材质／覆盖、刚性实例、成对面和 Voxy 紧凑面转换。它们是各自受控测试，不证明 Voxy 请求容量故障或真实完整来源已经闭合。

其中实际生产用转换 shader 对照了 CPU 打包、四边形／三角形、输出保护区、两批独立输入、拆分 dispatch 与 compute→BLAS；tessellation 用例实际执行四阶段 Vulkan patch 管线并核对 12×12 覆盖。这些是后端能力证据，不是已接管所有来源的声明。

`spotlessApply` 与 `check verifyRelease verifyCompliance --strict` 均成功，严格合规为 0 失败、0 警告。非 GPU 原生 CTest 本轮实际执行 74/74，采集器 2/2；probe 测试实际执行 41 项，bootstrap 实际执行 11 项通过／2 跳过。GAME 337 项、JNI 4 项及工具 Java 测试 11 项的任务为 `UP-TO-DATE`，不冒充本轮重新执行。发行检查核对 155 个必需条目和探针排除，JNI 头一致性与 Maven 开发构件检查通过。编译仍有既有 Unsafe 与 Gradle 弃用提醒，不能将合规零警告写成整个工具链没有提醒。

最终原生 core 与上述运行时提取身份一致。随后只补本记录的结果说明，执行 Markdown 与严格合规复核，不因此重跑 GPU 或客户端。

### 存储与实际清理

首个成功客户端生成环境后，预检曾测得工作区 16.219 GiB、验证合计 4.017 GiB，超过软上限／验证限额；立即保留日志、截图、源码身份与 shader 证据后回收生成副本。该次短暂超限保留事实，不写成全程均在预算内。

已通过 Windows 回收站清理本轮独立验证与线条验证的生成 client 环境，以及旧 smoke 验证的可再生 native 提取副本／缓存；先核实拥有标记、相关进程已结束、无转储，再保存 DLL 身份与逐条校验的证据。没有删除唯一证据、Prism 文件、正式世界、Git 管理引用或原生 third_party。此前已有结果先保存在各项 `result/runs/`，没有用新结果覆盖唯一历史副本。

清理后预检工作区 15.225 GiB、验证合计 3.023 GiB、冻结目录 1.918 GiB；外部受保护输入／SDK 例外仍为 7.999 GiB，未向外部新增大副本。清单见两项 `result/cleanup*.json`／`takeover-cleanup.json`；最终构建后重新统计，不能用本次数值代替后续占用。

## 结论

| 关键路径 | 本次结论 | 剩余边界 |
| --- | --- | --- |
| 独立模型／实例→世界 PT | 有真实无 Flywheel 输入与最终受控图像证据，具备继续设计基础 | 统一公共 API、所有生产者所有权与变更通知尚未实现 |
| 原版模型姿态与外观 | 实际 CPU 参考对照非零，姿态和可见性变化有输入证据 | 不是全部模型、运动历史或附加层完整视觉通过 |
| GUI／离屏依赖 | 实际 Vulkan 路径读回通过本组附件与混合组合 | 深度／模板、完整效果链和任意程序仍需逐项证明 |
| 模组实例／动态线条 | 原始来源、现有后端和生命周期夹具通过 | 不是所有模组绘制和新协议迁移通过 |
| GPU 后端基础合同 | 22 项通过 | 独立受控合同不等于客户端全场景正确 |
| 真实形变／粒子高层意图 | 动态顶点和 compute→BLAS 合同通过 | 本轮未把柔性弹簧、Necromancer 或 Quasar 的参数直接迁入新协议，连续形变与历史仍须来源专项 |
| 自定义世界表面程序 | 尚未实证完整求值策略 | 依赖屏幕颜色、深度、导数和多 pass 的来源，不能默认固定 PBR 等价 |
| Voxy | 紧凑输入 GPU 合同通过 | 当前根集合／8192 容量异常未修，真实 Voxy 客户端本轮未运行 |

判断是“已有关键通道具备实施基础，可以进入明确范围的接管骨架工程”，而不是“任何绘制都已证明可自动一比一替代”。下一步按[阶段计划](../project/plan-render_takeover.md)完成覆盖表与独立公共合同，先闭合一个原版刚性来源的完整生产链；Flywheel 适配随后使用相同合同，不能反过来定义公共层。困难表面程序和未触发来源继续明确登记，不以最终兼容回退永久替代目标。

本轮没有性能结论、正式接管实现、Prism 投放或新的提交／推送。开头检查点的签名推送与本轮未提交实验分开；未知 GPU 根因、长期稳定性和公开二进制许可仍未关闭。
