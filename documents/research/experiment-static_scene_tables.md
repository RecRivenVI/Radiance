# 静态场景表分段追加与重复组织实验

2026-10-18，按使用者授权细分静态场景追加和元数据准备，再实施分段上传与有界精确复用。局部 CPU 工作量和世界准备耗时下降，但同城整帧均值基本持平，p95/p99 未改善；不能将局部优化写成整体流畅度改善。保留三轮候选及中途成本转移，不扩大到动态几何生产或新的场景架构。

## 问题

既有 `StaticChunkScene` 已按发布修订缓存静态区块，因此不是重新添加一层区块缓存。本轮入口仍每帧把静态地址、历史地址和外观追加到临时连续数组，再复制到 staging；相机相关实例随后仍要组织。此前约 2.45 ms 的旧宽阶段仅作定位，下面另取新基线，细分静态表与实例变换。

九张表分别为实例几何偏移、当前 index/position/material 地址、上一帧 index/position 地址、历史变换、实例外观、水面排除域。CPU 录制、逻辑上传、GPU 完成和最终视觉分开，不把字节变化等同于每个字段均有语义变化。

## 方法

### 先取证及范围

只在 profile 开启期间，对每张完整上传表按字节比较；profile epoch／上下文首次观察也计入 changed，不能算真实变化。静态表追加、静态实例／相机变换、分配、staging 复制和内容 observer 分开计时。observer 本身约 1 ms/帧，两边均保留并单列；不是正常游玩时常开的扫描。

每次恢复同一个城市 ZIP，SHA-256 为 `40F41782F1A065500B321C6A588B925BD5425233D741E014EBC7F8DC833B3B02`。1920×1080、32 视距／模拟距离、Vanilla PT、RR Balanced、Reflex 2、FG 关闭、静音及模组不变；保留保存的相机。预热至少 60 秒且队列平静 10 秒后采样 60 秒，再 F3+T、等待并保存关闭。没有访问 Prism、生产世界或旧 MCVR。

各轮 live tick 继续推进；恢复的是相同初始存档，不是逐 tick 完全相同的动画。旧 Options 的反弹值未当作实际 shader 参数读回。焦点缓存 true 不证明实际 GLFW 焦点，生成帧计数均为 0，不能用于 FG 动态视觉结论。

### 实现与资源边界

- 静态快照只向本帧追加偏移与命中组。六张几何表以“动态前缀、不可变静态段、外部结构后缀”直接写入最终 staging，保持旧 shader 连续布局；不先生成一份静态临时副本。
- `SceneTable` 保留按字节拼接和大小检查；`SceneTableCache` 只缓存每个记录上下文最近的不可变版本。动态两端精确比较，静态段以强引用快照、范围和大小确认身份。新快照即使字节碰巧相同也失效，避免旧外观表钉住已卸载 BLAS。
- 根据实测，完整复用只用于偏移、水面排除，以及没有动态两端的纯静态表。变化频繁的混合表直接准备新版本，不复制一整份比较 key。不是根据模型名、材质名或相机可见性选择几何。
- 先保活再录制，不覆盖在途 GPU 表；失败保留原有效缓存并传播，旧资源仍按现有实际 GPU 完成条件退休。临时 staging 也进入原有帧退休器。空场景和离开世界清掉缓存引用。
- 变化表的 copy 后屏障合并记录；正式窗口每帧 7 次表上传、1 组屏障。可复用表的首次上传仍在缓存确认前记录自身屏障。没有在表准备中间插入 shader 消费。
- 相机双精度相减、当前静态变换、零 previous 几何地址、外部结构历史、TLAS 实例顺序、命中组和所有材质字段保持原规则。没有重写动态顶点、稳定原点、全局 GPU 常驻场景、AS 算法或 shader。

## 发现

### 实际变化率

新基线 PID 104208 共 1,634 帧，每表观察 1,634 次。偏移表和水面排除表各只有 2 次首次观察，其后全部相同；另外七表每次完整字节均不同。这不表示其中静态段每帧改变，更不表示每张表所有字节都必须重写。

每帧静态记录 17,705、静态几何 31,559、TLAS 实例 18,482；基线静态快照实际重建 2 次。完整元数据逻辑上传为 15,100,744 字节/帧，其中外观表为 12,537,600 字节。直接删除的静态中间复制为 13,381,016 字节/帧，不是 PCIe 或物理内存带宽读数。

世界准备观察下降约 1.426 ms、13.8%；静态表追加下降约 98.2%。整帧均值只差约 0.263 ms、0.7%，没有超过本轮波动依据；p95/p99 略高，不能宣称尾部卡顿改善。最大值较低只是一轮观测，不是已修全部尖峰。

最终静态记录、几何、TLAS 实例数逐帧与基线一致；PBR 输入顶点均值约 75,618.864→75,618.693。相机逐帧相同、雨雷均为零，最终采样起点比基线晚 93 tick。CPU/GPU 区间重叠，实体与其他未修改阶段也变化，不能把局部节省线性加到整帧。

最终窗口每帧复用两表、74,296 逻辑字节；七表仍上传 15,026,448 字节。主要成果是省去 CPU 中间复制，不能包装成静态 GPU 上传接近零。VMA 分配字节峰值 9,694,434,064→9,716,903,904，分配数峰值 72,860→72,875，分别 58／59 个观测；不是驻留显存，也没有证明显存下降。整卡统计含其他程序，保留在 load-context 中。

### 自动回归与运行

新增 `mcvr.scene-table` 执行 1,000 组随机三段布局和总计 5,043 条断言，覆盖精确拼接、同尺寸变化、插入边界、静态 owner/range 替换、独立视图、同帧不可变版本、prepare/retain/record 失败、旁路与完成条件退休。断言数不等于独立测试数。现有静态场景测试增加六表最终字节对照，保留移动相机／大坐标、动态前缀、外部后缀、资源替换、世界身份与在途保活验证。

前两轮完整执行以下命令通过，最后单变量改动正常完成原生 INSTALL、非 GPU CTest 71/71、clang-format、发行与严格检查；维护收尾再以已安装的同一 DLL 执行完整检查，防止验证后再次重链改变身份：

收尾的 `-x` 只避免重复构建已完成 INSTALL 且已实际加载核对的 native 产物，测试、JNI/资源/发行及严格检查没有跳过；后续产品修改仍必须重新构建。最终有效 GAME 314、probe 34、JNI 4、bootstrap 11 通过／2 跳过及非 GPU 71/71，实际执行／UP-TO-DATE 以每轮日志为准。shader 构建和 1,715 条解包资源检查通过，GAME 字节码和 shader 内容不变。没有重跑无关的旧 GPU 矩阵；真实 GPU 覆盖是上述四个城市流程，没有新增人工视觉或真实多视图验收。

四次流程均完成 F3+T、字体违规 0、三个维度保存、正常 native close 与 Aftermath disable，dumps=0；没有设备丢失、GPU 转储、危险注入或自动重试，不关闭历史 GPU 根因。

## 结论

保留分段静态表、受限精确复用及批量屏障：逻辑中间复制确实减少，CPU 世界准备局部下降，所有来源几何、相机、历史和资源退休合同保留。整帧均值基本持平且 p95/p99 未改善，当前不能宣称整体性能优化成功；GPU 和未修改 CPU 阶段仍有波动／潜在成本转移边界。

动态顶点生产、全局 GPU 常驻表、稳定原点、TLAS 增量架构与新的功能均未同时推进。后续动态优化须按使用者下一项授权开展；本轮停止新增实验，不扩大为长期诊断。
