# 已接管来源与 Voxy 效率实验

2026-10-29，本轮在既有脏工作区上减少公共提交、光束、柔性弹簧和 Voxy 的重复生产。功能、资源压力、整帧性能和人工体验分别判断；没有提交或推送。

## 问题

公共实例批次仍反复分配原生暂存、UTF-8 名称及确认快照；光束把滚动 UV 计入形状身份。柔性弹簧先生成曲线再提交，父空间整体运动也可能污染局部判变。Voxy 每帧选择、重复组织派生表，并为完整近景背后的内容继续细化、建模和参与追踪。

## 方法

- 公共提交复用独占、有界的 CPU 暂存和已接受快照。JNI 返回前不归还暂存；只有 Native 接受更新后才改变快照，纹理、来源、多视图与删除保护继续生效。
- 光束保留原来的相位、旋转、壳层、透明度和颜色，将形状与颜色／UV 参数分开。
- 弹簧按端点状态、相对位置／朝向决定是否运行原曲线算法；只保留每条连接当前局部形状，受力混色与贴图伸缩由既有外观参数表达。形状改变显式退休旧局部定义，Native 在途引用继续由既有所有权保持。
- Voxy 根据来源、相机、FOV、距离和近景覆盖变化选择；只延后已完成计划明确不需要的排队工作。近景覆盖沿用着色器已有的半开体素归属，不额外扩张覆盖，也不按相机可见性剔除 PT 几何。保留父节点、光源和更新的交接。
- 使用相同冻结城市、32 视距、1920×1080、512 方块 Voxy 请求半径、相同探针和设置。静止／固定相机移动分开，FRAME_ONLY／TIMED 分开。这个用例检查重叠和提交成本，不能代表任意远景距离或缩短近景后的收益。

本轮工作区临时允许 22 GiB，验证和外部目录分别保持 8 GiB。删除操作均使用回收站，候选和配套符号、源码快照及唯一故障证据保留；已验证重复的包装暂存和可再生编译缓存另有清单。

## 发现

### 实现与功能验证

本体、Extra 的构建、单元回归、发行结构与严格合规通过；Native 79 项 CPU 与 24 项 GPU 测试通过。最终 E 使用刚构建的 Native 产物完成检查，未重复编译 C++，测试没有跳过。

弹簧最终参数路径的隔离回归记录 1,377 次请求、1,376 次复用、23 次来源展开，其中 22 次是刻意重新执行原算法的诊断对照；局部位置和法线精确一致，UV 归一化容差为 `2e-6 × max(1, abs(expected))`。实际稳定形状只生产一次。没有把重算对照混入正式性能窗口，也不由这些计数推出 FPS。该用例是主世界固定连接，不代表跨空间连续形变的完整目视验收。

Voxy 最终 D 配套通过七阶段：来源存储、远处／返回、资源重载、旧代际拒收、Advanced、来源更新及退出重进；实际移动历史检查通过，无设备丢失。最终 E 另修正下述内置物品路由边界，Voxy、弹簧代码与 Native 产品源码和 D 一致；相关功能证据按实际配套身份引用，不改称 E 已重新跑过全部阶段。

配套身份和冻结源码见[最终候选清单](../../validations/conformance-takeover/result/source-efficiency-20261029/source-efficiency-e-20261029/candidate.json)，D 的直接功能证据位于同组 `spring-final` 以及 `validations/regression-voxy_integration/result/source-efficiency-final-20261029`。

### 失败与对照边界

- 早期 A 的变化记录复制把目标 position 加了两次，造成 JVM 原生内存访问崩溃。已换成带边界检查的批量复制，并添加多记录及尾部哨兵回归；A 没有投放。
- 一次弹簧运行参数错误地把期望来源写成 `simulated`，平台核对主动退出。更正为五个实际注册来源后通过，没有修改产品来放宽检查。
- 旧基线先因 Windows 着色器打开路径达到 261 字符而在进世界前失败。缩短验证目录，并在启动前检查冻结包中的最长 Native 文件路径。
- 冻结城市还暴露了旧版本的内置掉落物强制类型转换错误。正式修正保留路由／轮廓消费者，无法提供合法存储所有者时使用原 renderer。为不删除城市对象，对照基线只回补相同的 `VanillaItemReplacement.class`；其他 GAME 条目及全部 Native／资源逐条保持不变，内嵌 GAME 校验同步更新。这是修补基线，不能冒称原验收二进制。

基线修补清单见[身份与字节码核对](../../validations/performance-sources/result/baseline-item-routing-repair/repair.json)。原冻结产物未覆盖，原失败的 STOP、日志和校验归档保留。

修补后的基线在近景队列已清空后仍不断细化 LoD，观察到整卡显存约 15,628/16,376 MiB，未形成平静后的正式窗口。为避免继续逼近显存故障，按确切 PID 强制停止项目内副本；停止时即时读数已降到 15,278 MiB，不能据此证明它必然失败或无法最终稳定。保全日志／资源观察后回收客户端环境，最终日志没有设备丢失，不自动重跑同一基线压力。该组不是稳态 FPS 数据，不能计算完整提速比例。

### 其他来源的边界

Create 幽灵方块仍由来源的 `GhostRenderParams`、模型烘焙和透明度回调控制；轮廓、物理法杖及 ValueBox 有各自的小型捕获入口。现有 Catnip 不可变模板不会自动覆盖这些入口，不能把管理器本身当作所有预览的稳定历史身份。小型连续变化内容继续批量捕获，不为减少表面上的捕获数量新增一套持久管理。

粒子已有位置／尺寸／颜色分离，UV 帧仍可能区分基础定义。本轮公共提交先减负，不在没有粒子热点证据时重排对象和记录结构。Flywheel 变化队列、Sable 成员通知和 Veil 已有复用保留。以上不等于全部来源都完成效率验收。

### 城市候选的稳定窗口

最终 E 的静止窗口正常完成并通过资源重载、保存关闭。FRAME_ONLY 为 131 个有效帧间隔，均值 152.573 ms，p95 155.290 ms、p99 157.721 ms，约 6.55 真实 FPS；主队列 GPU 完成桶为 152.376 ms。TIMED 为 152.507 ms，GPU 世界 PT 138.361 ms、TLAS 构建 5.221 ms、SHARC 更新 5.758 ms。这些范围相互包含，不相加；GPU 完成桶不与每个 CPU 帧一一配对。

该窗口来源计数前后不变：4,042 个选择项中，4,004 个为已记录的非空节点；1,702 个确认完全被近景覆盖，2,302 个实际参与 PT，38 个为空。选择计划由变化驱动，静止后跳过重复计划。驻留数据约 1.043 GB，覆盖排除不等于这些缓存全部立即释放。

TIMED 中公共实例每帧约选择 4,109 项、更新 193 项，Native 保留模型 338 个；这些只说明路径实际生效。来源 CPU 分区中实体打包约 2.05 ms，原生远景元数据约 3.71 ms；整帧主要受 GPU 世界 PT 限制。本例没有活跃的 Create 预览／法杖或弹簧，不能据此证明那些独立入口的整帧收益。

这不是完整的 A/B 成功结论：基线在压力下被主动停止，候选稳定窗口也仍非常慢。保守的整节点覆盖判定会保留跨近景或高度边界的节点，部分区域继续使用原逐命中覆盖；不能为减少计数直接删掉它们。

固定移动窗口也正常完成、重载并保存退出。FRAME_ONLY 为 126 个有效间隔，均值 158.483 ms，p95 164.020 ms、p99 165.170 ms，约 6.31 真实 FPS；TIMED 为 156.875 ms。路线按同一 5 Hz、振幅 4 方块移动相机，包含区段边界更新，不是正常手工移动体验。静止／移动各只有一次完整运行，没有由这些数据推导运行间统计置信度。

候选整次运行整卡显存峰值分别为 15,710／15,792 MiB，进程私有提交峰值约 21.97／22.43 GiB。候选也处于明显资源压力下，不能声明显存峰值下降；整卡数字包含其他程序，不等于 Minecraft 独占量。GPU 世界 PT 区间也可能包含驻留／搬运影响，现有时间范围不能将它全部归因于着色器计算。原始数据及汇总见[结果](../../validations/conformance-takeover/result/source-efficiency-20261029/results.json)。

构建的测试依赖曾意外触发完整 Native 重编译，占用检查测得工作区短时约 22.16 GiB，超过本轮 22 GiB。随后回收已保全的失败客户端、哈希相同的复制暂存及可再生编译缓存，恢复上限；没有删除唯一验收证据。最终打包检查复用该次已构建的 Native，继续执行 CPU／GPU 测试，避免再重复生成全部编译缓存。

## 结论

已证实的内容是减少特定来源重复生产、功能合同通过，以及基线在这一完整城市压力下的资源问题；基线没有有效稳态窗口，不声明整帧提速比例。当前候选的主要开销位于 GPU 世界 PT，继续压缩小型 CPU 分配不能独立解决本例低帧率。视觉体验、真实操作下的弹簧形变及预览仍由用户验收。

最终 E 已替换 Prism 中的本体与 Extra，读回哈希一致；Voxy 和其他模组、配置、存档保持不变，没有启动游戏或投放探针。回执见[投放记录](../../validations/conformance-takeover/result/source-efficiency-20261029/source-efficiency-e-20261029/prism-deployment.json)。
