# Voxy 含水方块染色索引异常

2026-10-29，恢复 Voxy 接入后，依据当前来源源码、保留的 Prism 崩溃和配套发行包调查模型染色表异常。本轮只做功能验证，不做性能实验；来源仓库只读，原有设备丢失记录保留。

## 问题

上一轮 Prism 在 `VoxyModels.publish` 经 `LodScene.models` 发布模型表时抛出 `Publish Voxy model table: LOD tint index`。这是原生输入检查拒绝无效索引，不是本次 GPU 设备丢失。旧记录保存在 `validations/regression-voxy_integration/result/unlimited-geometry-20261028/crash-212244/`。

## 方法

对照来源 `ModelFactory` 写入的模型标志和颜色字段，与 Extra 的模型翻译和 Native 的边界检查。补充转换回归，并在既有七阶段用例加入含水台阶、含水楼梯、常量染色树叶。探针只在阶段检查点读取真实来源表，确认各类已实际摄入和翻译后的颜色索引有效。

本体沿用已验证的 Veil 配套包，冻结快照中 1,599 个本体产品源码文件与当前内容一致；本轮不修改其 Java、Native 或着色器。Extra 重新构建。候选、冻结源码和运行回执位于 `validations/regression-voxy_integration/result/tint-20261029/`。

## 发现

来源模型标志位 0 表示自身有染色来源，位 1 表示群系依赖。含水但本体不染色的模型会继承流体的群系依赖，所以允许出现“标志为 2、颜色为 -1”。此时 -1 是白色常量，不是颜色表索引。常量染色也可能是带符号的负整数，不能按正负判断字段用途。

原翻译只检查位 1，错误地启用 Native 的群系索引标志，于是白色常量被解释为无符号大索引。修正为同时要求“自身染色”和“群系依赖”，模型统计复用同一判断。保留来源颜色、逐面染色范围、透明度、材质和 Native 边界保护，不截断索引或取消真实水／草／树叶的群系染色。

第一次自动预检在 Java 模块解析时停止：新增探针类与产品使用同一 Java 包，形成分裂包，未进入世界，无设备丢失。探针移至独立 audit 包，通过反射仅在检查点读取产品表；运行器增加启动前的产品／探针包重叠检查。该失败的日志和回执保留，不算成功的功能运行。

第二次在世界载入前发现前轮新增的 Veil 检测入口无条件加载 Veil 专用类，Voxy 单独安装时缺少 `ShaderBlock`。调用入口改为同时要求安装 Veil 和显式启用检测；不修改产品适配。重新执行 Extra 检查通过，再启动当前配套的功能运行。两次前置失败均保全，无设备丢失，不计为七阶段通过。

## 结论

Extra 的 `spotlessApply check verifyRelease verifyCompliance --strict` 通过，122 项测试无失败，严格合规无失败或警告。本体产品源码未变，沿用前轮验证的发行 JAR；没有重复执行本体完整 `check` 或 Native 重编译。受影响的 `render_diagnostics:check`、本体格式与严格合规检查通过。

实际会话 `tint-20261029/functional-20261029-004149` 七阶段通过，加载 DLL 的哈希与冻结本体一致。每个检查点实际存在 1 个无自身染色的含水模型、2 个常量染色模型、8～11 个自身群系染色模型；颜色与索引检查均通过。Advanced 来源修改使模型数 22→23、原生记录构建 375→395。重载拒收旧 epoch，退出／重进使用新 session，正常保存退出，无设备丢失。运行器完成证据归档和读回验证后回收客户端环境。

与 Veil C 发行 JAR 对比，Extra 只有 `VoxyGeometry.class`、`VoxyModels.class` 两个产品条目变化，其余产品类与资源不变。当前染色表修复已有源码、自动回归与限定运行证据；不等于其他 Voxy 来源问题均解决。颜色、连续移动、水体、接缝和长期稳定性仍待用户验收，不依据本轮数据宣称性能改善。本轮未投放 Prism，未提交或推送。
