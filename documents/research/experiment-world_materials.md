# 世界材质、光照和启动交接实验

2026-10-27，承接 134／135 号授权，在 130～132 配套候选和未提交源码上开发。本文区分输入修复、实际 GPU／客户端证据与尚未完成的人工体验，不借用历史验收。基线身份在 `validations/conformance-takeover/result/persistent-sources-130/candidate.json`。

## 问题

来源颜色的八位转换、云的专用假照明、连续折射的介质状态、世界程序表面和第一人称照明范围需要共同处理。日月贴图与光源能量需要统一，曝光硬边测光和启动主线程停顿需要分别定位。End Sea 另需保留真实空间薄层和结构渐变，不能仅用传送门着色器替代。

## 方法

来源规则在 Vanilla／Extra 解释，公共平台只补有限的材质和空间参数。保留 130 的区段、持久来源、资源代际与在途退休。使用定向 GPU 合同、内置算法包实际配置编译和少量项目内场景；发生设备丢失立即保全停止，不自动重试。项目外实例未操作，不使用 Computer-Use，不提交、推送。

全部运行记录放在 `validations/conformance-takeover/result/world-materials-134/`，构建和定向检查日志在 `components/render_diagnostics/build/source-scene/`。运行环境按 1920×1080、静音和禁止抢焦点准备，保存实际产品哈希与配置；启动计时不当作稳定性能对照。

## 发现

### 颜色、表面和介质

原版发光墨粒子的浮点通道实际经整数截取和八位打包。统一入口先保留来源的低八位，再归一化；不通过关闭发光或截断全局 HDR 修正。普通基础表面与独立全亮效果的边界保持 134 号决定。

云几何不再按主相机上／下位置漏掉其他光路需要的面；复用普通表面光照，移除专用背光、雨天补亮和命中即停的路径。世界边界保留原透明度、动画与明确发光。

介质状态在实际透射事件才入栈／出栈，反射分支保留入射介质；光程按当前介质吸收。折射遵循两侧 IOR、Fresnel、全反射和 GGX 微表面粗糙度。缺失的辅助贴图与作者真实提供的全黑贴图区分，避免将占位图解释为粗糙玻璃。该状态栈对应有序封闭边界，不宣称解决任意相交体积的优先级或所有共面介质边界。

最后复核发现三份禁用视差的命中代码仍是独立副本，漏掉共同的介质／光照更新。它们现由同一份普通命中实现加 `RADIANCE_NO_HEIGHT_SURFACE` 能力定义表达；Advanced 首次表面缓存继续记录 `NO_HEIGHT_SURFACE_BIT`，不恢复被明确禁止的视差。旧副本送入回收站，源码合同检查改为覆盖当前执行文件，并新增配置变体测试。两套算法包共 11 处对应组均使用此合同，275 项源码／实际配置编译请求通过；最终发行包还需单独核对。

优先级成像另补齐透明薄层续接：连续加法层不消耗散射反弹次数，查询仍保持相机所有权，首次优先级选择只执行一次。真实 TLAS 用例在十六次反弹预算下跨过四十八层并到达合法端点，避免以增加反弹数掩盖截断；该回归随最终 GPU 门槛执行。

公式依据 [PBRT Dielectric BSDF](https://pbr-book.org/4ed/Reflection_Models/Dielectric_BSDF)，水／玻璃参考值分别约 1.333／1.5；不将粗糙度统一设零。现有含颜色的吸收近似继续保留，未实现完整光谱材料。

### End Sea 的来源与接入

Simulated 1.3.2 提交 48 张半格间距水平面，使用 `textures/entity/end_portal.png` 和循环颜色，源混合为 SRC_ALPHA／ONE。深度遮罩保留约十格的立方衰减，强度遮罩保留五轮来源扩散；不是二值阴影开关。

材质收集移到来源完成本帧遮罩之后，避免结构运动时采集上一帧的遮罩位置。共享求值用于命中和面积光采样，加法续接不消耗散射次数，不创建折射介质。发光预算以来源 48 层每层一个统一全亮单位建立，固定为 48；保留除以层数的表达，程序采样数不会隐式决定总能量。该基准取代未标定的总量 4，仍需检查实际图案、亮度和周边照明。

进一步核对发现，原有提交顺序把整段离屏／GUI 命令放在世界 PT 之后，即使 Java 已先生成遮罩，GPU 仍会先读取旧内容。世界合成边界现在封存离屏命令前缀，按上传、离屏输入、世界 PT、GUI 后缀、最终合成的顺序提交。前缀随帧栅栏退休，正常帧不新增 CPU 等待；显式读回完成后不会重复提交该前缀。世界纹理表也按实际格式为深度附件绑定只读深度布局，与离屏结束时的转换一致。

结构染色的真实范围为 sublevel 区块表面。来源将海面以下的顶点颜色，在三十格内线性混向 `(0.172, 0.156, 0.218)`，透明度不变。Extra 声明世界空间标量平面，Native 按本帧姿态变换到区段局部空间，在纹理相乘前求值；原版实体和独立实例不因所属结构自动染色，移动／倾斜不重编译区段。

### 末地崩溃

基线组合的 `baseline-sources-end-20261026-221245` 是 CPU 访问非法地址，JVM 故障栈进入 `org.joml.MemUtil$MemUtilUnsafe.put(Matrix4f,long)`，不是 `VK_ERROR_DEVICE_LOST`。Veil 序列化器收到堆缓冲，而其 JOML Unsafe 写法需要直接内存；Extra 改用临时直接缓冲，完成后复制为自有快照并释放临时分配，不吞异常。

原故障文件曾位于客户端根目录，已从回收站按 SHA-256 恢复并保存恢复清单；后续运行器在回收复制环境前逐条读回归档校验。`extra-direct-memory-fix-end-20261026-224101` 使用 130 本体与仅修此缺陷的 API 5 Extra，已进入末地、停留、返回并正常退出；这项证据不冒充最终 API 6 配对包的验证。

### 天空、曝光与启动

[Epic 天空建议](https://dev.epicgames.com/documentation/en-us/unreal-engine/sky-atmosphere-component-in-unreal-engine)的日／月照度比例仅作关系参考，未把 lux 数字直接塞进 radiance。保留渲染归一化强度，以实际日月贴图的投影能量归一化可见轮廓、直接采样与 MIS；月相只衰减一次。倾角变换共用，天气进入消光和散射，不加环境亮度下限。原有大气近似和体积云算法未重写。

[Epic 曝光文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/auto-exposure-in-unreal-engine)提供连续测光与亮暗适应参考。中心硬矩形改为连续全画面权重，在 EV 空间适应。新默认值扩展夜间测量／曝光范围，已有个人配置不被重写。固定曝光比较 PBR Neutral 和 ACES，默认仍为 [Khronos PBR Neutral](https://github.com/KhronosGroup/ToneMapping/blob/main/PBR_Neutral/README.md)。

首轮启动观察 `baseline-startup-20261026-220142` 的总时间约 29.073 秒、runTick 最大间隔约 1784 ms，但当时 agent 未实际启用；它不能证明完整 Early Window 连续呈现情况。新采集明确观察已完成的 early present 与游戏帧，和主菜单可交互时间分开记录，不将其声称为显示器 scanout。

JFR 指向 Native warmup、初始化和早期 CPU 负载查询。当前修复包括不变包提取复用、按包含关系和宏值依赖筛选编译定义，以及早期 UI 改用进程 CPU 时间差。必要初始化仍在原依赖位置，没有将等待移到进入世界。是否减少总等待和最长冻结，以新启动窗口为准。

新采集首次揭示旧 runTick 口径漏掉的大停顿：130 基线到可用主菜单 42.612 秒，已完成加载／游戏帧的最大间隔 13.912 秒；首个 134 候选为 335.105 秒及 308.204 秒。循环不展开候选仍需 319.793 秒及 297.625 秒，提示已撤回。两次控制器均在 300 秒先超时，客户端稍后正常停下；退出码未取得，记为未知。无 GPU／CPU 转储依赖的两套中间 PDB 已回收，身份和回收原因留在候选记录，不冒充仍保留实物。

这些旧日志的管线开始位置在获取全局缓存锁之前，结束时间包含排队，不能将最后结束的 `priority_geometry` 单独当作全部停顿来源。当前在创建反馈中分开记录缓存锁等待、驱动调用墙钟、驱动反馈及缓存命中；查询和 SHARC 更新的两次 `world` 构建都保留。

先将当前／外层介质显式传给命中阶段后，有效候选降到 190.046 秒，最长间隔 170.172 秒，驱动反馈累计约 162.814 秒，仍不满足目标。期间一套候选因误删 SHARC 原有扩展声明，在源码编译阶段失败；已恢复并保存其 Java 崩溃证据，该结果不参与耗时比较，也不是设备丢失。随后将完整历史移出命中载荷，由 raygen 私有状态维护；各条反射、透射和覆盖分支显式拥有独立历史，未降低层数、反弹或精度。

### 自动检查边界

最新完整门槛 `task136-local-history-final-gates.log` 通过 `spotlessApply check verifyRelease`、探针编译、严格合规与 24 项 GPU CTest；79 项无 GPU CTest 亦通过。新增用例检查完整容量的嵌套历史、独立分支、等待回调的线程归属与异常后工作线程回收。两处源码合同匹配更新为携带私有历史的实际调用，不修改查询语义。

## 结论
