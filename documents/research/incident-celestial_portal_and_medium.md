# 日月裁切、传送门与介质退出修复

2026-10-27，使用者在天空／随机远景候选中报告日月下半球裁切、玻璃后 End Sea 明显变黑，并要求恢复末地传送门来源语义及原版无世界界面的 60 FPS 限制。

## 问题

天空背景已延伸到下半球，日月命中环境时仍使用虚拟球形地面遮挡，方向光查询另有地平线提前返回。玻璃的来源背面剔除同时作用于连续折射，可能跳过退出边界，使后续薄层和背景继续累积玻璃吸收。

传送门使用了 End Sea 的方向／表面投影与能量归一化，与来源的屏幕投影和颜色累加不等价。原版帧率限制被重定向后，Native 只读取用户游戏内上限，没有保留无世界界面的限制。

## 方法

以 Minecraft 1.21.1 的 `Minecraft.getFramerateLimit`、`TheEndPortalRenderer` 和实际资源包中的 `rendertype_end_portal` 着色器为来源。逐项核对两套内建算法、BLAS／TLAS 面规则、介质提交、分支历史及薄层查询。

物理透射资格随几何建立进入 Native 面规则，关闭可能丢掉退出面的硬件捷径；实际默认命中路径再按图元 alpha 模式过滤，避免混合批次中的普通不透明面被一并放开。重合的正反薄片仍只选择一侧成员；不改变自身、手部、优先级、船内水面或普通单向几何的归属。

GPU 回归建立外向绕序的真实玻璃薄盒，保留摄像机查询的背面剔除标志，验证进入、退出、介质深度归零，以及后续远处叠层不再增加吸收；同时覆盖传光查询。已有嵌套、反射兄弟分支、折射、全反射和介质容量检查继续执行。客户端只做功能验证，不进行性能实验；工作区容量本轮经明确授权暂停，验证与外部目录仍为 8 GiB。

## 发现

日月纹理和方向光可见性不再由虚拟地面裁切，下半球透射使用同等仰角的空气柱。真实几何与天气消光仍然有效。

末地传送门与折跃门恢复来源投影、16／15 层颜色累加及不透明终点；不再归一化或额外乘四。保留 PT 入射路径权重与真实介质吸收，不把玻璃遮挡后的门直接写成未衰减颜色。End Sea 的空间薄层与归一化继续独立保留。

反射和其他传光查询原本就不执行普通来源背面过滤；介质仍须在实际透射事件后才改变，反射分支不提前弹出介质。两套算法共用边界规则和介质函数，未发现需要给 End Sea 单独补亮的依据。

无世界且存在 `screen` 或 `overlay` 时，由 Native 限制为 60 FPS；进入世界后的暂停与重载保持用户游戏内上限。来源设置值不被覆盖，也不叠加第二套 Java 限帧器。

早期 A 候选在进入世界时发生 CPU 访问空指针，未投放。匹配 PDB 将 `core.dll+0xec1b36` 定位到 `Entities::queueBuild` 的新增 alpha 数组读取；真实持久模型合法省略该数组。修正保留可选输入合同，CPU 从现有顶点处理、GPU 延迟路径从现有拓扑扫描取得实际 alpha 模式，不添加逐帧完整扫描。失败包、JVM 日志与 PDB age 14 一并保留；这不是设备丢失。

## 结论

最终配套身份为 `validations/conformance-takeover/result/visual-fixes-20261027-b/candidate.json`。完整构建、79 项非 GPU 检查通过；材质与介质相关的 24 项 GPU 检查通过。两套发行算法包的全部条目与通过 268 项配置着色器预检的包一致。首次构建因默认 Python 3.15 缺少既有诊断依赖失败，指定已安装依赖的 Python 3.14 后通过，没有放宽检查。

最终冻结包完成四组项目内会话：Vanilla PT 与 Advanced 的连续介质、玻璃后传送门、第一人称、日月和天气场景；末地真实 End Sea 的三个姿态及缓存重建；无世界主菜单八秒限帧。最终主菜单实测约 59.84 FPS。均正常退出，没有设备丢失；不作为性能收益对照。下半球太阳截图可见，月亮在日间天空的可辨外观和地平线连续运动仍需人工观察。

End Sea 真实遮罩会话与单独 GPU 玻璃薄盒验证分开记录，不把前者写成已经逐像素验证了任意玻璃组合。折射／反射介质历史、单面与成对薄片合同已通过自动回归；传送门动态外观及用户原场景的玻璃后 End Sea 仍交由使用者验收。不提交、不推送。
