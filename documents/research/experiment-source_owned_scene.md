# 来源维护场景架构的配套验证与城市对照

2026-10-25，本轮按使用者批准的来源场景架构实施并完成限定自动验证。共同区段服务和来源成员维护已经进入正式路径；巨大结构就绪明显加快，移动有小幅收益，静止整帧收益未稳定超过运行波动。人工外观仍待验收。

## 问题

模型与部分实例已驻留，但 Java 仍会先准备绑定和记录，再在提交末端判变。主世界和外部区段分别调度；Sable 每帧遍历区段、更新成员变换、收集方块实体；Flywheel 父 embedding 变化会使子实例全部标脏。目标是让来源维护成员与实际变化，平台统一区段和空间执行，不改变动画、材质、查询用途、几何覆盖、历史或资源退休。

## 方法

### 实现与边界

- `SectionScene` 管成员；主世界和外部区段共用 `SectionBuildQueue`、准入、快照、后台编译、Native 预算、完成发布和退休。队列使用完整 64 位身份，准备代际独立于 Minecraft dirty 标记。
- `RenderSpace` 保存双精度父空间、法线基及照明继承。区段、局部模型和 Flywheel 引用空间身份；来源已插值的姿态直接消费，不再插值一次。
- Sable 使用容器观察者、区段／plot／方块实体变化入口维护成员；普通帧只求来源姿态并检查平台代际。局部锚点避免将 plot 大坐标直接压入浮点变换。
- `LocalModelBatch` 在绑定和参数打包前比较已接受的实际状态；保留来源求值、纹理使用临界区、顺序和拒绝驻留时的完整回退。已接管粒子登记实际来源寿命。
- Flywheel 父空间姿态／照明不再把全部子实例标脏；原有实例自身更新、解析动画、迁移、删除仍执行。
- 世界退出时 Java 来源、空间、Native 实例场景在既有 GPU 完成与退休边界闭合。没有恢复旧的即时发布，也没有增加普通帧全 GPU idle。

这不是全量 GPU 场景数据库。每视图实例选择、相机派生、TLAS、部分表组织、必要动画和瞬时几何仍有逐帧工作。公共版本来自 `render_abi.def`：本轮 API 为 3，刚性输入为 4，记录由 152 增至 160 字节，必须配对更新本体与 Extra。

### 固定输入与口径

冻结夹具沿用 129 的 `components/render_diagnostics/build/platform-129/fixture.json` 与 `prism-fixture.zip`，后者 SHA-256 为 `6044d19475f830dbfc4fd5da9b68806d574e1943a71ff4bb52695449f3c102ab`。不再次读取或修改 Prism 世界。正式比较为完整旧包、新包、新包、完整旧包，各自重新解出同一存档，32 视距、1920×1080、静音，其他模组、模拟距离、材质、DLSS／RR、SHARC 与反弹配置保持冻结内容；FG 未开启。

城市使用 NeoForge 21.1.264 和同一 Java 21 运行库；纯原版／组合正确性夹具使用参考 Target 21.1.259。城市保存点、朝向和输入相同，来源模拟使稳定起点约有 0.002 方块以内漂移，移动终点相差不足 0.15 方块。没有将移动路线写成逐帧坐标完全相同。

每个正式进程含 20 秒加载、世界进入 65 秒后的 12 秒站立和 12 秒持续移动窗。均使用相同计时探针和 JFR；CPU 自身时间、Native、GPU 执行域重叠，不能相加。真实帧间隔不使用生成帧 FPS。线程 CPU 以窗口均值判断，不把粗粒度 CPU 采样当作逐帧等待分布。

本轮临时验证预算为 5 GiB。已完成的明细流归档为 ZIP，逐条 SHA-256 读回通过后，原文件送回收站；索引保留原相对路径。输入、源码、当前候选及唯一证据未删除。没有提交、推送、使用 Computer-Use、操作旧 MCVR 或投放／启动 Prism。

## 发现

### 工程与运行正确性

本体完整 `spotlessApply check verifyRelease verifyCompliance --strict` 与 Extra 配套门槛通过；本体严格合规失败／警告均为零。Native 非 GPU CTest 78 项通过，GPU 合同 23 项已通过；后续代际及退出修正在实际客户端再验证，不扩大为所有 GPU 条件证明。Extra 的 98 项测试通过。JNI 头文件、发行结构和探针排除核验通过。

功能回归使用 `candidate-lifecycle-06-20261025-224531`：移除并重新发布巨大结构成员、放置／移除方块客户端状态、F3+T、真正离开旧世界后进入新世界、双精度来源姿态一致性及正常保存退出均通过。该结构 665 个区段中 422 个有内容区段恢复就绪。Native 追踪无丢弃，取得 20,614 条 GPU 完成、发布、TLAS 引用与完成帧关联；这是 Native 版本消费证据，不是首个可见像素或端到端放挖延迟测量。没有跨 Java／Native 时钟直接相减。

纯原版 `core-20261025-230103` 通过实际 renderer 输入对照、公开状态变化、回退、重载和世界生命周期检查。组合 `sources-20261025-233022` 通过，实际记录 4 个 Sable 子世界、40 个 Flywheel 实例以及既有 LOD 执行；不代表八种 Flywheel 布局、所有第三方 GUI 和全部模组功能都已目视通过。

组合用例全进程、全部视图中，局部参数打包 333,554 条，打包前复用 2,073,530 条，后者占这些条目约 86.1%。这不是全部世界几何的覆盖率，也不是计时窗内上传量或 FPS 收益。原计时探针未接收新增 `RIGID` 计数，四次正式对照不能补填这些数；随后只在独立功能运行接通聚合，原计时探针 JAR 另留存，未重写历史样本。

### 运行中修正的缺口

1. 旧探针对已移除的反射调用做强制注入，导致首个运行加载失败；删除过时探针目标，不放宽注入要求。
2. 新空间 JNI 类有 DLL 导出，却漏登 SERVICE／GAME 绑定清单；修正登记，并用扫描全部 native 声明类的自动检查防止再次遗漏。
3. 平台重置后，来源再次提交相同成员会先承认新代际，漏掉重新绑定；修正共同成员服务，另加最小状态接缝测试。失败时实际重载已完成但就绪数一直为零；修正后从零逐步恢复到 422。
4. 嵌套 tick 使首次重进探针提前判为成功；加入重入保护并要求新 `ClientLevel` 身份，独立后续用例才记作真正重进通过。

失败／诊断用例 01～04 原证据保留。05 只证明恢复重载及其以前的项目，其重进标记不作为证据；06 取代该项证明。未遇到设备丢失，不把 Aftermath 没有转储解释为长期稳定性证明。

### 巨大结构与实际成本

从世界 ready 的 Java 同时钟起点，到首次采样到该结构 422 个有内容区段全部 Native-ready：旧 A／D 为 23.52／23.37 秒，新 B／C 为 7.15／7.14 秒，约缩短 69.5%。采样分辨率约一秒；它不是整个城市加载完成时间，不区分每一段读盘／网络／编译／GPU 的独立耗时，也不等同于首个显示帧。旧、新最终均为 665 个区段、422 就绪、dirty 零。

站立 Java 自身时间：Sable 更新旧 0.244～0.254→新 0.027～0.028 ms/帧；Sable 方块实体准备旧 0.521～0.558→新 0.032～0.038 ms/帧。局部参数打包旧 0.478～0.512→新 0.427～0.499 ms/帧，后一项仍有重叠波动，不能将它算作明确的大幅收益。

站立每帧 Native 对照均记录 TLAS 实例 18,469、刚性实例计数 744、引用顶点 62,192、驻留模型 249。计数有各自视图／调用口径，不换算为全项目覆盖率。Native 原先已经按变化提交；本轮站立变化记录旧 152、新 160 字节，而选择身份字节相同。主要新增收益来自更早少准备与共同调度，不能声称 Native 上传进一步大幅下降。

GPU 世界执行没有稳定下降；完整进程 VMA 峰值旧约 8.80～8.91 GiB，新约 8.90～8.91 GiB，范围重叠。这里不是 RTSS 整卡显存，也没有完整进程内存峰值测量。共享空间表和较大参数记录有额外容量成本，未测出资源占用的明确净收益。两个 shader 包共 249 个条目仅共同 ABI 定义变化，其他内容逐条 SHA-256 相同。

## 结论

本轮共同区段、来源成员维护、空间继承、打包前状态复用和对应生命周期已形成配套候选，值得保留。最明确的实测收益是巨大 Sable 结构更早就绪；移动有有限整帧收益，站立与加载长帧仍有明显限制。没有达到真实 60 FPS，也不据局部计数承诺后续上限。

下一次人工验收重点是巨大结构的完整外观、移动与旋转、结构内实体／方块实体、Create 动画及父结构运动、普通模型和粒子、边界放挖、F3+T 与退出重进。自动输入对照、姿态计算、实际 GPU 执行和人工视觉分别成立；本轮不自动部署 Prism，也不恢复 GUI、End Sea、4K 或其他专项。
