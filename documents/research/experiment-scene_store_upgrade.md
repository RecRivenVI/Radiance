# 场景库升级与渲染成本分解

2026-11-10。以 Radiance `574a690`、Extra `8728777` 为基线。

## 问题

确定 1440p、32 视距、RR Balanced、关闭 FG 时的首命中成本下限，再判断场景库、光追通道与 Java 生产路径的可回收成本。

## 方法

### M0 测量套件

- 限制方：城市移动参考约为 CPU 29 ms、GPU 主队列 24.1 ms、世界 PT 18.2 ms。重放用于隔离 GPU，实机用于 Java 归因与线程交接。Remix 以本轮相邻基线重新确定限制方。
- 上界：世界 PT 基线减去首命中下限，是省去后续光路和引导能回收的最大区间。若 F0 超过 8 ms，10.5 ms 世界 PT 预算只剩不到 2.5 ms 给其他光路，触发停止。首命中强制不透明的差值仅作 OMM 的宽松上界。城市帧线程最多隐藏其无阻塞重叠窗口。
- 判别实验：先量正常、终止在首命中、仅主光线强制不透明和 RR Performance，各候选以前后基线包围。保留首表面直接光和常规阴影；隔离真实遮罩、材质与路径截断造成的画面变化。若首命中超过 8 ms，报告这三项后停止。否则继续两个场景各自的固定与转头矩阵，并用城市实机量 Java 子项和帧线程关／开／关。引导或阴影的静态成本与执行成本难以区分时，补运行时恒假对照。
- 门槛：F0 ≤5 ms 时优先考虑负载与预算，5～8 ms 时评估通道拆分，超过 8 ms 停止。强制不透明的有效收益 ≥1.0 ms 才开 OMM，负载斜率折算每 100 字节 ≥0.8 ms 才开 G3。RR Balanced 对照量使用 2.19～2.45 ms，染红窗口作废；Performance 自身改变重建输入尺寸，单列其 RR 耗时，环境波动由相邻 Balanced 控制判断。
- 风险：终止路径不能误禁直接光；强制不透明会改变可见表面，差值包括随之改变的后续工作；重放调档须以实际内部尺寸核对，不能只读设置。测量不运行 SER，使用既有内存保护和经授权的旧事件登记。先安排两次固定视角重放，过停止门槛后才安排余下重放和三次静音项目客户端。

### S1 场景库刚体范围的判别计划

- 限制方：M0 城市关闭帧线程的两侧基线，渲染线程实际占用 26.72～28.54 ms，GPU 主队列 24.08～25.74 ms。刚体准备与元数据处理的互斥范围实测为 3.83～4.86 ms。即使完全省掉这两段，当前 GPU 主队列仍会限制整帧。
- 上界：理想状态最多省掉上述 CPU 工作。每帧约 13,100 个刚体选择中，仅约 445 条提交变更，但相机移动仍会改写相机相对历史。当前全场景的约 30,438 条历史矩阵若按原有整段方式上传，仅这一张表就约 1.95 MB，高于 1.5 MB 门槛。逐表确认哪些字节不可省，再区分真正的记录更新与相机派生更新。上界不把现有约 0.34～0.42 ms 的 GPU TLAS 构建算成可省项。
- 判别实验：先在独立诊断窗口核对表上传量、改动量和来源身份，再以旧／新／旧城市移动验证时间和上传。预言是刚体的地址、外观和命中组准备应跟随实际变化，选择扫描和相机相关矩阵在本卡仍允许随选择规模变化。对拍比较同身份的 TLAS 字段、命中组、地址、完整外观和历史，允许分配后的记录号不同。
- 门槛：互斥范围合计 ≤1.5 ms，元数据上传 ≤1.5 MB／帧，整帧均值低于两侧旧路径且超过两侧差值。静止、移动转头、放挖、箱子、卸载重载、五次资源重载、维度往返、辅助视图、Sable 各连续 600 帧无差。完成旧快照重放、20 个介质用例、五项 GPU 契约、构建及发行包检查。

### S2 介质目录增量的判别计划

- 限制方：城市移动时发布接触数据平均占 1.41～1.45 ms。以 A1 为例，每帧遍历的注册槽约 4,670，重制证明约 20。已有网格和接触对复用，整段 1.45 ms 只是可省上界。
- 上界：保持几何关系不变时，只应处理发布、移除、改变姿态的来源及已完成的后台证明。目录行的稳定地址来自 S1。若依旧使用动态几何前缀，来源没变也可能需要重定位后续目录，不能靠跳过写入掩盖。
- 判别实验：用稀疏目录与整段重建逐行对比局部增删、移动、离开和全局未知切换。若稳定布局成立，增删不改同一已发布来源的基址，修改一个来源只应标记该范围和受影响的对端。验证静止与移动的实机耗时及既有水、玻璃和空气缝用例。
- 门槛：静止 ≤0.1 ms、移动 ≤0.4 ms，20 个介质用例通过，水下出水、全反射、异色玻璃接触图差在噪声底内，保留旧全量重建对拍。

### S1 续测的判别计划

- 限制方：旧布局城市移动的渲染线程实耗 27.96～29.67 ms，GPU 主队列 23.97～26.19 ms。刚体准备和元数据处理占约 3.96 ms，省完这段之后仍可能转为 GPU 受限。
- 上界：先消除刚体不变的几何和外观行生产，再减少历史传输。整张历史矩阵约 1.95 MB。若 30,438 条记录都可以由原样传输的平移和一个标签表示，传输约 0.49 MB。非标准矩阵每条额外需要 64 字节。实际分布必须实测。
- 判别实验：在不改变矩阵计算位置和 GPU 表格式的前提下，先隔离无损历史传输。随后比较刚体来源版本、实际重建的记录、已上传的范围和字节，检查稳定帧能否跳过外观生产。两侧基线夹住同一候选，单独采逐行计数。
- 门槛：沿用 S1 的 1.5 ms、1.5 MB／帧、整帧收益、逐场景对拍及回归。特别核对第一人称和辅助视图的完整矩阵、变换历史失效及回收槽位的跨帧可见性。

### 11 月 11 日 S1 收尾计划

- 限制方：R3 的相邻实机基线帧间隔 28.62～29.53 ms，GPU 主队列 25.04～25.27 ms。R3 已将刚体准备和元数据处理降至 1.67 ms，两侧共同限制整帧。
- 上界：刚体表与上传合计基线约 3.8 ms。分离阴影和几何区间可省去每刚体一个空外观行，实际显存与上传量另测。R4 的静态历史复用只省主机打包和传输。
- 判别实验：恢复 R4 并先核对移动路线。依补充分离两个记录区间、让刚体采样键随来源身份保持稳定。用逐视图成功比较次数核对九个场景，再做旧快照重放、20 个介质用例和五项 GPU 契约。分别检查视图历史、资源重载和槽位清零与隔离。
- 门槛：合计 CPU ≤2.0 ms、上传 ≤1.5 MB／帧、整帧均值不高于较慢的基线，静止时地址和外观重写行数接近零。九项各 600 帧及全部回归通过后默认启用。若预检不通过，按补充安排继续离线工作。

### GS 阴影光线判别计划

- 限制方：Remix 世界 PT 基线约 16～17 ms，直接把阴影视为可见约 8.7～9.4 ms，城市玻璃约 37～40 ms 降至 27～28 ms。CPU 限制另用实机判断。
- 上界：跳过全部阴影测试的约 7～9 ms（Remix）只是宽松上界。它还改变了光照和后续路径。只给照明用光线强制不透明，同时保留介质查询，可进一步约束任意命中成本。
- 判别实验：两份旧快照各跑固定与转头。先分别比较强制不透明、只追首事件阴影和简化任意命中，使用相邻基线、RR 及同帧截图。按太阳／月亮、分层光、LoD 光分别统计发送和任意命中调用，介质边界另统计 ray query 与候选。计数窗口单独运行，排除原子累加的开销。
- 门槛：Remix 世界 PT 降至少 3 ms，图差落在噪声底内。强制不透明降至少 2 ms 才评估阴影微映射。若简化任意命中占主要收益，检查哪些命中组能保持现有行为并走轻路径。比对树影、彩色玻璃阴影、水下焦散。首事件阴影方案保留给用户选择。

### S2 自主推进开工

城市移动由 CPU 与 GPU 共同限制。现有接触阶段约 1.42～1.44 ms，所以单帧 CPU 节省的理论上界约 1.44 ms。第一候选只替换发布的准备、拷贝和上传，沿用接触求解与现有保留器。稳定区间复用，新旧范围按实际变化合并，保留旧全量发布和逐行对拍入口。

最便宜的判别是用同包切换全量和增量，在城市静止与移动比较完整阶段、实际重写行、提交到 GPU 的字节及设备内部复制。若实机的大头仍在来源登记或待处理配对扫描，发布减负不能替代这些成本。目标静止 ≤ 0.1 ms、移动 ≤ 0.4 ms。逐行对拍、两算法介质、GPU 契约和旧快照是不可修订的门槛。优先检查区间重定位重叠、未知状态恢复及旧证明退休三处。

静态区段快照自身就是可靠的生命周期输入。同一快照与基址保持不变时，不重复登记各区段；快照替换、消失或基址移动仍处理实际变更。用同一个发布器分别走旧路径和增量路径，对拍目录字节、空洞、重定位、缩容再扩容、全局未知切换和静态来源退役。GPU 仍读取不可变目录，脏范围上传，连续未变范围由上一版本复制，旧目录和证明缓冲沿用提交退休。

使用生产发布器、主机替代缓冲和 4,668 个分离来源做 A/B/A，各 240 帧。稳定样本的准备均值为 0.328／0.003／0.233 ms，46,680／0／46,680 行，来源巡检 4,668／0／4,668。旧路径每个来源摊销约 50～70 ns，包含十行目录填充、判等和来源巡检。交替增删 22 个尾部来源时为 0.879／0.359／0.813 ms，平均 46,691／11／46,691 行。候选的主机替代缓冲仍复制旧目录，模拟不包含重叠接触求解或真实 GPU 传输。

反方检查有三处。区间重叠可能把后写的行擦除，主机用同一目录双向换位对拍排除。主世界前缀和区段快照在移动中可能频繁变化，实机须查改写与巡检计数。旧设备版本的复制与在途驻留也可能抵消节省，须查主队列、资源和传输量。上述主机数据只支持保留默认关闭的候选，门槛不改。

实机用本体 `5B5846B55BCB` 在同一运行启用 S1、S2 对拍。静止、移动转头、放挖、箱子、区段卸载重载和 Sable 各通过 720 帧，资源重载五次共 1,800 帧，维度往返 840 帧，辅助视图 660 帧。同窗口主视图有 720 个非空帧，辅助视图没有刚体源。这次辅助视图对拍不能证明非空介质接触。记录在 `validations/performance-scene_replay/result/architecture-autonomous/s2/s1-validation/s1-scene-store-20261111-140130`。

用同一本体、同一 Extra、冻结城市与 S1 设定做实机 A/B/A，只切换 S2。移动时接触准备为 1.467／1.201／1.446 ms，候选比两侧均值少 0.255 ms（17.5%），未到 0.4 ms。平均写入行数 41,693／2,603／41,679，生命周期巡检 4,675／5.23／4,672。实际重制的接触证明仍约 20 份／帧，候选目录主机上传 62,484 B、设备内复制 938,087 B。节省了准备和主机传输，未消除设备端对原目录的读写。

### J1 自主推进开工

M0 记录方块实体整体约 5.35 ms，稳定输入求值约 0.66 ms，稳定选择约 1.05 ms。即使完全省去稳定输入求值，也远达不到 ≤ 1.0 ms，须一并消除常驻来源重新选择。现有区段索引掌握编译结果与所有者代际，原版接管可从这里维护主视图成员；外部视图仍显式选择，交接仍由发布器保留旧来源。判别先核对同一实体是否可能同时被主视图、子世界和交接选中，再测从区段增删到 Native 的来源差分。

已有稳定输入不等于可靠事件。信标光柱、末地折跃门冷却、保险库展示物、潮涌核心、饰纹陶罐、箱子配对、骷髅和依赖邻块的路径先固定活跃，后续有事件证据再缩小范围。抽查 4 帧按规程采用，最终用 1／2／4／8 帧对照。验收包含每帧最多三次 JNI、动画和文字逐项一致、区段卸载和重载所有者计数一致。现阶段仍需完成按视图的驻留提交，不能把只减少求值认作 J1 完成。
