# 持久实例选中与删除交错异常

2026-10-26 调查使用者在 Prism 人工验收中遇到的持久实例提交异常；修复不改变绘制语义，不重新运行性能对照。

## 问题

00:01:05 的崩溃报告为 `Submit persistent instance changes: invalid unordered_map<K, T> key`，调用经过 `RigidSceneNative.submit`、`LocalModelBatch.submitChanges` 及 `RigidModelCapture.submitAll`。安装的本体和 Extra 哈希与来源场景候选一致。已检查的当前日志没有设备丢失签名；不能据此将 Sable 或 Java 版本判为原因。

## 方法

保留原崩溃报告、latest/debug 日志并逐文件校验 SHA-256。只读检查 Java 来源寿命、快速选择与 Native 接受、删除和读取的顺序。使用实际生产 `InstanceStore` 头文件构造同一交错，另增加 opt-in 探针，让真实选择完成后、同批次 JNI 调用前删除来源。旧产物与源码快照保留，修复包使用单独的 `source-scene-fix` 目录。

## 发现

原 Native 先验证选中的实例仍存在，再处理删除，最后从已变更的表读取。相同身份同时属于不变选择与删除时，前置验证可以通过，最终读取却抛出报告中的异常。独立 MSVC 最小用例已复现相同错误文本；原人工运行未记录具体身份及移除事件，无法事后证明是哪一个来源触发。

快速选择原来只保存身份，没有像完整打包路径一样持有来源对象。修复后的选择同时保存强引用，并在 JNI 完成处设置可达性屏障。显式来源删除仍有效，不用强引用阻止合法删除。

Native 删除现在转移记录所有权：已被本批次选中且没有新参数的版本暂存到本批次，仍按既有帧／GPU 退休机制保留模型；它不恢复后续驻留。新参数替换旧版本时移除暂存及预算拒绝残留。同身份可在后续重新登记，旧帧快照不被新版本覆盖。真正缺少有效版本仍明确失败并给出身份，不吞异常。

## 结论

修复针对已复现的生命周期顺序缺陷；实际触发来源仍属证据边界。完整构建、发行核验、78 项原生与 23 项 GPU 检查通过，真实 Java／JNI 的已选中且无替换记录的来源删除交错通过。第一次组合运行误用了旧探针，虽正常完成，但不计作新增交错通过；修正打包入口并增加启动前包内容核验后才取得有效证据。使用者崩溃点位复验仍独立，不以一次自动运行代替长期稳定性或人工外观验收。原始证据与初步诊断在 `components/render_diagnostics/build/source-scene/prism-crash-20261026-000105/`，不覆盖上一轮实验记录。
