# 原版阶段 6、7 绘制收尾

2026-10-20 调查并实施。使用者已确认阶段 0～3 合并目视通过；本记录只核对原版及 NeoForge 的新增来源，不做性能比较。源码输入、请求归属、GPU 输出与使用者目视分别记录，CPU 提交确认不表示 GPU 已完成。

## 问题

普通粒子仍逐帧展开四个最终顶点；程序化来源与 GUI 已有后端，但缺少贯穿请求入口和执行消费者的统一核销。阶段 3 的 51 项保留来源不能以一份零计数表直接宣称迁移完成。

## 方法

复用既有持久资源、实例／历史、区段完成发布和附件后端。对照实际 `SingleQuadParticle` 生成器及其所有覆写入口；请求计数仅在显式启用的探针中汇总。通过的运行保留摘要，失败与交付保留原始证据。隔离验证入口为[原版请求核对](../../validations/conformance-vanilla/validation.md)。

## 发现

### 存储与状态整理

清理前外部占用 8,589,156,777 字节，清理后 6,400,464,193 字节；仓库排除 `.git` 与原生第三方源码后为 16,157,227,276 字节。已失效的 SDK 缓存先刷新到产品本就在用的系统 SDK，再回收副本；两份没有对应转储的旧 PDB、使用者已验收且正常关闭的阶段 0～3 临时客户端一并回收。输入、原始证据、冻结 C、世界夹具与源码保留。清单为 `build/takeover-stages/stage67-storage-retirement.json`。

旧状态页完整移入[历史阶段记录](../project/phase-1-before_vanilla_closeout.md)，当前页只保留已验收候选、当前工作和开放项；原有锚点引用随位置更新。

### 初始计数与驱动纠正

首次启动因工具误用了未安装的 `psutil`，且验证路径使一个 shader 文件名恰好达到 Windows 的 260 字符边界而失败；改用系统进程接口，验证目录缩短为 `conformance-vanilla`。没有修改产品的文件读取或渲染行为。

随后实际进入世界，加载、世界、GUI、重载已有请求及一次消费记录。但保存退出会泵入嵌套 `runTick`，初版路线驱动在断连返回前重复执行断连，退出码为 `0xC00000FD`，关闭未通过；没有设备丢失记录。已保存原始日志和计数，驱动增加覆盖该实际可达重入的作用域。该轮不是最终关闭或完整巡检通过。

初始探针还默认织入生产者 profiling Mixin，导致部件与烘焙来源按 adr-9 退回；固定请求巡检禁用这些无关 profiling 包装，不修改来源资格的判断。后续结果必须使用修正后的探针，不能将初始捕获比例当作正常产品比例。

### 严格 FG 后 GUI 的有界核查

本次查的是实际 CMake 固定的 Streamline **2.14.1**，不是其他版本 API。SDK 的 `ProgrammingGuideDLSS_G.md` 第 6.6 节明确将 HUD 与世界分别插值后再合成；`enableUserInterfaceRecomposition` 因此不满足“GUI 完全不插帧”。第 6.7 节和 `sl_dlss_g.h` 提供的是异步呈现 API 错误回调，要求立即保存错误并返回，不能作为绘制入口。

当前 Vulkan 路径在 `vkQueuePresentKHR` 前提交世界、UI 与依赖，并提供最终颜色、HUD-less 和 UI 输入。公开头文件没有应用侧逐生成帧 post-FG 绘制回调，也没有返回可由应用重新合成并呈现的生成帧纹理接口。本次不改 swapchain 所有权，不用错误回调绘制，不宣称 SDK UI Recomposition 等价于严格分离。严格 FG 后 GUI 保持开放项，交使用者决定；本轮不因此阻塞其他来源。

SDK 原文位于当前原生构建的 `build/v/_deps/streamline_sdk-src/{docs/ProgrammingGuideDLSS_G.md,include/sl_dlss_g.h}`；版本、下载来源及校验仍由 [Streamline 配置](../../components/native_renderer/cmake/Streamline.cmake)唯一固定。

### 粒子入口与中间失败

共享面在 `SingleQuadParticle.renderRotatedQuad` 的来源参数边界接入：原 `render`、朝向、roll、尺寸、sprite、照明和颜色回调继续执行，局部基础面与逐粒子姿态分开。LOOKAT_Y 的非单位四元数按原版向量旋转解释，不擅自归一化。历史采用原生要求的标记位、对象身份及同粒子的发射序号；容量不足时保留本帧动态网格，不丢几何。

第一次真实提交暴露了原刚性消费者检查将粒子的诊断 content name 当成离屏消费者；现只允许不改变执行 hit group 的 world resolver，仍拒绝 post/prebuilt 等消费者。随后振动粒子的非有限实例被拦在 GPU 提交前。崩溃报告明确为 `VibrationSignalParticle`、Age 30、位置与旋转 NaN；原版 `tick` 在寿命末尾计算 `1 / (lifetime-age)`。共享面路径保留原 PBR 顶点路径对这种无效末帧的退化处理，不向 AS 提交非有限实例。极小尺寸的法线先从未缩放基向量求出，避免构造过程额外下溢；这项边界回归不是振动粒子 NaN 的根因证明。

上述中间失败均为 CPU 异常，没有设备丢失。原始日志、崩溃报告与实际构件身份按各次 case 保存，没有将其关闭结果写为通过。

`procedural-20261020-062033` 正常保存关闭，实际加载 core 核对成功，160,107 个请求均一次消费，三个错误计数为零。但该轮使用了此前编译的探针：命令缩写 `probeJar` 被 Gradle 匹配为 `probeJarJar`，没有编译新增的探针源码。因此它只支持旧粒子输入对照、基础离屏透明叠加和生命周期，不能支持后来新增的深度／模板、字体淡出或完整路线。工具已增加逐源码的过期检查，后续显式执行 `probeClasses`。

### 状态夹具纠正与完整路线

完整路线首次因空烟花配置被原版构造器拒绝；改为非空、带拖尾及渐变色的原版组件。随后模板断言失败，源码核对发现夹具误用了 `enableStencil`：该 API 的 resize 会重新开启深度测试，普通 `RenderTarget.clear` 不清模板。显式恢复深度状态并清模板后，GPU 模板检查通过，无需修改产品。字体空画面同样来自夹具沿用了世界向上 Y 投影；改用真实 GUI 投影，并对同位置的两次字形读回比较 alpha。各次失败保留原日志，没有按产品缺陷虚报修复。

`full-20261020-065017` 完成 R0～R5、R7：菜单与两个冻结世界，小型模型／实体阵列、城市前移与返回、全部粒子和程序化输入、物品栏、GUI 缩放、1920×1080 → 1280×720 → 1920×1080、屏幕覆盖、F3+T，以及两个世界分别保存重进。退出码 0，四个场景实例有独立计数，未结束请求 0。17 个绘制族的 759,485 个请求全部一次消费，未消费、重复、未知分别为 0；每族均有正请求数。

共享粒子的 RGB／alpha 从顶点乘数移到逐实例乘数。已核对两条 PT 路径使用同一 `resolveSourceAlpha` 与 `applySurfaceMaterialColor`：这些普通粒子不使用表面覆盖混色，乘数合并不改变其 POST alpha 测试、裁切或颜色空间。原生的纹理 LOD 从变换后的实际三角形切线求出，不以无关的第三矩阵列估计粒子尺寸；历史仍由共同的模型／实例后端和完成退休负责。

真实 GPU 读回逐项通过 attachment → shader 采样 → 后续 alpha 叠加、cutout、半透明、字体淡出、层顺序、viewport/scissor、深度、模板与颜色写入。它不替代所有 GUI 的最终目视，也不证明严格 FG 后 GUI。实际加载 core 与包内相同；本次没有设备丢失，没有产生 GPU crash dump，不改变既有故障根因未知的结论。

原版区段本已由自有 `SectionBuilderMixins`／`FluidRendererMixins` 生成，保留来源高度、流向、贴图和已接受的 PT 颜色政策；本轮将真实动态输入和 JNI 完成发布纳入明确请求，不重复实现另一套流体。纯原版没有 `AdditionalSectionRenderer` 发送者；NeoForge 回调仍保留，模组附加几何不拿本次不适用结论放行。云沿用当前自有网格与已登记的既有差异，其重写仍另行批准。

原始数据在 `validations/conformance-vanilla/result/full-20261020-065017/`。源码、构件、构建门槛和合并目视状态以[当前状态](../project/status-current.md)为准。原 51 项和额外捕获按[覆盖表](../reference/registry-takeover_coverage.md)逐项保留；严格 FG、历史 C 的 p95 来源、GPU 根因及长期稳定性仍为开放项，本次不新测性能。

## 结论

阶段 6、7 的原版限定自动门槛与固定路线核销通过，新增目视待使用者验收。中间失败、纠正与最终通过各自保留，不混用不同探针或候选的结论；不把纯原版核销扩大为模组变体、所有分支的最终 RGB、设备丢失根因或稳定性闭合。当前停止于合并目视交付；之后按已确认顺序另行执行修改者变体与阶段 4、5、8。
