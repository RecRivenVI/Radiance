# 二期帧槽位与工作线程实验

2026-11-13。按二期规划核对所有权、帧线程开销及可以实际并行的工作。

## 问题

原 P1 在城市 32 视距把渲染线程 CPU 降到约 15.69 ms，整帧仍增加 1.48 ms。首次阻塞位置随帧变化。原 JNI 普查的串行 `streamlineFrameEvent` 均值为 1.79 ms。需要区分 SDK 等待、帧交接和线程唤醒。

## 方法

A0 对照使用城市冻结移动路线、2560×1440、32 视距、模拟距离 12、RR Balanced、FG 关。本体 `a9fb8b9d8668…`，Extra `52a49fb65298…`，探针 `fe74e8d679ad…`。相邻关闭、开启、关闭各有一个 12 秒整帧窗口。另取各自的 `TIMED` 窗口记录阶段，帧线程开启时同时开启原 P1 的输入重叠。所有权检查独立验证，正式计时关闭。

运行结果位于 `validations/performance-scene_replay/result/architecture-phase-two-20261113/development/a0`。对应三窗分别为 `p1-a0-r32-1440-20261113-052212`、`p1-b-r32-1440-20261113-052611` 与 `p1-a1-r32-1440-20261113-053004`。

### A3 同步减负与槽位实验

目标是在同一城市路线区分生产端同步、槽位栅栏和主队列空档。先保留原缓冲同步，使用完整入口名确认等待来源。然后将确认可推迟的上传交给对应槽位。在同一构件以 Reflex 模式 2 比较两个和三个槽位，再用最佳配置做帧线程关／开／关对照。新增槽位以采样到的进程专用显存峰值衡量，超过 1 GiB 时先追查分配构成。

A3 构件实际上固定使用三个槽位。实验把工作线程模式默认设为两个，`RADIANCE_FRAME_RECORDING_SLOTS=3` 选择三个。串行保留原有三个槽位。Sable 姿态、端点采样、着色及照明继承在生产侧更新，和该帧的空间快照一同交接。空间移除还会为交接中的区段保存最终姿态，仍在同步边界执行。

### A4 区段完成发布与预算拆分

### 11 月 14 日历史读取位置与命中有效性

玻璃转头重放使用 `cc2.zip`／`7cf50e8be70e…`／`cc2.zip`，三个窗口各预热 60 帧、计时 120 帧。世界 PT 为 42.454／42.538／42.326 ms，世界命令批次为 45.185／45.281／45.055 ms，RR 为 2.195／2.197／2.188 ms。三份末帧原始文件和 PNG 的哈希各自一致。推后历史读取在玻璃中未节省可辨认的耗时，实验包保留，产品继续原读取顺序。证据见 `non-ser-continuation-20261114/late-history-glass-1700/`。

命中阶段用 FP16 相邻值保守判断哪些面可能需要写历史法线，引导循环仍按实际读回的材质分类。Vulkan 未指定浮点格式转换的舍入模式，因此不依赖着色器手工舍入与存储图像写入始终相同。每次新追踪清除历史状态，只有当前命中成功读到历史三角形且写出历史法线时才附带有效位。无历史时回退到当前法线。介质探测和恢复仍在未完成的命中中用同一个字段传递三角面编号。两者的使用时机分开。

缺少 GPU 计数的直接原因是旧计时脚本 `g.py` 在导入时清除 `RADIANCE_SHARC_AUDIT`。续做入口恢复显式请求，计数专窗可同时取得原有 SHARC、介质和新增的历史三角形读取次数。诊断中尝试的 Native 栅栏读回改动已撤回，继续使用原有读回方式。

SHARC 开启的固定玻璃快照，每帧原有采样像素均为 4,929，介质查询与恢复均约 1,600 次。对齐两窗已有的 35 帧，历史三角形读取由约 15,825 降到 15,014 次，减少约 5.1%。计数覆盖大小不同的 dispatch，不能按一个缩放倍数换算全屏读取次数。正式玻璃转头窗未见耗时下降，因此计数证明消除了重复读取，不能证明这部分是动态城市的主要退步。证据见 `non-ser-continuation-20261114/guide-history-counts-armed-1700/`。

## 结论

串行入口的主要成本是 Reflex 休眠。此次实测休眠占同入口的 91%～93%，旧 JNI 普查中的 1.79 ms 没有等工作线程的可能。开启 P1 后，休眠转到 `prepareNextFrame`，整帧比两侧均值慢 1.10 ms。GPU 主队列仍在两侧范围内，唤醒只占约 0.036 ms。数据能确认 Reflex 等待的位置与量级发生变化，无法把旧的 1.48 ms 逐项归到调度、缓存或驱动。可重叠墙钟包括生产端的 Reflex 休眠，不能当作 Java 与 Native 同时做有用工作的时间。

A4 查询镜像和 A5 帧号修复保留，区段预算与发布拆分候选撤回。外部评审依据两份快照的逐像素结果接受 A6 画面，静态灯具和固定 tick 的实机对拍继续待验。Remix 32 的尾部退步与三槽的模拟至 GPU 完成延迟由使用者体验评估。默认配置改为三槽帧线程，设置 `RADIANCE_NATIVE_FRAME_WORKER=0` 回到两槽串行。FG 仍需使用者在有窗口焦点时验证。
