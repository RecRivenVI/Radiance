# 渲染工作量、坐标精度与发布生命周期审查

2026-10-31，本轮以实际 T+S 配套及两仓库未提交工作为起点，检查来源解释、公共平台、Native、着色器和回退路径。先采当前基线，再实施有针对性的改动；水晶 R+S 的历史收益没有充当本轮基线。以下分别说明源码判断、自动检查、实际运行、性能及尚待人工体验的边界。

## 问题

水晶此前暴露了提前转换 float、每次区段发布重建稳定资源，以及替代内容未就绪便撤下旧画面的不同问题。不能据此推断所有 CPU 几何都应搬到 GPU，也不能将模型持久化或缓存命中率等同于整帧提速。本轮寻找值得修复的同类问题，并核对移动、加载和对象移除后的占用与慢帧。

## 方法

冻结本体 T `25e184dd…`、Extra S `ca020c76…` 和探针 C `f9c9ef83…`，两仓库起始源码取配套 `source-pair.zip`，不是仅用 HEAD 描述脏工作区。当前提交分别为本体 `43cc7ded…`、Extra `02b61826…`。最终 W 本体 `f0a7ddf4…`、Extra `106660da…`、Native `c4954095…`，原始产品源码快照 `c88af1b6…`；本轮晚些时候只调整探针隔离、夹具强加载票据及文档，产品路径未再改变。

城市复用已冻结的纯原版城市输入 `832a650f…`，32 视距和模拟距离、正常游玩配置登记项 `prism_city_baseline_20261029`。核对运行时为 Vanilla PT、四次反弹、随机覆盖、DLSS Balanced、FG 关闭及相同资源包；没有把先前异常的 128 次反弹当作基线。项目实例静音、1920×1080 与 2560×1440，16 GiB 最大堆；城市不带 Voxy。第三方专项使用相应的固定本地输入，不取外部活跃实例，也不修改 Prism。

FRAME_ONLY 用于实际帧时间，TIMED 用于归因，生命周期流程包含初次加载、三分钟固定飞行、128 个不同实体的创建／移动／移除、退出重进。两边恢复同一世界输入和路线，但不冻结原本的生物和模拟；约千个自然实体存在少量数量差异，不能把几个百分点的小差异归为确定收益。首次和重进分开，操作系统及驱动缓存没有清空。

GPU 数据来自已完成主队列时间戳和另窗分段，不是逐帧 CPU/GPU 令牌配对或硬件忙碌计数；并行及嵌套区间不相加。Windows 渲染线程 CPU 时钟以 15.625 ms 量化，窗口均值比单帧 CPU 分位更有意义。帧间隔分位保留原始长帧，不剪尾；WDDM 使用本进程的专用／共享显存，整卡 NVML 只辅助解释。共享显存包含合法的主机可见缓冲，不能全部称为驱动换页。

## 发现

### 保留的修复与优化

**区块材质记录的无损字典。** 80 字节材质记录包含逐顶点 UV、颜色、法线及标志；城市中大量记录完全相同，原来每个顶点仍各存一份。后台打包现在按完整位模式建立每几何字典及 32 位索引，只有节省至少四分之一时才使用，否则保留直接数组。不量化数值、不省几何、不更改 BLAS 或来源材质。各区块仍独立拥有缓冲，卸载一个区块不会被同批次其他区块长期钉住。

GPU 增加间接读取和一个格式分支，这是实际代价；不能只看主机上传字节。CPU 侧只有构建时的临时表，不另留常驻材质副本。GPU 对照按全部 80 字节核验，包括有符号零和 NaN 位模式；这些测试仅检验材质传输，不将 NaN 位置送进真实 AS。所有三角形材质解码使用同一入口，Voxy 原有紧凑解码保持独立。

**水晶资源失效收敛。** 原先区段发布身份变化就关闭 Mesh，即使水晶几何、局部原点和材质输入没有改变，也重建模型、计算输入、颜色场及身份。现在只在新发布到来时比较完整不可变来源定义；相同内容接受新发布版本并继续持有资源，真实变化先创建替代项，再关闭旧项。不是每帧重新哈希顶点，也没有保留所有历史形状。颜色闪烁和真正形变仍继续计算。

三十次普通方块修改的精确计数由三十次定义创建变为零。为隔离 Native 材质改动，另构造只替换旧 `LevititeWorldAdapter` 类族的测试控制包，其余字节与 W Extra 相同；该包不作为候选交付。干净窗口中编辑阶段约 6.012→5.882 ms，但其他未改动窗口同时有正负波动，不能将这一个 2.2% 差值宣布为稳定 FPS 收益。保留它的依据是确认消除不必要资源生产、降低编辑窗口收集成本，并维持真实内容更新。

**End Sea 投影精度。** 水平原点从 double 提前变为绝对 float，会在两千万附近丢掉方块内乃至奇数方块精度。公共平面接口保留 double 水平原点，将高部与残差存入现有 112 字节参数；先在 double 中做相机相减，再转局部 float。遮罩、命中、阴影与光源求值使用一致空间；重复／镜像重复 UV 在转 float 前减周期，夹取纹理保持原边界。采样器寻址改变也使相关材质快照失效。API 升到 16，须配套 Extra，不能混装旧公共方法描述符。

真实 End Sea 夹具已检查正负两千万坐标、倾斜旋转中心、摄像机相对位置、来源深度／软强度读回和材质发布原点。GPU 回归另覆盖小步摄像机移动、重复／镜像／夹取及旧公式负对照。实际截图不代替用户连续动态验收，也不据此宣称全部远坐标系统已无误差。

**接触形状通知缺口。** 接触缓存监听的是来源区段，而以前公共通知依赖 RenderSection 存在；未建立该对象的空间可能漏通知。现在方块变化入口直接通知独立的区段形状订阅，负坐标按区段整除规范化，常规区段变化仍共用该入口。专门回归覆盖没有 RenderSection 与负坐标；这修复已确认的通知路径缺口，不冒称此前已复现某个具体接触画面错误。第三方若暗改碰撞形状而不发任何更新，仍需其来源合同提供通知，不添加逐帧全世界扫描。

### 撤回及保持不动的部分

收尾确认同内容内置 ZIP 会因元数据改变而使解包标记变化；现有着色器源码哈希缓存仍可复用，不能直接说全部着色器重新编译。固定 mtime 的打包原型没有使两次真实 INSTALL 的 ZIP 一致，未取得启动净收益，本轮撤回该原型，没有把新重链接产物替换成实测 W。包条目及嵌套源码逐项对照保留，作为低优先级构建线索，不继续扩张打包体系。

减少未使用静态历史矩阵的 U 原型，城市干净窗口由 25.101→25.059 ms，未支持可靠收益，已撤回自身四个文件的改动。源码快照、结果与退役清单保留；没有用测试通过作为保留额外表结构的理由。

弹簧持续形变、普通粒子和显式线展开仍可能有密集场景成本，但当前来源已经避免先生成全部内容再比较。小批量工作移动到 GPU 会新增参数准备、分派、同步及 AS 更新，现有证据不足以支持迁移。没有将 Java 改成 Native CPU 冒充 GPU 优化。

共同空间、请求代际、已发布版本、纹理代际及帧退休分别解决不同的寿命问题，保留这些状态是必要的。重载和删除不能只清缓存，也不能让旧结果覆盖新请求。此前 T 修好的水晶发布空窗在本轮真实区段编辑中继续通过，这是继承的正确性修复，不重复计算本轮收益。

### 过程中的诊断问题

第一次远坐标夹具将刚体移到未加载地区而没有 Sable 强加载票据，来源卸载后探针继续访问旧物理体，导致服务端异常。保留失败证据，修正夹具使用来源正式票据后通过；不是设备丢失，也不修改产品加载规则。

Voxy 独立组合暴露 Extra 的水晶 Ponder 探针未按请求隔离，菜单 draw 触发缺席的 Sable 类加载。修正探针启用条件后七阶段通过；产品 JAR 未因这个诊断错误改变。一次精度 GPU 测试的输入也曾先被 GLSL 无后缀 float 字面量舍入，修正测试为 double 字面量后，生产公式与负对照才得到有效验证。失败没有删掉、吞异常或计为通过。

## 结论

本轮保留无损材质字典、水晶按内容接受新发布，以及平面投影／形状通知正确性修复；静态历史表 U 原型撤回。最终产品仍为前述 W，人工体验未代填。
