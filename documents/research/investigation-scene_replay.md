# Native 场景重放与介质状态减负

2026-11-07，147 号任务因新增捕获代码的原生栈溢出停止，尚未完成工具的运行交付，也没有本轮城市 A/B 收益。停止后只保全证据和静态符号定位，未重试客户端或独立重放器。

## 问题

需要从当前生产场景冻结几何、材质、实例、相机、配置和介质接触数据，脱离 JVM 对相同输入重载算法包，并测量保持四项介质修复的单项减负。起点为本体 `ad5d465`、Extra `953ed9d`，已有 C6、final7 和修复前数字仅作历史背景。

主要风险是分页静态场景漏捕、嵌套设备地址或资源寿命错误，以及 A/B 历史和采样不一致。旧原型位于 `D:/Workspaces/Artifacts/Radiance/history-archive/MCVRSceneReplay/20260924/replay-free-camera/source.zip`；没有修改其内容。

## 方法

开发构建以 `-Pnative.sceneReplay=true` 启用，普通构建默认关闭；加载器、私有开发 DLL 和快照不进入发行包。复用生产 WorldPrepare、SBT、世界模块、RR 及 GPU 时间戳，不模拟 Java 来源生产。

捕获按实际顺序展开静态分页和动态表，保留 BLAS 输入与构建标志、贴图及采样器、附加层、完整 TextureMapping、天空和世界 UBO、船内排水域及 C6 接触过滤表。通过原帧资源退休等待读回，ZIP／Deflate 发布后才出现 `scene.json`。载入阶段验证输入边界并重定位基础及嵌套地址，缺少输入明确失败；不默默忽略发光采样表、FG、LoD 或世界后置光栅。

固定与预设转头窗口计划、同进程安全重建、采样序列和时间历史重置、图片与 GPU 归属帧统计已经编写，但没有完成实际重放验证。快照格式为本地 ABI 的 `radiance-native-scene-v2`。入口命令见[开发说明](../development/debugging-scene_replay.md)。

B 实验只将 Vanilla PT 中跨命中阶段传递的外层介质由完整 `vec4` 改为 IOR 标量；完整颜色吸收仍保留在 RGEN 的 MediumHistory，Advanced 的完整表面缓存不变。它只存在于 `compact-payload/compact-vanilla-pt.zip`，产品着色器未修改。实际驱动寄存器、溢出和占用没有新证据，不能将结构体减少 12 字节等同于寄存器节省。

## 发现

- 开发构建成功；`spotlessApply check verifyRelease` 成功（复用此前已成功的 Native 构建，排除重复的 configure/build 任务），84 项非 GPU CTest 和 29 项 GPU 契约通过。
- 新增 ZIP 真实读写、范围重定位及预算检查；Python 检查延迟 GPU 样本归属、预热／捕获帧排除，并回归启动前冻结 Extra 的路径要求。
- B 的 181 个定向 RT 请求离线编译通过；精简 Payload 的介质 GPU 契约通过。夹具两处外层 IOR 读数改用相同含义的访问器，未放宽断言。这些不是客户端画面或性能证明。

第一次准备在游戏启动前被既有运行器拒绝：Extra 产物必须位于本体项目内。工具已改为在快照输入目录冻结同一哈希的 Extra，再交给运行器。该次没有创建 Java 客户端；可再生准备目录已回收，原因保留。

### 原生崩溃与静态定位

实际城市运行 `replay-game-r32-1440-20261107-100258` 的 PID 为 37808，10:04:50 在首次世界渲染时发生 `EXCEPTION_STACK_OVERFLOW (0xc00000fd)`，没有完成正式计时窗口或捕获请求。

匹配 PDB 的符号解析与 DLL 机器码确认：

- `core.dll+0x1000577` 是 `__chkstk+55`。
- 栈中的返回地址 `+0x513ca6` 是 `mcvr::replay::capture+22`，后续属于 `WorldPrepareContext::render`。
- 捕获函数入口的指令载入 `0x100ac0`，即 1,051,328 字节栈探测；Java Render thread 栈为 1,048,576 字节。
- `TextureMapping` 本身为 524,304 字节；按值 UBO 读取与序列化临时对象对应这里的大栈风险。栈帧在捕获请求判断之前建立，因此尚未请求快照也会溢出。

这是本轮新工具引入的 CPU 栈缺陷，不是 C7 的驱动管线创建异常，也不是 B 的性能结果。日志没有设备丢失记录，但不据此宣称 GPU 正确性已经验证。后续应去掉大型栈临时对象，并复查捕获、验证和重放准备中的同类按值数据；不通过增大 Java 栈掩盖。按本轮明确停止条件，没有实施后再试。

证据统一位于 `validations/performance-scene_replay/result/`：`STOP.json`、上述运行目录的日志／崩溃报告、`native-symbols.json`、`native-stack-frame.json`、`failure-preservation.json` 和 `implementation-source-final.zip`。失败构件与匹配私有开发符号保留；原冻结城市、配置和其他失败证据没有覆盖。

## 结论

重放器尚不能交付为可靠计时工具，当前不可根据它选择或保留 B。保留未改产品着色器的 C6 基线与实验记录，不宣称介质退化已经消除。本轮没有提交、推送、投放 Prism 或恢复其他开发任务。

下一步先修复捕获大栈对象，再在获得继续运行安排后完成同版本捕获／重放一致性和自身波动；工具成立之后，才进入同进程相邻 A/B。历史研究记录保持原样。
