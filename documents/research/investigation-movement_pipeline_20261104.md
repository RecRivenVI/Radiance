# 城市移动时的区段与场景组织优化

2026-11-04。本轮在当前工作区上一次实施四项优化，再进行统一回归和一组同城移动对照；没有逐项全量性能实验，没有减少几何、采样或画质，也没有启用 FG。

## 问题

此前移动记录显示，空区段完成仍能失效静态场景；线性槽位分页使跨 X 边界影响过多页面；设备虽有同族多队列，却选择不同族队列而退回渲染线程构建；动态前缀变化会触发整份 SBT 重新打包。这些工作与世界 PT 的 GPU 开销同时存在，不能由局部省时推算整个场景达到 60 FPS。

## 方法

基线为实际用于上一轮城市录制的 JAR，SHA-256 为 `341ec5d13019536bd28e1aa5bb2f388b9714d6396d10c68dbe2cb35bc92c15ae`。候选为 `b0fea12c8c568f3d31508238f119e0c02ec5424d52ede40dc760f02061295dd6`，配套 Extra 不变。两份源码覆盖快照随各自候选保留。

使用项目内同一 Newport City 存档副本，分别恢复同一冻结存档和配置，运行中核对实际模块与选项一致：32 视距、2560×1440、4 次反弹、DLSS balanced、RR、SHARC、连续光学引导、均衡透明分支、随机覆盖，FG 关闭。自动实例静音，不操作 Prism 存档或设置。固定日照与天气，加载后预热 90 秒；这不是首次编译测试，也不保证所有可见区段已经发布。

正式记录使用 FRAME_ONLY：移动前静止 15 秒，以每秒 8 方块沿 512 方块方形路线移动 64 秒，窗口包含末尾约 4 秒，再静止记录。通过既有服务器位置接口每 50ms 更新位置；记录的实际相机覆盖相同范围，保留碰撞与插值产生的小幅偏移，不等同于真人连续飞行。短 TIMED 往返路线仅解释阶段耗时，4 秒 FLOW_AUDIT 仅核对队列与实际表变化，不用于正式整帧收益。

证据位于 `validations/performance-sources/result/movement-opt-20261104/`：`comparison.json`、两组 `launch.json`、`effective-settings.json`、路线、截图、负载记录及经过逐文件 SHA-256 读回校验的 `profiles/*/raw.zip`。原始存档输入在工具组件 `build/movement-opt-20261104/world-input.zip`，配置及缓存的退役映射见同一证据目录。两次运行均未检测到其他游戏重叠，正常退出，无新 GPU 转储或设备丢失。

## 发现

### 实现与正确性

- 空完成继续推进区段版本和交接；只有确实移除已发布几何才失效静态场景。各字段独立复用 CPU 数据和目录，不持有旧页的 GPU 资源。
- 主世界静态页改为 4×4×4 槽位网格。65×24×65 网格的一整列槽位影响 102 个页，X、Z 对称；这只是索引覆盖的上界，不是运行中每次重建的页数。TLAS、材质和 SBT 共用新顺序，相机与历史继续按原规则生成。
- 主队列族具有至少两条队列时使用同族第二队列，接通现有后台区段路径。原预算、代际、fence、发布 semaphore 和资源退休保留；无能力设备继续原同步路径。本机 FLOW 实测后台标志从 0 变为 1，两条队列族均为 0。
- 每个管线、pass、帧槽缓存当前使用的静态 SBT 打包块，动态前缀变化只调整真实偏移；CPU 暂存复用容量。映射变化重新生成，旧 GPU 表仍不可覆盖。移动细分窗口约 88.5% 的打包字节来自稳定块复制；GPU 表分配、上传及元数据复制仍存在。

`spotlessApply`、`check verifyRelease` 通过，合规失败 0、警告 0；Native CPU CTest 82 项及 GPU 29 项通过。新增回归检查空发布、空间页边界、字段和目录复用、索引与历史、旧资源退休、SBT 前缀平移和映射失效。两次客户端正常完成路线，静止截图没有发现明显内容差异；这不代替使用者的连续画面验收。

### 端到端结果

| 指标 | 基线 | 候选 |
| --- | ---: | ---: |
| 移动平均帧间隔 | 29.08 ms | 25.18 ms |
| 移动平均真实 FPS | 34.39 | 39.71 |
| 移动 p95 | 41.37 ms | 35.51 ms |
| 移动 p99 | 57.61 ms | 42.94 ms |
| 移动超过 50ms | 51 帧 | 9 帧 |
| 移动超过 100ms | 2 帧 | 2 帧 |
| 最长帧间隔 | 293.01 ms | 231.84 ms |
| 移动前静止平均 | 21.96 ms | 22.09 ms |
| 返回后静止平均 | 22.10 ms | 22.01 ms |

移动平均帧间隔降低 **13.4%**，p95 降低 14.2%，p99 降低 25.5%；静止平均变化不足 1%。保留全部帧，没有裁掉长帧。只有一组配对路线，不提供跨场景置信区间，也不宣称消除了所有移动卡顿。

在短 TIMED 移动窗口，静态场景刷新从 1.088 降至 0.673 ms/帧，SBT 打包从 1.591 降至 1.031 ms/帧；渲染线程上的区段批次录制转入后台，不能据此声称这部分工作消失。阶段存在包含关系，后台也与渲染重叠，不将这些局部差值相加作为整帧收益。

### 代价与限制

短 TIMED 移动窗口主 GPU 区间从 20.18 增至 21.47 ms；它与正式 FRAME_ONLY 路线不是同一个窗口，不能替代端到端结果。后台 GPU 工作可能竞争执行资源，记录的已发布内容也不同：候选最后 FLOW 窗口有 17,957 条静态区段记录，基线平均 17,765；排队计数分别为 0 与 19。不能将 GPU 差额全部归因于某一个优化，也不能把不同发布时点当作严格相同驻留内容的 GPU 对照。该差额明确保留，没有撤回整轮改动或伪称 GPU 提速。

进程私有提交峰值从 14.46 增至 15.31 GiB，工作集峰值从 6.39 增至 7.11 GiB。当前稳定块增加了 CPU 副本，但 JVM、驱动、在途工作和不同发布时点也在这些数值内；没有证据把整份差额都归到 SBT 缓存。缓存仅保留当前使用的块，不积累历史版本。整卡显存峰值从 13.83 变为 13.74 GiB，VMA 分配合计峰值从 6.58 变为 6.43 GiB；前者包含桌面等其他使用，后者包含不同内存类型，均不能直接当作本进程独占显存。

仍有两次超过 100ms 的长帧，公共元数据全表版本、实例求值及 GPU 世界 PT 的成本仍存在。本轮不扩大为其他渲染器重写。

## 结论

四项均保留。当前证据支持移动时平均及尾部帧时间改善，静止性能基本不变，同时付出更高的进程内存峰值，GPU 并行区间也存在上述差额。候选可交使用者在 Prism 体验；复杂交接、不同硬件及连续视觉仍以实际验收为准。本轮未提交、推送或启动 Prism。
