# 接管工程阶段 0～2 与地形样板

2026-10-19。本记录对应使用者批准的阶段 0、1、2 和一条地形发布样板；只对阶段 2 固定夹具进行性能比较。完整来源接管、严格 FG 后独立 GUI、设备丢失根因和长期稳定性不在本次通过范围内。

## 问题

此前 Voxy 把合法的请求根集合与 8192 个驻留网格共用容量限制，导致应用异常。物品框已有持久网格后端，但仍逐帧产生并比较完整 recipe；稳定状态仍经过完整 setup/clear。需要用实际资源来源取代这种重复推断，并验证同一最小骨架可以承载区段版本发布。

## 方法

按[接管计划](../project/plan-render_takeover.md)和[双轴登记](../reference/registry-takeover_coverage.md)限定修改。旧产品为改产品前保留的实际发行 JAR，SHA-256 为 `47F3CDA39B061CEF4706D1D7F8F24A609AB98354A2109CCA5DAF761DB0527B1A`，内嵌 core 为 `B023613AE93F98B4D54433ADB97D78D50DB1A380D4F8403F83FBE580F30A712C`。其完整原始源码在 `validations/conformance-boundaries/result/source-final.{json,zip}`；HEAD 不是脏工作区的完整身份。

模型来源由实际标准 JSON baker 声明，经 ModelManager 最终发布确认。每帧继续执行模型选择、事件、姿态和 tint 回调；不支持的自定义模型、foil／轮廓包装等使用原实际输入路径。来源被外部 Mixin 修改时保守回退，不把 `SimpleBakedModel` 类名本身当作稳定证明。局部资源和外观版本都有容量与字节上限，重载、淘汰不取代 native 的独立 GPU 引用退休。

功能比较只在[模型与地形验证](../../validations/conformance-takeover/validation.md)中执行原生成器双路径；正式[性能比较](../../validations/performance-takeover/validation.md)关闭双执行与重型生产者归因。夹具含 160 个物品框、24 幅绘画，使用同一已保存世界、设置和固定摆动视角；1920×1080 输出、NRD/FSR 预设、视距 8、静音。不是城市、原生全分辨率 1080p 或 Voxy 性能测试。

地形样板连续修改 x=15/16 的边界方块，保留水并执行真实 `AddSectionGeometryEvent` renderer。关联 GPU build fence 完成、当前代际发布、TLAS 记录及随后完成帧；CPU 已记录命令不能冒充 GPU 已执行，也不声称证明了首个显示像素。

## 发现

### 实现与直接反例

- Voxy 请求域改为有界的紧凑行区间，保留来源最大 64 根单元范围；驻留仍为 8192，字节预算保持不变。CPU 红测试先复现旧错误，修复后 74/74 通过；Java 与实际客户端结果分别核销。
- 六类数据表达资源、实例、更新、绘制、依赖和发布，世界／GUI／屏幕域分开；仅实现样板实际消费者，未提前构建通用 GLSL 或替换 SDK 呈现。
- 物品框资源热帧只取实际外观标量和姿态，不再次完整展开、hash 或创建 BLAS；绘画继续复用其既有网格后端，不把之前已经消除的绘画顶点量计算为本轮收益。
- 静态材质状态适配保留原 `CULL(true)` 和默认线宽的实际 no-op 行为。不能把默认 cull 擅自解释为每次强制启用。
- 区段发布加入当前 epoch、owner、revision 与完成条件的共同判定；空版本、同一有序命令图与已完成异步 fence 分开。旧有效几何在新构建期间保持原有寿命。

### 首次失败与纠正

最初功能运行因诊断自身的 item/baked 归因 Mixin 使来源资格不可证明而安全回退，不能记为接管通过。已在该限定用例关闭不使用的生产者归因，未在产品端绕过资格检查。后续绘画重载检查发现夹具的墙体填充早于区块就绪，绘画支撑实际为空；先加入服务器支撑／存活诊断，再等待所有夹具区块加载后建立世界，没有修改产品以掩盖夹具错误。

第一次完整配套检查因 JNI 文件格式失败，使用既有 clang-format 修正；下一轮 348 项 GAME 测试中一个旧所有权测试仍用空几何占位，新增资源身份读取使其失败，已改为有身份的测试几何。原始失败日志保留在 `build/takeover-stages/`，不将失败算为通过。

第一次通过的功能候选证据为 `validations/conformance-takeover/result/functional-20261019-200420/`：实际烘焙源 1,024 次／79,584 顶点比较、热窗构建数 28→28，重载前后绘画实际比较、12 次边界修改和 1,580 条完成链通过。该候选之后又收紧资源声明和源缓存总预算，最终产物必须另行运行；不把此过程记录当成最终产物验证。

四个进程的刚性实例均为 344、引用顶点 25,376、原生刚性驻留模型 8，静态区段记录 687／345,212 字节，静态重建及缓存构建为 0。普通动态批次通常约 48 顶点／1 个 BLAS 输入；原始瞬时峰值分别为 6,316 顶点、2 个输入和 1,034 个 TLAS 实例。元数据逻辑上传峰值 510,424 字节／帧，实体 GPU 上传计量峰值 6,896 字节；不是 PCIe 实际传输量。基线已经复用大部分几何，不能把这些既有节省再次算作本轮顶点／BLAS 收益。

本轮没有取得全进程 VMA／显存峰值，报告将未观测值写为 null，不能把原始零采样当作零显存。CPU 缓存预算、实际模型／实例／上传峰值与在途退休的验证已分别保留；整卡启动前占用不能用于计算 Minecraft 独占显存。16 个正式窗口无 writer/native/cap 丢样，四个进程均完成四窗、保存与 native 关闭，实际 DLL 均从各自实例加载并与对应内嵌 DLL 哈希一致。没有设备丢失。

第一次正式启动在进世界前失败：手工读取 VM／程序参数文件没有带上 ModDevGradle `RunGameTask.exec()` 才安装的 `classpathProvider`，NeoForge 找不到 `MinecraftServer.class`。没有采样或设备丢失，native 关闭后保留 `validations/performance-takeover/result/attempt-1-launch/`。现从实际 Gradle task 导出相同 classpath，以 Java 参数文件传递，实际加载 DLL 另经 OS 模块路径与内嵌哈希核对；不借用当前产品开发 classes 来执行基线。

第二次进入世界后，旧 benchmark agent 的默认 30 秒预热加 30 秒采样触发自动退出，只有一个完整窗口和一个中断窗口。证据在 `validations/performance-takeover/result/attempt-2-agent-stop/`，不计入完整对照。现仅使用 agent 的输入隔离功能，由阶段驱动控制四个窗口及正常退出；FrameProfiler 自己完成采样。同时以真实归档格式补充测试，场景名从 METADATA 读取，不再假定时间戳目录包含场景名。没有修改产品来处理这两项工具问题。

### 使用者目视清单

1. 多个物品框共享同一物品，分别旋转、替换与移除，检查相邻对象不串姿态、颜色或残留；同时看框体和框内物品。
2. 检查 tint 物品、镂空植物与玻璃的颜色、边缘和透射；检查附魔 foil、发光轮廓、发光物品框及地图分支。后几项保留其实际消费者，不声称已全部直接化。
3. 从正面、背面及侧面看不同尺寸绘画，检查前后贴图、厚度、逐格受光和运动历史。
4. F3+T 后重复前述操作，保存退出、重进世界，检查模型／纹理更新与删除重建；自动通过不替代长期视觉观察。
5. 在区段边界反复放挖，观察水面和相邻几何更新；确认构建中没有短暂清空原有效几何，反射／阴影仍包含相机之外的几何。
6. 如需 Voxy，先用普通低压力路线观察近远景交接和水／cutout；最大请求范围的自动通过不等于远景整体画面验收。
7. GUI 物品、Ponder 默认行为与屏幕效果只做回归观察；本轮没有实现严格 FG 后 GUI，不能将输入或静态截图算成生成帧动态通过。

## 结论

阶段 0、1、2 和地形样板的限定自动门槛已具备对应证据，阶段 2 值得在使用者验收后继续分批推广。来源直接声明、稳定热帧与实际状态适配减少了 CPU 工作，本样板取得约 8% 帧间隔下降；没有依据将其推广到城市、其他模组组合或 60 FPS 目标。接口／回归和原始数据与目视验收分开，未迁移来源及源数组被第三方直接修改的更新合同不能靠标准模型类名自动扩大覆盖。

本 Goal 到此批样板和人工交接为止，不进入阶段 3。使用者目视、完整显存峰值、严格 FG／GUI、全来源程序、长期稳定性及既有未知 GPU 故障保持未完成，公开二进制许可门禁不变。不提交、推送或投放 Prism。阶段补丁位于 `D:/Workspaces/Scratches/RadianceUnification/takeover-stage-{0,1,2,terrain}.zip`；它们是范围明确的审查差量，完整前置未提交源码与最终状态由 final ZIP／索引恢复，不把 HEAD 当完整工作区身份。
