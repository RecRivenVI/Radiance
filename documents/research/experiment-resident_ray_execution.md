# 来源常驻与光线追踪执行实验

2026-11-08。去除方块实体的 64 格客户端门槛后，实际参与光追的场景扩大。合批省下一部分 CPU 工作，整合候选在 SPBR 城市移动和 RTX Remix 固定视角上仍慢于 149。双光路计数通过 GPU 契约和两个算法的定向介质场景，光源表与加速实验仍有覆盖或正确性缺口。

## 问题

来源常驻是否能抵消完整方块实体场景的生产与提交成本，反射和折射预算是否正确独立，以及光源采样、镂空和着色重排是否值得常驻。

## 方法

使用 149 实测构件作为旧配置锚点。城市的探索对照采用 Newport City、SPBR 两层资源包、位置 `(-94.5, 143, 182.5)`、偏航 28°、俯仰 17°、视场 70°。输出 2560×1440、32 视距、RR Balanced、关闭 FG。三次运行使用相同探针、路线及冻结输入。细分采样和未启用细分的窗口独立比较。

介质夹具使用水、红蓝及青色玻璃、真实空气间隙和动态接触。普通透明玻璃用于非介质对照。最大计数先由小型 GPU 契约覆盖，城市只采用新默认值。

### 城市配套候选

正式对照改用俯看街区的 `(-94.5, 150, 182.5)`、偏航 208°、俯仰 13°。视场设置为 70°，实际提交的垂直视场约 77°。两侧从同一存档和路线开始，SPBR Legacy 后加载 SPBR Mirror，实际资源列表、RR Balanced、32 视距、2560×1440、FG 关闭及采样关闭均核对。额外保留同构件双 worker 对照。初步范围和旧四次反弹相同的探索结果在上表，正式候选则同时扩大实际输入和改变光路预算。

| 构件 | 两轮平均帧间隔 | 两轮 P99 | 两轮世界 PT 均值 |
| --- | --- | --- | --- |
| 149，旧四次反弹 | 19.99／21.05 ms | 32.85／43.65 ms | 12.67／12.74 ms |

实际移动平均由 20.52 增至 30.99 ms，约增加 51%。两侧截图中大型 Sable 结构和手持物均可见，候选的玻璃窗反射和室内亮度有差异。世界 PT 平均约增加 6.91 ms。渲染线程实际 CPU 时间由约 19.92 增至 30.22 ms，Java 方块实体由约 2.00 增至 3.29 ms，Native 刚体元数据由约 0.21 增至 2.22 ms。TLAS 从约 18,447 到 30,436 个实例，刚体约从 1,105 到 13,099 个。TLAS 构建在两侧分别约 0.30～0.32 和 0.35～0.37 ms，实体 BLAS 约 0.16～0.21 ms。RR 平均仍约 2.2 ms。阶段区间与整帧重叠，不能将上述差异相加。

窗口内的进程工作集峰值在 149 两次为 9.51／7.03 GiB，在 150 为 7.95／8.50 GiB。进程专用显存峰值分别为 6.78／7.04 和 7.12／6.80 GiB。这里专用显存来自 WDDM，每次正式窗口只取得 3～4 个采样。工作集漂移较大，不能据此判定这一轮稳定节省或增加了多少内存。

同一候选使用两个 CPU worker 时，刚体元数据区间平均由 2.22 降至 1.78 ms，包含约 0.48 ms 的并行准备。实际帧间隔均值为 31.87 ms，P99 为 56.40 ms。世界 PT 仍为约 19.67 ms，负载与串行同量级。局部减负未转化为整帧收益，默认保持串行。worker 仅接收实例批、父变换快照及此前接受的视图历史，游戏对象和 Vulkan 录制仍由各自原线程负责。

双计数版本通过 GPU 契约、Vanilla PT 和 Advanced 介质验证。反射和折射分别使用 4 和 8 的默认值，历史按可进入的不同介质容量设置。同一光学参数的嵌套边界保留重复深度，退出空气免费，返回不同的外层介质计一次。最大配置的 GPU 契约覆盖 128 次反射、256 次折射和 257 层介质历史。

### 主动光源采样与重放

Advanced 区块灯使用局部位置，只有真正变化的表版本才需上传到录制槽。夜景将带 labPBR 发光贴图的海晶灯移开两格后捕获，6,936 个网格槽中有一个槽保存 8 条有效光源记录。独立重放两窗的光追模块平均为 14.02 和 14.07 ms，帧间隔均值为 15.49 和 15.54 ms。游戏和重放的灯位及受照色调一致，局部亮度、噪声及游戏字幕有差异。这是同配置重复性核对，不能据此推断打开采样的增量成本。

首次重放用长目录解包 Advanced 失败，未出现设备丢失。保留相同快照并用短盘符映射后运行成功。关采样的游戏截图仍可见海晶灯照亮周围。现有表覆盖部分区块贴图、程序薄层及远景代理，实体、方块实体模型及粒子的发光面尚无通用采样项。材质的真实命中发光继续有效。

### 方块实体与 Sable 交接

组合探针覆盖装配、分离、合并、拆回主世界、普通方块实体与 Flywheel 所有权交接，以及资源重载、保留区段时卸载来源和视距切换。测试过程中依次定位三处缺陷：

- 资源重载时，Sable 包装器把 Flywheel 只接受批量顶点的烘焙写入拆成单顶点调用。Extra 在光栅分支为该写入器保留批量入口。
- 字体页退休时，交接快照重新冻结已经释放的告示牌模型 CPU 缓冲。改为按所有者只退休对应字形实例，保留告示牌主体。
- 重载后的卸载探针让被保留区段跨帧存活。几何摆放已使用退休前冻结的空间姿态，介质接触仍向活动空间表查找相同父空间。两者改为使用同一份区段快照中的世界姿态与局部姿态，保留旧区段直到交接正常完成。

本体 `59eaffde12f7…` 与 Extra `52a49fb65298…` 完成整条探针流程并正常保存退出。检查了重载后和 Flywheel 拆回主世界的截图。稳定阶段的模型构建与上传计数各维持在 1，检测到退役空间已关闭后，保留的区段只完成一次交接。结果位于 `validations/performance-scene_replay/result/execution150/final-handoff-retired-space-vanilla-pt-handoff-20261108-230829/`。城市和 RTX Remix 的正式计时使用修复这三个交接问题之前的整合包 `6c1a44ef1c77…`，图形组合和动作在对应窗口内未进入该故障流程。最终配套包未重跑两图性能矩阵。

### SER 重排对照

同一构件固定城市视角，按原路径、只用命中对象、最小重排、原路径、最小重排运行。诊断构件另跑介质夹具，实际 SPIR-V 通过验证，分别含零条和七条重排指令。诊断模块的 SHA-256 与编译产物一起保留。

| --- | ---: | ---: | ---: |
| 原路径一 | 21.97 ms | 27.55 ms | 33.09 ms |
| 命中对象 | 22.17 ms | 29.60 ms | 33.52 ms |
| 最小重排一 | 18.55 ms | 27.61 ms | 37.87 ms |
| 原路径二 | 21.19 ms | 27.62 ms | 31.88 ms |

两轮最小重排都出现蓝色窗面遮住室内，以及第一人称手持物缺面。只用命中对象的截图保留室内与手持物。最小重排的世界 PT 降幅约 14%，画面已变，不能当作等质量收益。这组运行未出现设备丢失；它不能解释过去的读地址故障。

另做一个只在重排前后保存和恢复主射线数据的变体。实验包第一次因内嵌着色器索引与实际字节不匹配被引导层拒绝，重新生成并校验索引后进入同一城市视角并正常保存退出。截图中的蓝色窗面和手持物缺面仍在。保留源码差异、诊断构件身份和截图，日常继续走无重排路径。诊断会改变执行条件，不纳入性能对照。整轮共消耗五次恢复启动，其中四次用于交接与重载，另一次纠正实验包索引。未发生设备丢失。

### 镂空与加速结构的可用边界

主射线的 any-hit 还处理归属、侧别、介质重放和程序表面。即使某块镂空贴图的 alpha 为一，也不能跳过这些条件。初步对两套冻结资源包的树叶、短草、蒲公英和藤蔓做保守检查，允许所有四级 mip 和邻域过滤后，抽样材质均无可证明为全透明的区域。此检查是充分条件，不能排除基于实际 mip 使用范围或明确语义分组的实现。当前构件未启用 OMM。

去除距离门槛后的城市探索样本中，TLAS 构建平均 0.32～0.47 ms，动态实体 BLAS 平均 0.15～0.21 ms。它们小于场景表准备和世界 PT，尚无证据支持以 PTLAS 或 Cluster AS 替换现行构建路线。

### 独立 Native 帧线程的实施条件

当前由 Java 逐帧调用 acquire、submit 和 present。Native 录制同时消费当前的世界 UBO、纹理代际、来源选择、公共空间和 GUI 数据。即使交换链图像与录制槽位已解耦，也仍有多处 JNI 直接依赖活动录制上下文。

可先让 Java 在同一游戏帧封存场景引用和资源增量，显式登记游戏时钟、相机采样时间和历史重置原因。录制线程只持有已发布的快照，Vulkan 命令池、描述符、交换链和 SDK 标记由同一所有者推进。两个线程分别拥有游戏状态和呈现状态，队列上限从一份待呈现快照起步。可替换的姿态和相机更新允许合并，资源创建、删除、重载及世界切换必须按代际有序交接。

连续画面只在同一资源代际内插值，并以实际呈现过的上一份快照生成运动历史。输入由游戏线程采样，Native 不读取活的 Minecraft 对象。暂停、最小化、HDR 变更、重建与设备失败要能唤醒或取消队列，旧快照随提交完成标记退休。先做可撤回的单视图原型，保留同线程基线，再比较真实帧间隔、输入到呈现延迟、内存和 SDK 行为。150 号任务保留当前线程结构。

客户端使用当前开发构件连接只监听回环地址的原版 1.21.1 服务端。服务端日志记录玩家加入，客户端在外部世界渲染并正常退出。此验证不变更服务端发送范围，也不代表所有有模组服务端组合均已验证。

### 151 号的配套基线与介质历史隔离

| 路径 | 世界 PT |
| --- | ---: |
| 44／8 对照 | 2.70～2.70 ms |
| 44／8，只扩介质历史 | 28.29～28.34 ms |

## 结论

保留通过交接回归的来源维护、按视图合批和双计数，串行准备与普通光线遍历仍为默认。实际扩大方块实体范围并采用 4／8 后，两套地图的整帧时间均增加，不能归为等画质提速。来源仍有逐帧生产的入口，主动采样尚未覆盖通用动态来源，OMM 无正式实现。窗口最小化恢复、实际 FG 呈现及连续人工画面验收留待真人测试。

152 号实际包相对 150 配套的同配置对照，SPBR 城市移动整帧平均 32.65 → 30.04 ms，Remix 固定视角 23.54 → 25.34 ms。没有跨场景统一的提速结论。保留已通过回归的介质、来源及安全保护成果。动态来源光源表和按命中身份计权仍缺证据，当前 Advanced 的首表面直接光与后续命中发光为独立入口，扩大光源表前必须验证同一传播路径的权重。Native 帧工作线程仍为默认关闭的实验，尚缺独立的 SDK 帧状态和可比输入延迟。按执行顺序，非 SER 尚未达到整体交付条件，152 号未重开 SER 实验。旧内存停止事件仍单列，未被重新分类为已确认的设备丢失。
