# 完整绘制体系接管推进计划

## 本轮整体重组

2026-10-26 的 130／131／132 号已形成持久来源及已知原版特殊路径的配套候选，边界为来源状态、共同请求、Sable 实体共用、显式端点插值及来源处剥离光栅照明。构建与自动功能通过，人工视觉待验；城市及来源密集对照未证明稳定整帧提速，不能沿用上一轮区段收益。实现、真实路径、失败与性能在[本轮记录](../research/experiment-persistent_sources.md)汇总；不自动推进 GUI／FG、设置、End Sea 或整个材质系统重写。

2026-10-25 的后续授权以[adr-14](../design/adr-14-source_owned_scene.md)继续贯通来源、Java 平台与 Native：主世界和外部区段共用请求及版本流程；来源事件维护 Sable 成员；局部模型、区段和 Flywheel 引用共同空间；稳定绑定复用，已接受状态在打包之前判变。现有 Native 渲染算法、材质、历史和退休继续使用，不另起一套渲染器。

代码、配套自动门槛、运行回归及同城市 32 视距、1920×1080 的四次对照已完成，见[实验](../research/experiment-source_owned_scene.md)。生命周期检查覆盖成员移除／重绑、内容更新、重载和真正的世界重进；纯原版和实际组合均通过，人工外观仍待验收。必要动画、瞬时输入和不能证明稳定的来源仍执行，不能把本轮写成全部内容已经纯事件驱动，也不恢复独立 GUI 或其他功能任务。

2026-10-24 按使用者批准的 127 号执行书连续完成步骤一至四：公共接入与生命周期、持久资源和实例、Native 执行职责与效果编排、Vanilla 全范围和既有第三方迁移，以及可查看的实际路由与整体候选。步骤五的共同细化及步骤六的集中性能测量不在首次交付前自动推进。

完成条件是正式生产路径实际经过公共平台；稳定实例具有显式增删改和代际；Native 的资源、场景、视图、效果与呈现边界清楚；本体独立运行，Extra 独立构建并提供既有适配；按需状态页面展示实际路由而非设计覆盖率；最后交付两份可运行 JAR 和人工清单。保留捕获的原版分支必须逐项登记，不能改名冒充直接接管。

优先验证三个拆分风险：额外模组的早期 Mixin／JNI 绑定时序；世界切换和重载期间稳定实例与旧 GPU 引用的寿命；GUI、离屏及世界效果的顺序、状态恢复和既定 FG 启停。现有区块预算、完成发布、材质语义和资源退休不改为另一套简化实现。

Extra 按使用者指定放在同级独立仓库 `../Radiance-Extra/`，是独立标准模组仓库，不登记为组件或子模块。本体不依赖 Extra；迁移先保留可恢复源码，再撤除旧入口。Git 操作按使用者独立授权执行，不自动启动子代理或操作外部实例。运行次数和用途在冻结候选后、实际启动前说明；工程完成、自动运行和人工视觉验收分别记录。

## 目标

执行[完整绘制范围决定](../design/adr-11-complete_drawing_scope.md)，接管当前游戏版本，以及已纳入依赖在各自已验证版本范围内的所有绘制，在 Radiance 层保存对应原始实现的内容、表面、状态、时序及输出语义。持久几何与实例化是消除重复工作的手段，不能作为完整接管的范围上限。完成定义以该决定为准，不以接管类数量、原版／模组分组或平均 FPS 计算完成度。

2026-10-21 按 [adr-13](../design/adr-13-takeover_instancing_stages.md)将第一节统一为五阶段：阶段 1 初步调查与打基础、阶段 2 接管原版渲染层均完成；阶段 3 实例化主体与自动对照完成，并于 2026-10-22 获使用者目视通过；81 号可行性调查已结束；使用者通过 91 号选择保留现有 Vulkan GUI 并整理代码、核查 DLSS FG；2026-10-23 的当前范围已实现并取得 SDK 实际生成及启停证据，使用者决定工程收口、视觉验收后补。阶段 5 GPU 专项优化暂缓。第二节不变。52 号[性能诊断](../research/investigation-vanilla_performance.md)是历史研究基线，旧阶段 3 未完成的城市六进程对照不作为收益证据。

随后执行的[边界实验](../research/experiment-takeover_boundaries.md)补充了实例独立替换、UI 实际输入与区段完成发布。严格 FG／GUI 呈现分离未获证明；标准 SDK 的 UI Recomposition 仍会插值 UI，不将其当作“完全绕过 FG”的接口。

## 范围

参考 Target 为当前 `1.21.1-neoforge`，版本事实仍从 `target.properties` 读取。世界、GUI、HUD、文字、加载画面、GUI 3D、离屏、屏幕覆盖和后处理都在能力范围内；原版、加载器、Create/Flywheel/Catnip、航空学/Simulated/Sable、Veil 与 Voxy 是来源批次。外部仓库和参考源码只读，产品改动只在 Radiance。

依赖范围以 target.properties 与 inputs.toml 为准，每项兼容区间、验证方法及未证明部分登记在[依赖表](../reference/dependency-rendering.md#兼容范围与证明方式)。接口稳定的加载器核对接口差异并测试范围两端；深度修改原版的依赖逐版本核销。元数据只声明已验证范围，范围外与未登记改动按 adr-9 自动退回；现有声明的证明缺口不在本次文档修订中冒充已验证或擅自改变产品。

按绘制类型统一管理同类实现，来源只接入薄适配器，合同遵守 adr-9；阶段编号仍按来源核销进度组织，不能据此复制同类执行器。

复用现有模型、纹理、查询、场景、JNI、SBT 和完成退休合同，逐步扩展为拥有资源、状态、程序及依赖的渲染实现。Ponder 保持默认行为，世界几何无后置光栅；GUI/离屏可由接管层的 Vulkan 光栅／计算执行。所有已接受语义调整继续有效，未经批准的来源差异视为缺陷或未完成，不能借本次规划改变。

同时维护“绘制能力”和“来源”两个轴。高层直接提交与合法的动态顶点请求都需要权威输入；可持久几何不重复展开，真正变化的内容不冻结。其他已声明支持的来源也进入登记，不因本表没有单列模组名而永久排除。

接管层不依赖 Flywheel API，Flywheel 与原版及其他模组一样位于来源适配边界。正式工程前先做非性能可行性实测：无 Flywheel 的独立模型／实例提交、实际部件与附加层、GUI 状态及离屏依赖、兼容来源和重载。现有能力通过与新合同完整实现分别记录，不以示例成功宣称全部绘制已经接管。

### 接管层增量实例续项

2026-10-24 使用者授权在阶段 3 已验收基础上推进增量实例闭环，本项属于接管层；既有完成与目视证据保持原范围。[来源归因](../research/experiment-takeover_incremental_work.md)首先查明：纯原版仍反复探测缺席的 Sable，不能把实体主体全部视为必要动画。三个安装状态门禁的独立 ABBA 已重复取得整帧收益，没有减少内容或质量。

根据修正后的分布，首个增量原型选择已发布的主世界静态区段。已完成 CPU 实例记录复用、原路径逐帧核对、替换／重载／历史／退休测试和独立开关 ABBA；局部省时没有形成稳定整帧收益，生产集成已撤回，源码与结果保留在研究记录的冻结证据中。当前只保留缺席来源门禁，不继续扩大这层缓存。

该早期实验没有新增实例协议，相关历史结论见实验记录。本次整体重组已将具有来源身份的局部模型接到正式持久参数协议；无变化传视图选择，变化传参数，删除与资源／世界失效分别处理。每视图派生表仍依既有规则组织，不称完整 GPU 数据库；当前边界见[架构说明](../design/architecture-native_renderer.md#持久实例的实际范围)，本轮不做集中性能对照。

使用者随后要求固定自己的实例配置，并追加 32 视距、3840×2160、原版传送命令的[加载至平静基准](../research/investigation-loading_chain_baseline.md)。本续项补齐了连续加载时间轴、编译与原生 worker 分布，保留完整内容及参数；没有实施新的增量架构优化，也没有恢复其他阶段。后续技术选择需区分加载尾部与 4K 平静时 GPU 限制，不将当前主设置文件中的反弹数替代实际活动着色器属性。

### 区块流水线续项

2026-10-24 使用者授权优化完整区块链路，以缩短 32 视距就绪时间并降低加载及移动长帧；后续对照回到 1920×1080，其他使用者配置、世界内容及完整 PT 参与不变。本项属于接管层续项，不重新编号或恢复 GUI、第三方及 GPU 专项。

1. 固定产品、探针、城市、配置及 Java 堆；全程轻量计时与有界细分窗口分开，区分读取、生成、客户端到达、Java 构建、native 批次及发布。
2. 用不可变分页发布替代静态区段任意变化触发的全场景重建；保持实例顺序、相机／历史、代际拒收与旧资源退休。
3. 元数据变化时仅从主机传输变化内容，复用未变化页；保持连续 shader 表及在途缓冲独立，不能原地覆盖旧帧。
4. 修正整坐标拓扑键的哈希聚集；区段排队、提级与公平选择使用索引队列，同轮快照只在来源版本未变化时复用。后台请求短暂合并且有最长等待，交互更新不等待合并；每次实际来源变化均使快照失效。
5. 以 Java 准入、原生待打包、在途 GPU 与待发布版本的总数及输入字节实行背压，保留交互容量与后台有限等待。独立原生工作线程负责打包、上传和 GPU 构建，渲染线程只发布已经完成的版本；同族第二队列显式同步，不支持时保留安全的主队列执行。
6. 外部世界区段使用同一修订、预算和完成后发布链，不再由未完成轮询产生新版本，也不绕过 GPU 完成条件。保留来源变换、历史、附加渲染器和资源退休。
7. 完成自动回归、实际重载、同城加载／固定移动及放挖／边界更新对照。正式帧时与带逐区段追踪的交互窗分开，更新关联至 GPU 完成的场景帧；不将编译或 JNI 返回当成画面完成。以就绪时间、长帧及内存／显存成本决定取舍，设备丢失保全后停止。

当前实现、失败采样与最终比较集中写入[区块流水线实验](../research/experiment-chunk_pipeline.md)。完整稳定 GPU 场景地址数据库与显示器首像素时刻不在本轮范围；连续 GPU 表仍有完整目标分配、内部复制及版本共存成本，不能只以主机上传下降证明整体收益。

本轮正式路径、自动验证、同城加载／移动和放挖追踪已完成，完整候选交人工体验。共同加载前 60 秒、路线帧时及加载放挖延迟已有改善；严格初始平静、静止 FPS 与资源峰值没有全面改善。人工视觉与真实移动尚待使用者，本轮完成后不自动推进实体、第三方或其他接管层任务。

### 第一节阶段 4：GUI 整理与 FG 核查

105 号[调查](../research/investigation-gui_fg_classification.md)保留历史。使用者于 2026-10-23 直接决定：保留已求值反色，局部模糊保留不透明方案，实际全屏菜单模糊关闭 FG；仅压暗且世界输入合法时不因暂停关闭。按[更新计划](plan-gui_frame_generation.md)完成背景角色、统一启停与窗口取证，实现和自动回归通过，单次前台会话取得 SDK 额外生成与模糊启停证据。使用者明确尚未进行人工视觉验收，后续补做，并决定本阶段工程收口。加载覆盖仍保守关闭，局部模糊和淡出提前恢复不阻塞当前收口；不重写 GUI 或自动恢复其他阶段。

[81 号研究](../research/experiment-gui_separation.md)仍保留：UI Recomposition 不等于严格 GUI 绕过 FG，固定 RGBA 总图不能表达任意背景操作。严格呈现分离不作为本轮整理的完成门槛，也不能改名宣称已实现。

### 固定巡检路线与计数推进

巡检采用固定夹具版本、相机点、操作顺序、资源与依赖组合，记录世界和设置哈希；视觉路线不混作性能路线。每次巡检按以下顺序分段，原版与依赖变体分别运行：

| 段 | 固定入口和操作 | 当前核销范围 |
| --- | --- | --- |
| R0 | Early Window → 标题 → 单人游戏列表 → 小型夹具；结束后按反向路径退出 | 原版 SERVICE／GAME 请求与呈现计数已核销 |
| R1 | 小型夹具 `(0.5, 73, 14.5)`、yaw `-180`、pitch `0` 面向物品框墙；左右移动并看绘画两侧，旋转／更换／移除共享物品 | 阶段 2／3；固定世界取已校验的 small-vanilla-fixture.zip，不用用户后续修改后的副本计时 |
| R2 | 到同一夹具 `x=-12～12, y=65, z=-3～8` 的实体／BER 阵列，依次观察动画、装备、眼睛／能量层、箱子开合，再坐船／矿车和切换第一人称 | 阶段 3；未在实景出现的变体保留独立原生成器／状态反例，不代填目视 |
| R3 | 新城市以冻结夹具清单中的 camera／rotation 为起点，再沿原视线缓慢前进和回退；地形更新另到小型夹具 `x=15/16, y=66, z=1` 边界重复放挖和观察水面 | 地形样板与城市完整性；采样窗口仍静止，不把路线运动混入静态性能 |
| R4 | 在固定程序化夹具依次触发粒子、线点、天气和其余网格，按各来源已登记的对象／参数执行 | 原版 109 种注册粒子及非注册来源、实际消费者和原生成器对照已通过 |
| R5 | 打开物品栏和 3D 预览、逐项悬浮提示，切 GUI 缩放与窗口尺寸，再执行规定的离屏采样／读回和屏幕效果顺序 | 原版 GPU 状态、覆盖与附件依赖已通过，新增动态目视待验 |
| R6 | 在各已验证依赖的固定组合执行登记对象与操作，再按 R1～R5 复查对应绘制族 | 后续变体和来源阶段；不把未知版本混入组合 |
| R7 | F3+T → 删除／重建对象 → 保存退出 → 重进小型夹具与城市 → 正常关闭 | 各阶段生命周期；不是 GPU 根因或长期稳定性验收 |

1. **原版自动核销通过**：从 Early Window 到标题、菜单、世界列表及进入小型夹具，覆盖加载与屏幕过渡。
2. **阶段 0～3 目视通过、计数回归通过**：在阶段 2／3 小型夹具固定起点检查共享模型、物品框旋转／替换、绘画两侧、实体动画／装备／附加层、船／矿车及第一人称；保留显式捕获原因。
3. **自动路线与既有目视通过**：进入冻结的新城市固定相机并前进／回退，核对完整场景；不新增性能窗口，不将该运行写成压力或长期稳定性通过。
4. **原版自动核销通过、新增目视待验**：粒子、程序化网格和真实线点、物品栏、裁切、真实离屏采样／读回、屏幕效果、resize、F3+T 与两世界保存重进，具体证据见本轮研究记录。
5. **待办**：在每个已验证依赖组合增加该来源的固定对象与操作；未在路线出现的注册来源以独立夹具补齐，不用城市是否出现决定支持范围。

计数单位是实际原始绘制请求／语义提交，而非每个三角形或每帧 GPU invocation。按场景 epoch、来源请求身份和嵌套输出目标归属请求，记录唯一负责方、对应绘制类型及三种最终结论；没有负责方计入 unowned，多负责方计入 duplicate，未知程序／状态／依赖计入 unknown，各计数分开，禁止重复消费掩盖漏接管。逐项连接状态／目标依赖与输出对照，未出现项不能自动记零。

计数在原版阶段 4、5 已接入程序化、场景与目标边界；阶段 6 增补 renderer 替代与退回的实际计数，不把注册资格充作实际直接提交次数。第三方总验收合并固定路线，执行零 unowned／零 duplicate／零 unknown 核销；现有证据的范围不因重编号扩大。

## 共用验证门槛

每阶段先锁定具体机制及反例，再实施；原／新路径的独立功能对照覆盖位置、拓扑、UV、程序和材料、查询、运动、状态、层顺序、目标依赖及重载。核对实际生产入口，缓存类或源码字符串测试只作补充。测试既有几何数据，也有最终绘制结果，尤其 cutout、半透明、混合、深度／模板、文字、淡出和动态效果。优先使用既有验证工具和测试，不恢复已退休的场景回放产品。

产品阶段完成时从仓库根目录执行：

```powershell
.\gradlew.bat spotlessApply
.\gradlew.bat check verifyRelease verifyCompliance --strict
.\gradlew.bat :native_renderer:gpuTest
```

按受影响验证的 `validation.md` 执行项目内客户端功能流程；记录实际源码、依赖、shader、JAR、内嵌／提取／加载 DLL 身份。自动实例按约定使用 1920×1080、静音，不操作用户正在使用的 Prism。新阶段不因计划存在自动获得运行或部署授权。

63 号执行书已授权原版阶段 3 的实例化与冻结后的指定性能对照，第三方接管暂缓。使用同一城市副本、相机和设置，区分 FRAME_ONLY、阶段计时与 JFR 归因，逐窗保留并行游戏进程及整卡负载；不叠加嵌套计时，不以生成帧 FPS 代表真实帧。此前未完成六进程对照及 SHARC 修复前的旧数据不拼入本轮基线。

自然设备丢失立即保全证据并停止，不自动重试；应用容量异常单独归类。长期稳定性、GPU 根因和公开二进制许可不由某阶段的短时成功自动关闭。

## 结果

阶段 0～2 与地形样板的限定自动门槛已完成，详见[本轮实验与人工清单](../research/experiment-takeover_stages.md)。覆盖／语义表、Voxy 最大根域反例、六类数据合同、真实源生成器／离屏对照、重载及连续地形完成链均有证据；小型样板的 ABBA FRAME_ONLY 为静止 8.608→7.936 ms、移动 8.620→7.871 ms，超过本轮重复差值。只在实际声明并发布的稳定模型上直接提交，自定义和未证明的消费者仍保持原路径。

完整原始源码与必要新文件由 `validations/conformance-takeover/result/source-final.{json,zip}` 固定，完整分发 JAR 与 core 的身份及实际加载对应关系见实验记录；阶段范围差量在 `D:/Workspaces/Scratches/RadianceUnification/`。不以固定 HEAD、历史候选或中间失败替代本轮通过。

阶段 3 的限定自动门槛也已完成，详见[实体接管实验](../research/experiment-entity_takeover.md)：155 项来源均有局部部件对照或保留原因，实际未知 Mixin 退回、公开姿态和重载生命周期通过。使用者暂停性能对比后保留 MCP 暂停后的 6 个有效 FRAME_ONLY 窗口，未完成任一六进程城市组，不下收益结论。最终 C 与阶段 0～3 合并清单由[纯原版验收入口](../../validations/visual-takeover_stages/validation.md)交付，城市与小型夹具各一入口，不启动游戏。

使用者已确认新编号阶段 1、2 完成；历史结果按上表映射读取，完整自动范围和人工范围分开。Voxy 不装入纯原版实例，其既有自动证据与待验独立保留。严格 FG 后 GUI、完整显存峰值、后续来源迁移、GPU 根因、长期稳定性和公开二进制许可均未闭合。阶段 3 已获使用者目视通过；阶段 4 当前范围工程收口，实际生成帧与启停已验证，人工视觉验收尚未进行、后续补做。96 号历史无正计数保持原事实，其余开发及 Prism 投放暂缓。本次仅按使用者新授权将当前源码检查点提交为 Update 并推送，不代表公开发布许可。
