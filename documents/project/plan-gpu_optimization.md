# Native GPU 测量与系统优化

## 目标

减少当前城市配置下的 GPU 工作和慢帧，重点处理移动、转头及水面倒影放大时的高成本。采用实时路径追踪的采样、复用、执行组织和质量预算；以 1440p 的 16.67 ms GPU 帧预算作为推进目标，不承诺当前 CPU、任意城市视角或 4K 必然达到真实 60／120 FPS。

使用者已于 2026-11-01 撤销本轮“不允许任何质量损失”的要求。允许有损近似及不同质量预算；保留可比较的当前参考配置，说明每项取舍造成的噪声、延迟、模糊或细节变化，不把错误和漏绘当作有损优化。

## 范围

处理 Native 的几何／加速结构、GPU 材质与光照、路径推进、透明与介质、SHARC、降噪重建、GUI／HDR／FG 合成及其同步。第一组仍使用同一城市、32 视距、当前配置、不带 Voxy；在最昂贵的路径确定后再选小型专项场景，不展开模组、分辨率和设置的全组合。

暂缓 CPU 接管架构和来源生产优化。继续记录 CPU 供给、等待及真实帧间隔，防止把 CPU 饿死 GPU 或异步排队误判成 GPU 着色器瓶颈。第三方来源解释、既定成像所有权与资源寿命不借此重做；已完成首组透明路径测量与预算实现，后续优化继续按实际测量选择。

使用者补充允许并推荐为 DLSS-RR 和 NRD＋DLSS 采用 NVIDIA 专用优化；以实际渲染设备和各项能力检测为准，不支持时自动关闭专用项。FSR／XeSS 暂不做专项优化，共用代码正常保留，详见[NVIDIA 路径补充](../research/survey-nvidia_gpu_paths.md)。

工具和实现证据见[资料与诊断准备](../research/survey-gpu_optimization.md)。不使用 Computer-Use、子代理或 Goal，不提交、推送或替换 Prism。使用者允许其他线程的纯原版客户端重叠；记录实际负载与时段，不按进程存在一律拒收，也不假定没有干扰。发生设备丢失保全首次证据并停止，不自动重试。按 X-12 控制候选和结果体积，不导出整套 32 视距 GPU 资源来代替短窗口分析。

## 步骤

1. **完成：建立资料与能力依据。** 阅读 NVIDIA 最佳实践、Q2RTX、RTXPT、NRD Sample、RTX Remix、RTXDI 和 Khronos 原文；核对当前计时、抽样覆盖、编译设置及实际驱动能力，保留查询输出及支持／启用的区别。
2. **进行中：准备并接通计数器。** 复用现有 FrameProfiler、GPU 区间、帧退休和完成后读回；Nsight Systems 已取得有效城市整卡短窗口，Graphics 的逐着色器分析、全路径软件抽样与源码关联尚待实现。按下节分别补齐分母和来源标识，默认编译掉插桩，不引入任意脚本平台或常开逐像素原子热点。软件插桩先用小型定向场景验证计数与退出／重载，再到城市；正常帧记录、软件抽样和硬件取证分别开启。
3. **进行中：冻结当前基线并锁定主因。** 当前配套已取得城市最近保存点的 1440p 静止 RR 基线，尚未完成其他姿态和 NRD＋DLSS。核对运行时实际算法、反弹、DLSS／RR／FG、内外分辨率、HDR、缓存条件、驱动和其他负载。分别观察城市静止、转头、固定移动、近距离不透明面、水面及倒影放大，保留正确画面和相机／缩放。先 1440p，再用同姿态 1080p 区分屏幕成本与场景固定工作；4K 只在驻留预算允许且确有判断价值时补测。
4. **进行中：先减少昂贵路径的必要工作。** 已修正透明首表面的身份判定，并交付均衡单路径预算；其他热点按后续测量处理。 按实际热点处理 opaque／any-hit 分流、重复材质读取和着色、阴影可见性、POM／水波／云步进、追踪调用活跃状态、AS 组织和缓存使用。把“查询变少”“单次查询／着色变轻”“时间缩短”分别报告，真实图像和整帧必须一起比较；无稳定收益或综合退步的候选不保留。
5. **进行中：按视觉贡献分配预算。** 首个透明事件已加入概率下限、能量补偿和局部交错采样，复用现有重建；动态质量与其余预算策略仍待推进。 分别试验漫反射与镜面／透射预算、后续反弹提前进入缓存、贡献阈值／俄罗斯轮盘赌、光源重要性采样和时空复用，以及低分辨率／分棋盘采样后的重建。先保护主可见面、近处清晰反射与透射，再评估粗糙或低贡献路径的近似；控制漏光、拖影、光照响应迟滞和水面噪声。以少量成套质量配置交使用者体验，不堆积互相补偿的滑块。
6. **暂停：SER 接入；其他硬件策略待办。** 使用者于 2026-11-02 决定暂停 SER。独立诊断在冻结 AS 后仍复现 GPU 页错误，能完成的变体还存在输出差异，普通 coherent 补丁也未稳定解决；没有可信性能收益。正式路径不含 SER，故障源码与转储保留，不自动续跑。OMM 和区块 AS 策略对照仍待办。按镂空 any-hit 占比、重复烘焙和活跃状态证据选择试验，同步衡量额外 AS、构建、缓存失效和显存。是否拆开主表面、反射／折射与光照 pass，或尝试 inline ray query，由工作分布决定，不预先重写全部 shader 或编译链。
7. **待办：收敛整体候选。** 再核对降噪／RR 输入、运动历史、曝光、HDR、GUI 和 FG 关系；用同一城市与初始基线比较实际帧间隔、GPU 主队列、关键 pass 均值／p95／p99，以及内存／显存峰值和稳定占用。移动、转头、加载分别报告，不相加重叠区间，不把生成帧或专项场景收益推广为普通真实 FPS。交付完整候选供人工验收，明确保留的质量取舍和剩余 CPU 上限。

### 需要接通的计数器

| 类别 | 最小数据 | 判定用途 |
| --- | --- | --- |
| 实际工作规模 | 显示／内部分辨率、分派位置、查询／更新 pass、帧与视图身份、样本数 | 正确归一化，区分主世界、优先级、离屏与 SHARC 更新 |
| 路径工作 | 主成像、漫反射、镜面、透射、阴影的 trace 调用；路径深度及提前终止分布 | 解释“四次反弹”下为何仍有不同工作量 |
| 续接与候选命中 | any-hit 进入、透明／镂空拒绝、边界续接及层数 | 区分合法多层工作、重复采样和异常循环；不是 BVH 节点计数 |
| 材质工作 | 不透明／镂空／普通半透明／水／玻璃／发光命中，POM 和程序步进 | 定位放大某类表面时的成本，避免按屏幕面积猜测 |
| 光照与缓存 | 直接光候选／可见性查询，SHARC 查询／命中／终止，更新与解析 | 判断应改重要性采样、缓存策略，还是 shading |
| 场景与 AS | opaque／non-opaque 几何及实例覆盖，BLAS／TLAS 构建与更新区间、数量／字节 | 解释遍历和构建成本，避免持久实例越多反而求交越慢 |
| 硬件状态 | 实际可见的吞吐、占用、warp 等待、寄存器／spill、缓存／带宽、RT live state 和跨队列时间线 | 分清 SM、访存、执行分歧、追踪和同步；不预设所有 RT Core 指标均可直接读取 |

软件抽样必须记录启用的 pass、采样率和分母，轮换采样相位且不消耗渲染随机序列；稀有事件或样本不足标为未知。将计数分片以降低原子竞争，只在已完成 GPU 版本上读取，保留原始帧身份；未返回值不填零。运行时关闭时不分配计数缓冲、不增加同步，并核对禁用变体未保留插桩指令。

保持 shader 优化级别，单独启用可关联的调试信息并隔离缓存。先验证 Nsight 的实际源码／IR 与 shader 身份；不能用 C++ PDB 当作 GLSL 行映射。硬件计数首轮用单次短窗口；多次采样只用于稳定场景并核对工作一致性。保留一个不加载重型工具的正常记录窗口，用它确认最终收益。

## 结果

本轮已按使用者决定整理无 SER 正式候选，交 Prism 人工验收，不启动客户端；完整变动、性能口径和画面取舍见[GPU 专项收尾](../research/experiment-gpu_optimization_closeout.md)。

最新[执行优化实验](../research/experiment-sharc_execution.md)已实现 SHARC 命中前提前查询与训练权重修正、末次反弹省算、次级材质中转与首命中状态减负。同一进程完成窗口普通帧 22.01→18.17 ms、世界 PT 15.88→11.73 ms；最大长帧未改善，末尾参考未完成，不据此承诺整城真实 60 FPS。随后首次启用 SER 发生 Aftermath 确认的 GPU Read 页错误，完整证据已保存，停止后续 GPU 运行。SER 及未测 AS 策略钩子从正式源码撤下，本轮候选只做构建与投放，人工视觉由使用者完成。

已形成透明预算候选，本体 `e46d28eec779…`、配套 Extra 沿用 `bb98550ed61a…`，API 16。修正 Vanilla PT 双路径按随机 lobe 判断透明身份的偏差，新增均衡采样，保留旧个人选择；真实帧种子只有 31 位的分布回归与极端浮点分组回归已通过。实现、失败迭代和边界见[透明预算实验](../research/experiment-transparent_budget.md)。

最终 K 的同点位 RR 普通帧为双路径 51.79／45.34 ms、均衡 34.57 ms；独立 TIMED 世界 PT 为 38.03／34.42→25.90 ms。其他游戏客户端全程或部分重叠，参考自身也有明显波动，不能据此承诺独占设备收益或真实 60 FPS。中间 I 因种子分布缺陷，不再作为最终收益依据。普通半透明未切到前景／背景混合，场景、分辨率和反弹设置保持不变。

手部额外重复 miss 查询没有稳定整帧成本证据，本轮不建立屏幕边界系统。NRD＋DLSS 独立启动、5×5 重建和 prepass 已确认；RR→SR 的运行中切换持续报告矩阵警告，尚未定根因，不据该组宣布重建正确或性能收益。最终 K 采用先 NRD、后 RR 的验证顺序，正常退出并恢复输入，转头和资源重载完成；连续动态外观与玻璃／水的画质取舍仍待用户验收。

查询工作量观察、整卡硬件窗口与源码核对见[前轮路径调查](../research/investigation-gpu_path_cost.md)及[NVIDIA 补充](../research/survey-nvidia_gpu_paths.md)。Nsight Graphics 的 Qt 自动导出崩溃，仍无可靠逐着色器 stall／寄存器证据；没有因此直接启用 SER 或 OMM。全路径计数、调用点状态、其他姿态及更广泛质量预算继续保留在后续范围，不以本轮局部结果标记 GPU 阶段完成。

完整构建、发行核验、严格合规、82 项非 GPU、28 项 GPU 和 268 个着色器配置请求通过。无设备丢失，未提交、推送或替换 Prism。按现有上限回收可再生解包和逐字节重复着色器副本，原始测量无损归档，保留 Native 增量缓存、原输入和活动故障候选。
