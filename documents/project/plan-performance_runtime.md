# 正常游玩配置的性能与资源成本收敛

## 目标

以冻结城市、32 视距、已核验的 Prism 配置和不含 Voxy 的组合，调查并减少 CPU 重复工作，解释 GPU 分段成本与内存、显存驻留。保持完整几何、画质、历史和资源退休，不以局部计数代替整帧收益。

## 范围

本轮先处理公共实例提交、静态 TLAS 输入组织与资源归因，随后据实测决定分配策略和系统内存／显存取舍。既有来源接管和第三方语义不重写。1080p 与 1440p 分别比较，加载、站立、移动及退出世界分别解释。

## 约束

- 实际模块参数以加载的资源和探针输出为准：四次反弹、随机覆盖、DLSS Balanced、关闭 FG。旧的 128 次反弹结果不能作为普通游玩基线。
- 同一组对照使用相同核心之外的模组、探针、世界和配置；记录观测开销与硬件、驱动状态。实现、自动验证、运行证据与人工体验分开判断。
- 设备丢失立即保全并停止，不自动重试；不提交、不推送，不操作 Prism 实例。
- 遵守当前 X-12，保留 Native 增量缓存；只保留当前必要候选及当前基线原始记录，不积累可再生客户端。

## 步骤

1. 复用已核验的正常配置基线，锁定来源准备和 Native 提交中的高成本环节。
2. 在区段发布时准备不变的 TLAS 记录，逐帧只复制并修正相机与全局索引；BLAS 所有权组和原有帧保留机制分别保护模型与元数据。复用公共提交暂存容器，保留确认和多视图边界。
3. 补充实际分配名称和受支持的显存预算查询，核实退出世界后的大块空闲内存由哪些有效资源固定。
4. 完成格式、构建、发行与相关回归，在同一城市做有针对性的站立和移动对照，按波动决定必要重复。
5. 解释 GPU 分辨率差异及资源生命周期，根据证据选择或放弃局部分配优化和系统内存换显存方案。

## 结果

本轮已完成静态实例记录复用、目录未变时的元数据复制计划、公共批次暂存复用和小资源分配候选。最终 I 的完整构建、发行、严格合规、Native CPU 80 项和 GPU 24 项通过，静止、倒序移动及 I 生命周期均正常结束，无设备丢失。静止改善和菜单驻留减少成立，移动未取得稳定收益，初次加载没有改善证据，实体移除后的一段 GPU 增时尚未定案，不能将分池写成全工况性能验收通过。正常配置的旧基线与口径修正见[城市基准复测](../research/investigation-city_baseline_retest.md)，本轮结果和取舍统一见[实验记录](../research/experiment-runtime_efficiency.md)。

不扩展为新场景数据库、通用 CPU 换入或 GPU shader 全面重写。连续目录发布和 SBT 更新、原版来源准备以及世界 PT 仍需后续选择，不把本轮结构优化写成真实 60 FPS 已达成。人工视觉与手感尚未验收，Prism 未改动。
