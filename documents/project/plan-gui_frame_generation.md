# GUI 分类补帧实施计划

本计划按使用者 2026-10-23 的直接讨论更新：保留 Vulkan GUI、UI Alpha 与已求值反色准星；实际全屏菜单模糊关闭 FG，局部模糊保留不透明已求值方案。当前工程范围为窗口采证、背景变暗分离和统一启停，实现、自动回归及前台 SDK 验证已完成。使用者于 2026-10-23 决定本阶段工程收口，并明确尚未进行人工视觉验收，后续补做；不再自动开发或追加客户端。105 号关于全屏模糊继续补帧的目标被本次决定取代，其[调查记录](../research/investigation-gui_fg_classification.md)保留历史。

## 目标

保持现有原生帧 RGB、GUI 顺序、世界完整几何及资源寿命，让有世界背景且没有全屏菜单模糊的暂停、容器、设置页按实际输入使用 FG。保持用户 FG 开关与硬件可用性前提，不强制开启；真正暂停不推进模拟。取得对应场景的 SDK 实际生成正计数后，再单独裁决生成帧动态质量。

## 范围

- 只修改 1.21.1-neoforge、现有 Vulkan GUI 与 Streamline 2.14.1 的输入／启停，不升级 SDK、不新增 FG 后端或第三方接管。
- 沿当前 ScreenEffectCoordinator、DrawTargetContract、UIModuleContext 与 DlssFrameGeneration 扩展同一合同，不另造一套 GUI renderer／呈现所有者。
- 保留 96 号实际测试包作单一功能基线，身份以 `components/render_diagnostics/build/gui-fg-fix/manifest.json` 为准；91／96 号报告不改写。
- 不将新方案带入人工实例，除非后续另行授权。自动验证仅项目内、1920×1080、静音、不使用宿主输入和 Computer-Use；本计划不含性能实验。
- 已求值覆盖用于反色准星，局部模糊保留为未来设计；全屏菜单模糊直接关闭 FG。不把普通透明控件、离屏附件或全部画面统一设为不透明。已求值区域的动态质量是需验收的代价，不是已证明无损的中间表示。

## 步骤

### P0：建立可用的生成帧前置证据（前台正计数已验证）

1. 在现有 capture 开关后记录应用 GLFW／Win32 窗口、实际 swapchain、前台窗口及根窗口与 PID；沿用 SDK 日志核对其关联窗口。SDK 公开接口未提供窗口反查值，应用 HWND 不冒充 SDK 已确认 HWND。只读，不激活窗口，不改 SDK 判断。
2. 继续由原呈现所有者唯一调用 GetState，关联 SDK token、CPU 呈现编号、场景与实际呈现数；不新增并行查询或只用 Java 缓存正数作为证明。
3. 完成构建、自动回归与候选固定后通知使用者，再安排一次前台候选会话。使用者自行将本项目测试窗口置于前台并保持，自动探针执行场景，不注入键鼠；未运行的前台与 SDK 正计数不填通过。
4. 若仍无额外生成正计数，保留最早 SDK 拒绝条件并停止该组运行；不自动重复、不放宽证据标准。后续 CPU／离屏开发可独立继续，生成帧验收保持阻断。

已取得本次前台窗口及 SDK 额外生成证据；历史焦点差异机制仍未定因，不改写旧会话结果。

### P1：背景与前景最小合同、变暗分离（自动回归与实际 FG 输入通过）

1. 在 ScreenEffectCoordinator 定义每帧 GUI 状态及背景操作作用域；默认绘制属于前景，只有真实背景来源显式声明角色。
2. 对 `Screen.renderTransparentBackground`、完整菜单背景调用和死亡渐变添加薄适配器；保留实际纹理／渐变参数。不要包住整个容器 renderBackground，也不要按 shader、纹理名字或 Screen 类型白名单猜角色。
3. 在背景调用两侧 flush GuiGraphics，保持批次顺序；将角色与已有目标、混合、viewport/scissor 状态一起捕获，进入 native 后复制到已有状态快照，不能只读一个会变化的全局标志。
4. 在 UIModuleContext 公共准备入口，对明确背景变暗执行原 RGB，并在 H 上执行同一操作，保持 coverage；局部列表底色、容器底图、3D、字体和提示仍按普通覆盖。
5. 为 Panorama／全屏 clear／不透明替代背景记录“世界被替换”；同一设置页从标题进入与从世界进入可得到不同结论。

当前切片沿原执行器采用下列接口，不新增 GUI renderer 或呈现所有者。

| 位置 | 最小接口／状态 | 负责的事实 |
| --- | --- | --- |
| ScreenEffectCoordinator／GuiDrawScope | `guiBackground`，作用域两侧 flush，嵌套与异常恢复 | 背景角色只覆盖对应的实际 draw；清理失败不覆盖原错 |
| DrawTargetContract.GuiRole／JNI | `FOREGROUND`、`BACKGROUND_EFFECT`、`WORLD_REPLACEMENT` | 角色进入同一 native 准备入口，录制对应 blend／push constant；附件 alpha 不变 |
| FrameworkContext | `fgGuiRole`、`fgGui`，acquire 时重置 | 本帧背景替换、全屏菜单模糊、不支持合成事实，不以暂停推断 |
| DlssFrameGeneration | `GuiFrameState.decide` 与既有实际资源检查 | 唯一 FG 许可负责方；来源只记录事实，SDK 真实生成另读 GetState |

决策仅两种模式：`WorldWithUiAlpha`／`Off`。Off 原因区分用户关闭、能力不可用、无世界帧、世界被替换、全屏菜单模糊、输入未就绪或合成未支持；实际暂停不是关闭原因。初始 worldRendered 不能代替最终可见性，最后一项背景替换同样必须生效。

实现与机器核对结果：背景渐变不污染无控件区域的 UIAlpha；前景、3D 和提示保持原处理。完整动态外观由后续人工验收确认。

### P2：反色保留与全屏菜单模糊关闭（启停已验证，视觉验收待补）

1. 保留原版 RGB 反色及实际准星片元 A=1，HUD-less 不含准星；不宣称在生成背景上重新反色。
2. 沿 `processBlurEffect` 的实际入口及原版半径阈值记录本帧全屏菜单模糊，最终 FG 决策关闭；仅开启设置、不执行模糊不触发。
3. 原生模糊、背景变暗和控件顺序保持。蜘蛛后处理、景深、纹理过滤及第三方离屏模糊不被这个入口误分类。
4. 局部模糊仍可按不透明已求值区域规划，但本轮未发现需迁移的原版局部入口，不建设通用第三方滤镜框架。

可见结果：全屏模糊菜单不补帧，关闭模糊后具有合法世界输入的同一菜单可恢复；准星保留原色，动态结果交前台测试。原全屏模糊继续补帧的拆分与支撑传播不再属于本阶段任务。

### P3：暂停、加载与历史收敛（本切片已实现，加载尾段另行处理）

1. 已移除暂停／PauseScreen 一刀切；JNI 菜单模糊只记录本帧事实，由 FG 统一决定 Off。保留原世界渲染准入与加载 overlay 门控，不能把没有世界的帧放行。
2. 对暂停继续使用本帧世界输出、depth／motion、相机与抖动，继续推进 token／present，不推进游戏模拟、不缓存上一帧 H 配本帧深度，不强制归零运动。
3. 对世界、资源、尺寸或背景处理拓扑硬切使用既有 FG reset；普通 GUI 动画、连续渐变和稳定暂停不每帧 reset，不重置无关 PT 历史。
4. 加载覆盖当前保守地全程 Off；GAME loading alpha 修正及淡出提前恢复留在后续切片，本轮不改早期窗口或加载 RGB。
5. 对没有当前合法世界输入的阶段 Off；加载结束后按既有 reset 恢复。后续淡出提前恢复必须先证明资源提交、当前颜色／深度／motion 同 epoch，不添加任意暖机帧数或全局 idle。
6. 普通短期切换保持资源，用户长期关闭仍走原卸载／释放；沿现有图像、描述符与在途退休机制处理 resize、F3+T 和关闭。

实现结果：有合法世界输入且无全屏菜单模糊时允许 FG，全屏加载关闭。加载淡出提前恢复属于另行决定的后续优化，不作为本阶段收口门槛。

### P4：相关回归与单次候选功能会话（已运行，视觉验收待补）

1. 在已有 coverage／FG state／framebuffer 测试中补实际接缝：容器渐变不污染前景 alpha，背景作用域退出后字体／3D 恢复，世界替换优先于早期 worldRendered。
2. GPU 对照原路径 RGB，覆盖分数 UI、背景操作前后顺序、裁切及附件；验证背景不改变 coverage、作用域结束后前景继续累积。现有模糊与反色回归仍执行，全屏菜单模糊不再要求支撑继续补帧。按现有 UNORM 误差使用最多 1～2 个 8-bit LSB 的解释性容差，不用 RGB 全图平均掩盖小控件错误。
3. 验证暂停／恢复的矩阵、depth／motion、资源 epoch 和 reset 次数，不把静止画面截图当历史正确证明；多次背景调用不去重，未知运算记录 Off 原因。
4. 构建与关闭 FG 的原生自动回归后通知使用者，执行一次前台候选会话，沿下表完成真实 Screen 路线并同时记录输入／SDK 计数。该会话同时核对 P0，不以旧包重复做一轮焦点试验。若没有正计数，保留最早失败理由，不启动第二个生成帧会话。
5. 执行相关自动检查、完整 check 和发行验证，核对实际加载 DLL 与冻结包；只交一个最终候选及一份源码身份，不逐小项复制整套包。自然发生设备丢失立即保全并结束该组，不自动重试。

| 最小路线 | 需要确认的结果 |
| --- | --- |
| 无世界标题 → 设置／返回 → 全屏世界加载 | 全程无合法世界输入时 Off，不因全景图运动开 FG |
| 正常世界 HUD，明暗背景并缓慢移动 | 有实际生成正计数，准星、热栏和文字动态质量由使用者观察 |
| 背包、3D 玩家／物品、提示、窄窗口配方 | 渐变归背景、面板归 UI；世界继续，局部透明和顺序不变 |
| 暂停 → 设置 → 视频／声音 → 返回，另测模糊为零 | 真暂停不推进模拟；实际全屏菜单模糊关闭；无模糊且世界输入合法时允许 FG |
| 非暂停菜单＋移动背景／实体 | 全屏模糊同样关闭；无模糊时检查 UI 边缘与深度不连续 |
| 加载／F3+T 淡出 → 恢复，resize 后返回 | 本切片加载覆盖期间保持 Off，移除后按合法输入恢复；提前恢复不在本次验收内 |
| 告示牌／书本与死亡页代表例 | 不因默认暂停标志停 FG，着色背景与实际前景分离 |

本次先交付变暗、启停与前台取证切片；不沿用包含全屏模糊继续补帧的旧总工期估算，不因尚无生成正计数就改写为动态通过。

### 启动次数与使用者配合（工程验证已结束）

本切片实际运行两次项目内客户端：一次关闭 FG 的原生 RGB／Mixin／生命周期回归，一次获使用者确认的前台候选会话。人工视觉验收尚未进行，待使用者另行安排；不把前台在场当作目视通过。使用者只需在被提前告知后，自行将指定测试窗口放到前台并保持，按短清单观察动态准星／文字／菜单；其他场景通过项目探针调用真实 Screen 和绘制 API 驱动。不会向桌面发送键鼠，不自动激活窗口，不操作 Prism。任何一次设备丢失或正计数前置失败都按上述停止条件缩减次数，不补跑循环。

### 资源预算与存储安排（后续运行继续适用）

96 号收尾的基线为仓库约 14.70 GiB、验证 instance/result 约 3.17 GiB；仓外按字面含独立调查目录约 7.986 GiB。后续每次构建／启动前重新统计，不把这些旧数值当作永久余额。

- 仓外硬线只余约 15 MiB，不放客户端、SDK、副本 JAR 或大截图；只在现有调查目录写小型索引／脚本，新增文本以 1 MiB 为预算。不可清理的独立目录不改变归属或统计口径。
- 使用项目内同一个 GUI 验证实例，单次复制环境预留不超过 600 MiB；每次结束立即清复制环境，只留最多 64 MiB 的必要输入／日志／截图。两次串行，不同时持有两个客户端副本；启动 guard 须将已有证据和下一次峰值都计入 4 GiB。
- 新冻结包约 158 MiB，至多一套；复用现有 native build/v，不另建 CMake 树。源码与最终交付只各留一份，先核 X-12 的最多五套规则；有引用冲突不擅删，报告具体缺口。
- GPU 复用既有 H、blur scratch、UIAlpha 与帧资源；已求值 coverage 使用 MainTarget 的专用 alpha，不新增全屏 RGBA UI 目标或第二套世界缓存。1080p 每张 RGBA8／R32 图约 7.91 MiB，RGBA16 图约 15.82 MiB，按实际在途图像数核算；预计无新增全屏图像，清退加权中间物时按 GPU 完成退休，不能提前释放。
- 输入捕获只取必要的原始帧，不连续录全帧二进制；原始失败证据保留。预算不足先停止运行并清理已完成的自有可再生环境，仍不足就报告，不突破硬线或删唯一证据。

## 结果

2026-10-23 已按使用者直接授权完成窗口采证、背景变暗与统一启停。完整构建、74 项非 GPU／23 项 GPU、Java 及探针回归通过，严格合规 0 失败／0 警告；关闭 FG 的原生 GUI 会话正常完成 F3+T、保存与关闭，未发生设备丢失。随后使用者确认前台测试，单次候选会话取得 SDK 额外生成，世界／背包／无模糊暂停允许，全屏菜单模糊关闭，返回后恢复；实际输入 coverage 核对通过，正常保存关闭。实际证据、两个既有 bootstrap 条件跳过项、候选与源码身份集中在[实现记录](../research/experiment-gui_fg_policy.md)。使用者已决定阶段 4 按当前范围工程收口，人工视觉验收尚未进行，后续补做。原 96 号无生成正计数的事实保留，不与本次合并。局部模糊与加载淡出提前恢复未实施，不阻塞当前工程收口；没有穷举全部 Screen、严格 GUI 绕过 FG 或第三方兼容，后续阶段不自动恢复。
