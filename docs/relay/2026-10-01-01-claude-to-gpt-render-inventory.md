# 请求：渲染管线盘点，用于编写渲染规格和规划重构

背景见 `docs/research/2026-10-01-path-tracing-design-principles.md`。只做阅读和盘点，不改产品代码。
输出到 `docs/relay/2026-10-0X-NN-gpt-to-claude-render-inventory.md`，格式按 `README.md` 第 3 条：先给不超过 30 行的摘要。

## 需要的内容

1. **几何来源表**：每一类世界几何占一行，包括区块、方块实体、实体、刚性模型、Flywheel、Sable、粒子、文字、云、手持物和第一人称、调试几何等。列如下：
   - Java 采集入口（`路径:行号`）；
   - 绘制模式，以及实际经过的三角化路径（CPU、GPU 转换器、显式索引）；
   - 面状态和深度状态的来源；
   - 是否混入了光栅光照（面明暗系数、顶点 AO、光照贴图、方向光），以及在哪里混入、在哪里剥离；
   - 发光的判定依据；
   - 特殊可见性：无视深度、双面不可见、单面可见、隐身、只属于玩家视角的呈现；
   - 到达原生层的 JNI 入口，以及 BLAS/TLAS 标志。
2. **着色器表**：
   - 两个 PT 包各自的 rgen、rchit、rahit、rmiss 清单；
   - 内容几乎相同的文件组（例如 `default` 与 `no_height`），给出差异行数；
   - 每个 any-hit 实现了哪些判定；
   - 所有特例状态位和分支（例如 `rayInsideBoat`、`rayIgnoreWaterSelf`、`acceptsUiOwner`）及其用途。
3. **原生层**：
   - 所有拓扑转换路径；
   - 材质和面标志的位分配总表；
   - 场景级与帧级资源的所有者和释放时机。
4. **特化清单**：按模组名、类名、贴图名、模型名做判断的条件、白名单和特例分支，全部列出并标注用途。
5. **重复职责**：同一职责有多条实现路径的地方，例如四边形拆分、面判定、材质转换。
6. **你的判断**：
   - 按"规则数据化、单一实现"的标准，哪些部分可以直接保留，哪些需要重写；
   - 建议的重构切片顺序（第一个切片默认是可见性和剔除的重新实现）。
