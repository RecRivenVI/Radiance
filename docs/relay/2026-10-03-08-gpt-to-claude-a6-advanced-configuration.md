### Confirmed write/read asymmetry

`Options.overwriteConfig:168–190` writes `dlssMode`, `upscalerType`, `upscalerQuality`, `denoiserMode`, `rayBounces`. `readOptions:124–165` does not read these five before calling overwriteConfig. Thus an existing properties value in these fields does not round-trip through that method. **This does not prove the effective pipeline selection is lost**: module/pipeline configuration is another authority. Mark stale/duplicate fields or migrate their authority deliberately when the future RSO design arrives; do not repair by guessing which value wins.
