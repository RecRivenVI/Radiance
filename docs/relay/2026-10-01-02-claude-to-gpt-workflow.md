# 开发方式与流程（新线程必读）

## 1. 角色

- **用户**：项目所有者，负责所有产品决策和授权。回复用户一律使用简体中文。
- **Claude**：主导顾问，额度有限。负责判断、决策建议、规格和审阅。只读摘要，不做大范围阅读。
- **GPT（你）**：执行者。负责阅读、盘点、实现、验证、写文档。需要 Claude 判断的事项，写进 `docs/relay/`，由用户转交。

## 2. 沟通方式

- 协议见 `docs/relay/README.md`，未关闭事项见 `docs/relay/INDEX.md`。
- 写给 Claude 的报告：开头先给不超过 30 行的摘要，内容是结论、风险和需要的决定；细节放后面，用 `路径:行号` 引用。
- 批注时保留原文。用户确认的决定，由你写进开发账本、ROADMAP 或 research 文档，并在 relay 文件里留下链接，然后把该 relay 文件标为 closed。

## 3. 当前阶段：冻结（直到用户批准总计划）

- **禁止**：修改产品代码或着色器，以及一切以修复为目的的改动。发现的问题记为 finding，不当场修。
- **允许**：只读盘点；写分析脚本，放在 `run/` 或临时目录；写文档；经用户授权、用于取证的隔离运行。
- **性能实验暂停**，直到用户明确恢复。
- 总流程分四个阶段：
  1. 冻结；
  2. 理解：做盘点，写成 relay 报告；
  3. 规格与决策：每条决定写成一份 DECISION 文件；
  4. 计划与分片实施：每片都要包含规格条目、契约测试、实现，以及删除旧路径。

## 5. 用户的大计划（本阶段只做理解和规划，不实施）

0. 把 MCVR 并入 Radiance，作为 native 组件，并计划脱离上游。
1. 扫描 Minecraft（Mojang 映射）、NeoForge、Create、Sable、Aeronautics、Veil 等的源码，盘点 OpenGL 世界绘制和 UI 绘制调用，并核对 Radiance 的翻译完整度和语义。
   - 扫描要覆盖这几层：RenderSystem、RenderType 状态、VertexConsumer、GuiGraphics、着色器和后处理链、帧缓冲。
   - 静态扫描的结果用 Audit 的运行时统计确认是否真的会执行。
2. 路径追踪的生命周期：长时间游玩后的性能衰减、内存和显存泄漏、无上限增长的计数和缓存。做法是静态所有权清单加长时间浸泡测试。
3. 成体系地接入画面增强技术：
   - DLSS 走 Streamline：SR（需要自研降噪）、RR、FG、Reflex。NR 和 MFG 先把基础设施做好，目前无法测试。
   - FSR：超分辨率加帧生成。
   - XeSS：超分辨率；若有帧生成，一并接入，以官方文档为准。
4. 重做 Advanced 模式：多光源采样改为渲染器内部始终开启的能力。取消"着色器包/管线"界面。配置系统等用户的 RSO 移植初步完成后再定。
5. 清点原版为画面效果所做的设计，并逐项重新决定在路径追踪下的呈现方式。包括：
   - 原版光照：面明暗系数、AO、光照贴图；
   - 覆盖层：受伤变红、弹簧应力变红、附魔闪光；
   - 置顶绘制：发光描边、名牌；
   - 固定宽度线条：选中框、F3+G、F3+B 实体碰撞箱和 sublevel 碰撞箱；
   - 带格式、颜色、发光效果的文字；
   - 任何情况下都全亮度的发光式渲染。

   计划 1 和计划 5 合并为一份"绘制意图总目录"：计划 1 是扫描层，计划 5 是决策层。

## 7. 长期约定（不得违反）

- **Git**：
  - 未经用户明确授权，不提交、不推送；
  - 强制推送只能用 `--force-with-lease=refs/heads/develop:<sha>`；
  - 删除文件一律移入 Windows 回收站；
  - 不重置工作区；研究文档不得当垃圾处理。
- **用户的 amend 习惯**：用户发起 amend 即视为授权完成全流程，包括推送。仓库没有协作者，强制推送是常规操作。步骤如下：
  1. 改写前，建一个临时本地备份（分支或 bundle），记录当前完整内容，包括未提交的改动。
  2. 把改动 amend 到指定的历史提交。**不修改该提交的元数据**：作者、作者时间保持不变，提交消息除非用户另有要求也保持不变；committer date 设为与 author date 相同。
  3. 校验：
     - `commitdate == authordate`；
     - 存在 SSH 签名；
     - 新提交的 tree 哈希与备份内容一致。
  4. 用 `--force-with-lease` 强制推送，再用 `git ls-remote` 确认远端已指向新 SHA。
  5. **推送确认无误后，立即删除本次的临时备份，不留堆积。** 以前遗留的备份只清点一次，列给用户，确认后清理。
  6. 在账本里追加"旧 SHA → 新 SHA"对照。账本引用的旧 SHA 依靠这份对照查找，不依靠保留备份。
- **运行**：
  - 自动化客户端只在 `Radiance/run/` 的隔离实例中运行，主音量为 0；
  - 运行前确认机器空闲，并提前告诉用户何时开始、负载多大；
  - 不在有测量运行时构建。
- **Prism**：
  - 遵守 `E:\Minecraft\PrismLauncherDev\AGENT_GUIDE.md`；
  - 启动游戏要经用户授权，投放只在用户要求时进行；
  - 永远不在 Prism 或生产世界启用主动 Audit 探针；
  - 不碰别人的锁和凭据。
- **产品**：
  - 全场景参与路径追踪；
  - 不降低画质、视距和动画频率；
  - 不做基于相机的 PT 裁剪；
  - 不针对模组或几何特化，不加白名单，不设亮度下限；
  - Ponder PT 保持归档。
- **搜索范围**：只在 Radiance 和 MCVR 两个仓库内搜索，不从它们的上层目录递归扫描。
