## Effective scope

The task reset both projects to upstream-shaped repositories, created the development direction for
the 1.21.1 NeoForge port, investigated Early Window and rebuild cost, refreshed dependencies, and
then expanded into the first large fork audit and behavior review.

## Durable architecture and process decisions

- Keep Radiance and MCVR as separate upstream-shaped repositories. Do not restore the abandoned
  structural merge or the old Stonecutter repository organization.
- Separate mechanical porting, intended product behavior, third-party compatibility, correctness
  fixes/guards, and temporary diagnostics when reviewing changes.
- Treat Minecraft 1.21.1 and the exact NeoForge/mod sources as semantic authority. A current or
  upstream Radiance implementation is evidence, not automatically the intended behavior.
- The Early Window direction is NeoForge's supported early-window SPI followed by handoff to the
  same main window and Vulkan ownership. Preserve NeoForge title, icon, and loading semantics and
  ship one Radiance JAR target.
- Resize, minimize/restore, and early handoff should rebuild size-dependent swapchain resources
  without rebuilding the complete world, ray-tracing, UI, and cache state. The observed initial
  world-pipeline cost was an implementation cost, not proof that Vulkan inherently requires it.
- Agent diagnostics use the repository test instance. The unauthorized Prism test root created
  during the task was removed and is not a supported workflow.
