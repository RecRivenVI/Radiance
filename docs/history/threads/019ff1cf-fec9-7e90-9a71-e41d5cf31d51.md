## Effective scope

This task grew far beyond its title. It covered renderer ownership, NeoForge interception, lines,
transparency, particles, block outlines, first-person geometry, name tags and glowing entities,
resource reload, PBR texture policy, Ponder, NVIDIA Ray Reconstruction failures, driver recovery,
workspace migration, and many temporary visual experiments. It is an historical integration diary,
not a current specification.

## Durable renderer model

- Minecraft and NeoForge decide what semantic content should be drawn; Radiance intercepts and
  translates those requests; MCVR owns Vulkan execution and GPU resource lifetime.
- OpenGL can exist during early loading and in unsupported third-party code, but after the main
  GLFW window is handed over as `GLFW_NO_API`, the normal Radiance world/UI path is Vulkan. Do not
  promise that no OpenGL call can exist anywhere in the process.
- Source-first review uses Minecraft 1.21.1, NeoForge, and the exact third-party versions. Ported
  code and upstream Radiance are comparison material, not semantic authority by default.
- Unsupported third-party rendering must fail closed or be explicitly classified; silent loss is
  not compatibility.

## Durable implementation lessons

- NeoForge interception must cover hand rendering, render stages, highlights, section geometry,
  block-entity visibility, dimension transitions, fluids, custom particles, and breaking overlays.
- A historical MCVR line bug used quad indices for line topology. The correct repair follows the
  vanilla topology; the later experimental special line-antialiasing path was reverted.
- Transparency requires distinct semantics for cutout, normal alpha coverage, physical
  transmission/refraction, and additive/emissive content. Similar appearance does not make these
  interchangeable. Nested media/IOR correctness remains separate work.
- Particles intended as world content need geometry and ray traversal through relevant reflection
  and refraction paths rather than a single post overlay.
- Block outlines should follow the authoritative `VoxelShape` edges. An overcomplicated custom
  merging attempt was reverted.
- First-person player geometry can exist for indirect/reflection/shadow paths while direct camera
  visibility follows the approved camera rule; sleeping and detached-camera cases remain distinct.
- Resource reload needs a generation transaction: build the new resource set, publish it at a safe
  boundary, retire old resources after GPU use, and reset incompatible temporal history.
- A proposed external-PBR “authority texture” mechanism was removed after review because normal
  Minecraft resource priority already resolves individual material channels.
- Partial device-loss recovery was removed because selected Vulkan-object recreation could not
  restore the complete Java/native/Streamline/world lifecycle safely.

## Runtime evidence retained

The NVIDIA RR/device-loss investigation reproduced GPU MMU page faults in MCVR and in NVIDIA's
official Vulkan RR sample while the machine was in the bad state. RTSS, OBS, and NVIDIA capture
were not necessary conditions. A driver-downgrade comparison was invalidated by an automatic
Windows driver update. After reinstall and reboot, the same 610.88 version ran two official RR
samples for about 10 hours 57 minutes and Radiance for about 10 hours 46 minutes without device
loss. This supports a bad driver/install/runtime-state explanation for that episode; it does not
certify the code or driver version universally.

[`../../research/CRASH_AND_RUNTIME_INVESTIGATION_HISTORY.md`](../../research/CRASH_AND_RUNTIME_INVESTIGATION_HISTORY.md).

## Superseded or rejected experiments

- Full-model outline union, special F3 line antialiasing, the external-PBR authority texture, and
  incomplete device-loss auto-recovery were removed or reverted.
- Microgeometry/POM ideas were investigated but not implemented as a general solution.
- Some one-sided-geometry proposals were abandoned at the time; later product decisions and
  current roadmap entries control any renewed work.
- Historical name-tag, glowing, text-routing, and priority-layer designs changed multiple times.
  Use the current source and development ledger, not an intermediate task message.
- Old Stonecutter commits, workspace layouts, build hashes, and deployment paths no longer describe
  the current repositories.
