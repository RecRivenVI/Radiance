## 2. 已完成修复（按主题）

### 2.1 启动 / 基础兼容（早期 run8–run18）
- layout 保活：`descriptor.hpp/.cpp`、`dynamic_pipeline.hpp/.cpp` 增加 `pipelineLayoutKeepAlive`，避免重建后 descriptor table 释放仍被管线引用的 layout。
- 命名统一：`distributedArchiveName`/`game.path`。
- Veil/Sable/Create-on-Aeronautics 兼容链（未提交）：`VeilRenderSystemMixins`（GL30C→GL43C）、`VeilDynamicBufferManagerMixins`、`VeilShaderManagerCapabilitiesMixins`、`VertexArrayProxy` native owner、`ShaderProxy/VertexArrayProxy` 属性格式映射、`PBRVertexFormatElements` 动态 ID、`VeilSizedShaderBlockMixins`/`VeilDynamicShaderBlockMixins`（Create 重复注册根因）、`VeilLayoutSerializerMixins`、`VeilNecromancerDispatcherMixins`、`VeilFirstPersonRendererMixins`。
- `PonderWorldStageMixins`（已在本轮删除，见 2.6）：曾把 Ponder 世界回调延迟到 `WorldRasterPass`。
- stonecutter 图鉴移植：`SimulatedDiagramCompatibility`（含 `DiagramBufferSource` 每层独立 allocator，修 `BufferBuilder: Not building!`）、`SimulatedDiagramScreenMixins`、`SimulatedDiagramStickyNoteMixins`；native `beginDiagram` 的 clearRect 移植。
- `HttpTextureMixins`：修复皮肤/披风上传 targetID 缺失导致的纹理串写（文字↔披风/皮肤↔文字），用户已确认。
- overlay post 管线 `pipelineLayoutKeepAlive`（Graphics/Compute/RayTracing builder），修实例 `hs_err_pid63504`；run18 验证。
- `SableSubLevelBridge`：解析变换替代 JOML `Matrix4d.invert()`（±2e7 精度不足）+ 四元数归一化；修 Sable 实体模型偏移；诊断代码已移除。
- `RadianceImmediateWindowProvider`：窗口位置改 `glfwGetVideoMode`+`glfwGetMonitorPos` 整屏居中；实测客户区原点 (427,240)。

### 2.2 PT 去假明暗（用户拍板：要物理正确）
- `BlockModelRendererMixins`：无条件去 CPU 烘焙面亮度（原仅 external section）。
- `FluidRendererMixins`：去方向系数。
- `ChunkProxy`：清理 `externalSectionBuild`/`isBuildingExternalSection`。
- `MCVR/src/shader/util/vertex.glsl` `applyFlywheelFragmentLighting`：删除 cardinal/动态光/lightmap 乘色（保留 crumbling）；`render_world_post.*` 查实为死 shader。

### 2.3 显存泄漏（已修复并实测）
症状：进世界后显存约 34–52 MB/s 持续增长，十几分钟 3 GB→28 GB，帧率崩到个位数；离开世界后停止。
定位（新增分配追踪）：
- 根因：`MCVR/src/core/vulkan/descriptor.cpp` 的 `DescriptorTable::retainDescriptorResources` 在重绑同一槽位时**只 push_back 不替换**，导致 `world_prepare` 每帧新建并绑定的 9 个元数据 buffer + 每帧 TLAS 被永久持有（`buffer@Submit frame` +42 MB/s）。
- 修复：改为"重绑即替换"（槽位只保留当前资源）。
- 验证：修复后会话 vram 484→峰值 4377 MB 走平，`leak/s none`。

### 2.4 世界网格输出目标 / 方块选中轮廓自发光
- `WorldMeshSink.RenderTypeSnapshot`：输出目标不再只认 `MAIN_TARGET`，改为白名单所有 vanilla 主帧目标（MAIN/OUTLINE/TRANSLUCENT/PARTICLES/WEATHER/CLOUDS/ITEM_ENTITY）；自定义 FBO 仍拒绝。修 `translucent`（幽灵预览/glint）被整层丢弃的问题。
- `entities.cpp`：`radiance:debug/*` 的强制 `albedoEmission=1` 现在排除 `radiance:debug/block_outline`（选中轮廓不再发光）。

### 2.5 Overlay（Outliner 面 / 幽灵预览 / glint）半透明语义
- `alpha_mode.glsl` 新增 `ALPHA_MODE_ORDERED_OPAQUE = 24`；两个内置 shader pack（vanilla-pt、advanced）的 `transparent_only.rchit` 增加分支：模式 24 = 无光照不透明（`radiance += rgb; throughput = 0`）；模式 23 = 无光照 source-over（`radiance += rgb*alpha; throughput *= 1-alpha`）。
- `WorldMeshSink.isOrderedOverlay`：`ponder:outline_solid` → 模式 24，`ponder:outline_translucent*`/`translucent`/`translucent_moving_block`/`entity_translucent*` → 模式 23；materialKey 前缀 `lightning|` 使其进入 `transparent_only.rchit` 命中组。
- native `Entities::queueWorldMesh` alpha 校验放宽到 ≤24。
- 注：曾用 `BOAT_WATER_MASK(128)` 做过"仅主相机可见"（不投影/不进反射），用户明确更喜欢"在世界几何里并完整参与 PT"，已改回 `RayTracingFlags.WORLD`（现全部参与阴影/反射/GI）。

### 2.6 Catnip Outliner 改为 Radiance 自绘重建（最新，待用户验收）
- 删除 `PonderWorldStageMixins`（不再延迟到 WorldRasterPass；Ponder 世界回调现在内联在 WORLD_STAGE，`RenderType.draw` 由 `WorldMeshSink` 接住）。
- 新增：
  - `com/radiance/compatibility/outliner/RadianceOutlinerRenderer.java`：世界阶段内接管 `Outliner.renderOutlines`，自行遍历、复刻淡出（alpha³），支持的 outline 用恒等 Pose + no-op buffer 渲染，不支持的（`ItemOutline`）仍走原 buffer 路径。
  - `RadianceOutlinerContext.java`：线程上下文 + 自绘发射器（线段/贴图面）+ `NoopSuperRenderTypeBuffer/NoopVertexConsumer`；线段经 `EntityProxy.queueOutlinerLines`（WORLD、CAMERA_SHIFT、按 outline 宽度），面经 `WorldMeshSink.submitCaptured`（entity_translucent → 模式 23）。
  - mixins：`compatibility.catnip.OutlinerRenderMixins`、`OutlinePrimitiveMixins`、`OutlineParamsAccessor`（alpha/faceTexture/highlightedFaceTexture/disableCull）。
  - `EntityProxy.queueOutlinerLines(...)` 新公共 API。
- 语义：边 = PT 线段（宽度取 `params.getLineWidth()`，默认 1/32）；面 = 贴图 source-over（AABB 非高亮面 alpha×0.5，高亮贴图优先）；颜色/alpha/淡出复用原 params；完整参与 PT。
- 状态：已投放，用户尚未反馈效果。

### 2.7 崩溃修复（levitite）
- 根因：Veil `PipelineVertexBufferMixin.drawPatches` 在 `VertexBuffer.draw()` HEAD 调 `glGetInteger`，因 mixin 应用顺序先于 Radiance 的取消执行，Vulkan 无 GL 上下文 → 访问违例（`hs_err_pid27084.log`，WER dump `javaw.exe.27084.dmp`）。
- 修复：`VertexBufferMixins` 优先级 2000→500（晚应用 → HEAD 回调先执行并 cancel）。

   - `levitite_ghosts` 在主世界被光栅化（原版主世界故意跳过）。
