## 正式组合

- **A 基础**：仅Radiance及其实际必需运行依赖，单个正式分发JAR模式；包含打包的原生库/Shader与自身必需Java库，不强加可选兼容mod。
- **B 完整**：A + Create/Flywheel/Ponder/Catnip相关组件 + Sable/Veil/SableCompanion + Aeronautics/Simulated及发布物硬依赖（如Offroad/Registrate）。按元数据得到最小合法集合；缺硬依赖属于环境配置失败，不归渲染器缺陷。

两组后续都应覆盖：启动与同窗口交接 → 标题/设置/模组UI → 进入隔离测试世界 → 代表性功能 → 退出世界 → 再次进入 → 资源重载 → 正常关闭。窗口resize/最小化恢复、冷/热缓存性能另作同环境测试，不用一次未崩溃证明全部正确。

## 源码依赖顺序

1. **用户裁决效果**：先确认MC-xx、EXT-xx、MOD-xx的效果去留；MC-05与MC-09默认保留已确定。未选项目不视为授权。
2. **锁定版本与契约**：核定上述发布物/嵌套依赖，确认真实Mixin签名；按资源创建/绑定/使用/销毁写出所有权与错误契约。
3. **共享基础**：真实纹理/buffer/shader/state/离屏target与重载generation；禁止以合成ID或成功状态代替资源。先关闭资源端与消费者端的不一致，再接入更多功能。
4. **Loader扩展**：核对取消原版流程后遗失的ModelData、流体/biome、维度、手部与stage事件；明确由谁生产几何和哪个target接收，不把回调执行当作画面完成。
5. **Veil资源与消费者**：按缺口表拆CPU状态、可翻译资源、真实回退和待用户取舍功能，不能全停renderer后保留读取者，也不能创建假VeilRenderer。
6. **Create/Flywheel与Ponder**：把真正Backend/Engine/Instancer目标与普通BER回退分开；世界、Sable embedding和Ponder/图集environment均需相应资源/相机/target。
7. **Sable及Aeronautics/Simulated**：在共享几何和目标可用后，验证双精度局部/世界/相机/物品坐标、sublevel生命周期、图集/便签与Plunger专属端点。
8. **帧/退出与性能**：在上述生命周期可用后再调整世界预热时机、cache失效、曝光与重建，避免新并发掩盖缺陷。
9. **最后收口诊断和绕过**：分离正常错误传播与观察逻辑，移除本地排查探针与已被替换的伪实现，再重复A/B验收。

源码能先解决：遗漏调用者、错误版本签名、假资源、缺少事件路由、明显坐标空间不一致、错误生命周期顺序和未实现backend。必须实测：GPU驱动/时序、混合和深度、像素/手姿态、复杂模型、世界重入、异常退出、冷/热缓存性能。
